# 自进化记忆的逐题取舍：研究思路与实验设计

## 1. 要解决什么问题

带记忆的语言模型（或 Agent）做完一道题后，会把经验写进记忆库，后面的题再检索这些经验。SeqMem-Eval 等工作已经表明：在整套题上，平均准确率往往高于「完全不用记忆」。

平均分变高，并不表示每一道题都受益。可能出现：

- 无记忆时答对，加上记忆后答错（**伤害**）；
- 无记忆时答错，加上记忆后答对（**帮助**）；
- 对错不变（**持平**）。

如果伤害真实存在，而且能在模型写出答案之前被判断出来，就可以做「这道题要不要用记忆 / 用哪一版记忆」的选择。如果伤害存在但无法预测，就只能做整段记忆的监控和版本回退。如果伤害并不高于模型自身的随机波动，这条线就不值得继续。

本阶段（记为 E0）只做**诊断与可行性检验**：在公开基准上，用官方记忆方法复现实验，按题目编号配对，回答上面三个问题。E0 **不**改记忆算法本身，也**不**训练新的大模型；机器学习部分用在「伤害能否预测」和「在线监控」上。

## 2. 用一个例子说明比较方式

下面是说明用的例子，不是实验日志。

题目：把直角坐标 \((0,3)\) 写成极坐标，要求 \(r>0\)，\(0\le\theta<2\pi\)。正确答案是 \((3,\pi/2)\)。

| 条件 | 模型答案 | 对错 |
| --- | --- | --- |
| 不使用记忆 | \((3,\pi/2)\) | 对 |
| 使用记忆（检索到一道把角度写成度数的旧题） | \((3,90)\) | 错 |

这一题记为**伤害**：记忆把原本做对的题带错了。

注意：模型即使不看记忆，同一道题连做两次也可能一次对、一次错。所以「由对变错」不能直接算成记忆的责任。实验必须估计这种**采样噪声**，再看记忆造成的伤害是否明显高于噪声。

## 3. 总体设计

核心做法是：**同一道题，分别在「无记忆」和「有记忆」下各答一次，按题目编号配对，比较对错变化。**

```
公开数据集（固定题序）
        │
        ├─► Baseline 无记忆，完整跑 2 遍     ──► 噪声底、对照准确率
        │
        └─► 四种记忆方法，各完整跑 1 遍     ──► 与 Baseline 第 1 遍按题配对
                                                    │
                                                    ▼
                              伤害 / 帮助 / 持平 统计
                              伤害是否可预测
                              抽查监控是否够用
                                                    │
                                                    ▼
                              GO / PARTIAL / NO-GO → 决定是否做下一阶段
```

约束：

- 数据和方法都来自开源基准 SeqMem-Eval，**不修改其代码**，只调用官方入口。
- 题目按固定顺序做；后面的题只能看到前面留下的记忆，看不到未来的题。
- 生成模型固定为 Qwen3-8B，采样设置与 SeqMem-Eval 论文中该模型一致（温度 0.7，关闭思考模式，最多 2048 token）。
- 检索用 Qwen3-Embedding-0.6B，每次取最相似的 3 条。
- 当前在单卡 RTX 4090 上用 vLLM 提供生成服务；实验进程的向量模型放在 CPU，避免和生成服务抢显存。

## 5. 对照与记忆方法（Baseline）

无记忆跑 **2 遍**，每种记忆方法跑 **1 遍**。记忆方法都是 SeqMem-Eval 已实现的在线方法。

| 名称 | 留下什么 | 新题时怎么用 | 在本实验中的角色 |
| --- | --- | --- | --- |
| **Baseline** | 不留 | 只看当前题 | 对照；两遍之间的翻转率 = 噪声底 |
| **HistoryRAG**（命令名 ExpRAG） | 过去每题的题目、回答、对错 | 按相似度取出旧题原文放进提示 | 最直接的「原样检索」记忆 |
| **DC-RS** | 旧解答 + 一份不断改写的备忘（cheatsheet） | 同时读备忘和检索到的旧解答 | 会综合、改写经验的记忆 |
| **AWM-Online** | 从成功解答归纳出的操作步骤 + 少量成功例子 | 读步骤和例子 | 「工作流」式记忆 |
| **ExpeL-Online-ST** | 可增删改的规则 + 成功案例 | 读规则并参考相似成功案例；每题只答一次 | 「规则提炼」式记忆 |

**故意不用** ExpeL 的多次尝试版本（答错后看反馈再答）。那个版本改变的不只是记忆，无法和「单次作答 + 记忆」直接比较。

每种方法的准确率还会和 SeqMem-Eval 论文表 3（Qwen3-8B）核对，允许约 3 个百分点偏差。偏差过大时，先查实验设置是否和论文一致，再解释记忆的影响。

## 6. 具体怎么做（流程）

### 6.1 跑实验矩阵

对每个任务，执行：

1. Baseline 第 1 遍、Baseline 第 2 遍；
2. HistoryRAG、DC-RS、AWM-Online、ExpeL-Online-ST 各一遍。

一共 \(5\) 个任务 \(\times\) \((2 + 4)\) 种运行 \(= 30\) 个作业。每个作业写一份逐题日志（题目编号、对错、检索到了什么）。作业可断点续跑：已完成的会跳过。

### 6.2 按题配对

对「某任务 × 某记忆方法」：

- 取 Baseline 第 1 遍作为无记忆结果 \(y_0\)；
- 取该方法同题结果 \(y_1\)；
- 定义差值 \(d = y_1 - y_0\)：
  - \(d = +1\)：帮助；
  - \(d = -1\)：伤害；
  - \(d = 0\)：持平。

得到帮助率、伤害率、不一致率，并用 McNemar 检验比较有无记忆是否整体不同。

### 6.3 估计噪声底，得到「超额伤害」

两次 Baseline 在同一道题上也可能不一致。定义：

\[
\text{噪声翻转率} = P(\text{第1遍对且第2遍错})
\]

\[
\text{超额伤害率} = \text{记忆伤害率} - \text{噪声翻转率}
\]

真正关心的是超额伤害率，以及它的 bootstrap 置信区间是否整体落在 0 以上。

### 6.4 检验三个事先规定的假设

**H1：伤害超过噪声。**  
若某个「任务 × 方法」格子满足：超额伤害率 \(\ge 5\%\)，且置信区间下界 \(> 0\)，则认为该格子存在真实伤害。至少一个格子成立，则 H1 通过。

**H2：伤害可在作答前预测。**  
只用写答案之前就能看到的特征（做到数据流的什么位置、检索条数、检索到的旧题里做错的比例、题目长度、记忆文本长度、题目与检索结果的相似度等），训练逻辑回归，预测「是否会被伤害」。  
验证方式：

- 按时间切分：前 60% 题训练，后 40% 测试（模拟在线）；
- 留一任务：用四个任务训练，在第五个任务上测试。

要求 AUC \(\ge 0.65\)（时间切分或留一任务的中位数达到即可）。特征用 hashing 相似度，不引入「未来题」的统计量。

**H3：抽查监控是否够用。**  
正式系统不能每题都做两次。这里模拟：每一步以概率 \(\varepsilon\in\{0.1,0.2,0.3,1.0\}\) 再跑一次无记忆对照，用 anytime-valid 置信序列（PrPl-EB）跟踪「有记忆相对无记忆的提升」。看最终区间宽度、能否确认提升、能否对持续伤害报警。这是为下一阶段的在线监控做分辨率检查。

### 6.5 额外看的剖面（不作硬门槛）

- 按数据流窗口看提升/伤害是否随时间变坏；
- 按题目难度分层（难度用「另一次 Baseline」的正确率估计，避免和 \(y_0\) 人为相关）；
- 门控上界：若事先知道 help/hurt，理想选择能拿到多高准确率；用可预测模型做「\(P(\text{help})\ge P(\text{hurt})\) 才注入记忆」，和始终开、始终关比较。这是在估「值得不值得做门控」，还不是最终系统。

### 6.6 产出与判定

分析脚本汇总表格，并写出 `verdict.md`：

| 判定 | 条件 | 下一步 |
| --- | --- | --- |
| **GO** | H1、H2 都成立 | 做逐题门控 + 记忆版本选择 + 监控（E1） |
| **PARTIAL** | 只有 H1 | 不做逐题预测门控，改为版本回退 + 监控 |
| **NO-GO** | H1 不成立 | 停止这条线或换设定 |

## 7. 下一阶段打算做什么（E0 之后）

仅当 E0 给出 GO 或 PARTIAL 时继续。

- **GO**：训练/校准一个在线门控：对当前题决定「用当前记忆 / 用某一历史快照 / 不用记忆」。比较始终开、始终关、门控策略，以及事后才知道对错的 oracle 上界。版本快照用基准已有的「冻结记忆文件、禁止继续更新」能力构造。
- **PARTIAL**：不做细粒度门控，重点做随时有效的监控与回退策略。
- 全程继续使用同一批公开数据和同一组官方方法，避免自造数据。
