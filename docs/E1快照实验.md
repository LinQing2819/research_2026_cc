# E1a：公开基线上的快照恢复可行性实验

当前先回答：在相同后续题目上，较早的记忆是否比部署时的最新记忆更好？
这一步成立后，再做在线影子探测、退化监测和回退。此处不宣称实现了完整 E1 方法。

## 公开方法与数据

直接调用固定版本的 `third_party/SeqMem-Eval/main.py`，不修改子模块。
方法为 ExpRAG（日志名 HistoryRAG）、AWM-Online、ExpeL-Online-ST；
对照为官方 Baseline。候选数据为 MATH500、MMLU-Pro Engineering/Physics、
HumanEval、APIBench-HF，直接复用 `data/seqmem/` 已下载的公开文件和官方判分器。

暂不纳入 DC-RS：固定版本 runner 在加载 seed 时删除 `memory` 字段，
而 DC-RS 恰好从该字段恢复小抄，导致恢复后内容丢失。不能把这种结果当作官方方法的公平比较。
ExpeL 的规则从 `memory_meta.insights_after` 恢复；AWM 的工作流从辅助事件恢复。
这些是官方恢复接口下的冻结版本，尚未证明其与原在线进程的全部内部状态逐位一致。

## 设计

1. 读取 E0 的 `flip_summary.csv`、`reproduction.csv`。仅选满足 H1 门槛、
   方法和两次 Baseline 均在论文参考值 ±3 点内的完整格。
   按超额伤害率降序、uplift 升序、名称排序，最多选 3 格。
   偏差超限需先排查，不能为凑数绕过筛选。3 点容差只是复现诊断，不是有效性的统计证明。
2. 按官方数据原顺序，在 20%、40%、60% 位置从 E0 memory JSONL 截取快照。
   完整核对 memory 中主样本的 ID 和原始公开数据顺序。AWM 截取时包括第 K 题后的
   workflow_induced 辅助事件，排除第 K+1 题及以后事件。
3. 60%–80% 为版本选择集，80%–100% 为测试集。三份快照和无记忆对照
   都做同一批后续题，不更新记忆，各跑两遍。
4. 只在选择集上选择最佳快照；另一个策略允许选择无记忆。平分优先最新快照，
   再优先 Baseline。测试集只报告效果，不用于选择部署版本。
5. 输出始终使用最新快照、始终无记忆、选择集选快照、选择集选快照或无记忆，
   以及测试集最佳固定版本和逐题 oracle 的描述性上限。

**这里的“最新”是 60% 的部署快照，不是完整 E0 的最终版本。**
拿完整 E0 记忆测试原数据的后段会泄漏，因为那些题已进入记忆。
Baseline 也重新在固定后续题上运行，避免依赖旧日志的局部位置 ID。
所有输出统一配对到保存的公开题目 ID；APIBench 子集经过裁切后，官方内部位置 ID
重新编号，因此使用清单保留原 ID 映射。

E0 已经分析过这套数据，所以这仍是**探索性实验**。
后续需要新留出数据、独立记忆构建轨迹、更多重复和模型确认，不能称这最后 20% 为
从整个项目开始就从未看过的确认集。HumanEval 测试集只有约 33 题，检验能力有限。

## 服务器执行

以下命令在 `/data/zlq/research_2026_cc` 执行。代码目录中运行脚本；
不要在子模块目录运行。E0 的 runs/reports 保留原位置。

```bash
cd /data/zlq/research_2026_cc
git pull --ff-only
git submodule update --init --recursive
.venv-client/bin/python -m pip install -e .
```

如果 vLLM 已经在 8000 提供 Qwen3-8B，直接复用。否则在单独 screen 窗口启动：

```bash
screen -S vllm
CUDA_VISIBLE_DEVICES=0 VLLM=/data/zlq/research_2026_cc/.venv/bin/vllm bash scripts/e0/serve_vllm.sh
```

等服务 ready，按 Ctrl-A D 离开 screen。若服务器安装在 `.venv-vllm/`，
将 `VLLM=` 改成该环境的绝对路径。模型、生成参数、embedding CPU 设置继承 E0。

先用每段 2 题冒烟（独立目录，不会覆盖正式实验）：

```bash
.venv-client/bin/python scripts/e1/snapshot_study.py prepare --smoke 2
.venv-client/bin/python scripts/e1/snapshot_study.py run --smoke 2 --dry-run
.venv-client/bin/python scripts/e1/snapshot_study.py run --smoke 2
.venv-client/bin/python scripts/e1/snapshot_study.py analyze --smoke 2
```

确认跑通后正式运行：

```bash
.venv-client/bin/python scripts/e1/snapshot_study.py prepare
.venv-client/bin/python scripts/e1/snapshot_study.py run --dry-run
screen -S e1
.venv-client/bin/python scripts/e1/snapshot_study.py run
```

按 Ctrl-A D 后实验继续运行。结束后：

```bash
.venv-client/bin/python scripts/e1/snapshot_study.py analyze
cat reports/e1_snapshot/Qwen__Qwen3-8B/verdict.md
cat reports/e1_snapshot/Qwen__Qwen3-8B/recovery.csv
cat reports/e1_snapshot/Qwen__Qwen3-8B/policies.csv
```

最多 3 格 ×（3 快照 + Baseline）× 2 遍 = 24 个冻结评估作业，
每作业只评估原数据后 40%。不需要重新构建记忆。
默认串行运行，显卡只服务 vLLM。

## 断点与定位失败

- `prepare` 只执行一次；已有 manifest 时拒绝覆盖。要改协议，在 YAML 中用新的
  `artifacts_dir` / `reports_dir`，不要改已运行实验的清单。
- `run` 重新执行会跳过已经完整完成且清单哈希相符的作业。失败的单个冻结作业从固定
  seed 重新跑，不从局部评估结果恢复；因为官方 `--resume` 会禁用 seed 加载。
- `analyze` 要求所有作业完整完成，任何缺失/半截结果都会报错，不静默减少分母。
- 每作业日志：`runs/e1_snapshot/Qwen__Qwen3-8B/outputs/<任务>/<方法>/<版本>/rep<k>/stdout.log`。
- 清单和筛选：`runs/e1_snapshot/Qwen__Qwen3-8B/manifest.json` / `screening.json`。
- seed 和裁切数据都有 SHA256 校验；修改输入会被拒绝。
- 若 `prepare` 提示没有合格格，先查看 `screening.json` 和 E0 reproduction.csv，
  排查复现差异；脚本不会擅自放宽标准。

## 怎么读结果

- `arms.csv`：所有快照在选择集/测试集的准确率。
- `policies.csv`：可部署的选择策略相对最新快照和无记忆的配对增益、固定时点 bootstrap 区间。
- `recovery.csv`：旧快照选择在测试集是否恢复至少 3 点、bootstrap 下界是否 >0。
  `promising_exploratory` 是筛选信号，不是确认性 GO。
  同时报告按题目重复平均差值计算的保守 Hoeffding p 值与跨格 Holm 校正；
  不把同一道题的两次运行当成两道独立题。它们也依赖条件独立题目假设。
- `paired_outcomes.csv`：保留原题目 ID、split、arm、rep，可用于后续复核。
- `verdict.md`：结论边界和下一步建议。

两次冻结评估共用一个 E0 记忆构建轨迹；区间不能涵盖重建记忆的随机性，
也没有随时有效或任意漂移保证。逐题 oracle 与测试集最优版本是偏乐观的描述性上限。

若旧快照在独立后续样本上仍有收益，继续确认并设计预算受限监测；
若只有无记忆更好，优先研究停用记忆；
若上限很小，转向伤害机制干预。不要用一次小样本不显著结果宣称“不存在版本退化”。
