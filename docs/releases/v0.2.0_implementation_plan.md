## 实现顺序

1. **冻结复核记录**：`configs/e2_duplicate_review.json`；记录 V5、完整公共投影 hash、
   原始审计 hash、三对阶段/qid/公共内容 hash、duplicate/distinct、理由与日期/来源。
   将批准的记录 digest 作为 V5 固定参数；不同记录不能仅换路径就获得批准。
2. **纯数据资格模块**：新增 `qualification.py`。
   解析当前原始审计与完整复核记录，校验完整覆盖与所有 hash；
   只允许这次获批的 prefix↔test 例外；产生共同 test 排除列表。
   原审计不改。缺失、改动、额外候选、误报无依据、未决均失败。
3. **不加载模型的数据入口**：`audit-data` 在完整数据/源前缀校验后输出证据及资格，
   使用只读 SQLite 查询旧预算槽；不调用 Ledger 构造器、不重置 meta、不执行生成。
   按 R3 拆出 `load_public_inputs` 的明确公共列投影，不沿用会读取gold的 `load_public`；
   评分数据另读另封存。旧账本必须存在、可读、来源可核验，有效WAL不能漏计。
   单一证据文件含原审计、候选的公共投影、复核摘要、源/数据 hash、
   原始/数据合格计数、旧账本次数及明确下一步。
   失败也保留可以判断失败原因的证据，不让用户继续写零散 Python 脚本。
   稳定数据资格与可变状态快照分开；时间、账本次数、迁移前后identity不进入稳定输入hash。
4. **prepare 接入**：在 hash 权重/embedding 前检查同一数据资格。
   原 split64/96留档，另存过滤后的 evaluation_splits64/94；仅为过滤后题目建检索/提示。
   完整复核文件与代码进入 fingerprint；原始审计、资格、排除进入 manifest。
   保留 `component-v4.sqlite` 同一预算槽，零生成才允许从旧身份迁移；
   V5 同身份重启不受“迁移必须零尝试”的误限制。
   原锁内再次核对迁移条件，并保留原identity溯源；不存在旧槽不能伪装成零次。
5. **主对照检查**：抽成可测 helper，保留旧两因子共同变化检查；
   对 ON−OO、ON−NN、ON−ZE 分别统计完整 token IDs 有区别的 test 数。
   任一为0写证据并停止，不删题/换题/追加重复。report 增加该摘要与数据/上下文分层覆盖率。
6. **Transport 修复**：完整响应与 HTTPError 的 body 读取都纳入保护；
   IncompleteRead 保存部分字节的可核验表示与错误状态，计费重试仍由 Ledger 处理。
   已知400等非重试状态不能因 body 断裂降级为可重试；完整非法UTF-8/JSON不伪装超时。
7. **版本与状态**：软件0.2.0、协议V5分别显示；版本源与 pyproject 保持一致并检查，
   `version`（或 `--version`）不需要模型/数据，`status` 只读账本/已存产物。
   旧审查/协议原文不删除，README明确 E1 是历史工具、当前配置是 e2_component.yaml。
8. **验证**：对新资格逻辑做正反例、零预算只读审计、迁移/恢复、被排除题不生成、
   实际原数据的公共投影匹配（若测试用真实数据则明确本地可选）；
   真实短读 HTTP + 同seed计费重试、400截断禁止重试、无效主对照零生成。
   重跑现有46项，检查版本、CLI、shell、打包与 diff。
9. **文档与发布**：重写 README 主要说明问题、七臂、低功效、当前证据/下一步；
   更新运行手册和 CHANGELOG，汇总两名验证者对全部代码问题的结论与三轮设计状态。
   commit/push main，创建并推送新 tag v0.2.0，生成
   `.cache/releases/memgate-v0.2.0.bundle`（main及该tag，官方子模块保持原commit）。
   不覆盖已存在的同名tag。
10. **服务器交付**：给出通过 bundle fetch/ff-only merge 的命令（服务器没有GitHub SSH）；
    先 version、audit-data；资格通过才 prepare；prepare可行才起E2服务，
    然后 preflight→smoke→run。未取得的服务器验收结果不得写为已通过。
