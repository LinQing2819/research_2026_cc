# 第 1 轮科研评审：新颖性

日期：2026-10-20。范围：V0、V1，以及后补的 V2；只研究，不改代码、不运行实验。

## 1. 明确判定

| 候选 | 本轮判定 | 理由与去向 |
| --- | --- | --- |
| V0：记忆演化 + MIR/局部回放/快照回退 + anytime testing | **FAIL** | 诊断问题、回退与统计验收均已有近邻；没有提出记忆特有、可检验的新机制。 |
| V1：检索更新 + certified zero-effect strata | **FAIL，不能作为独立方法主线** | 零期望效应论证成立，但核心计算节省可被“去重缓存 + 零差跳过”的简单 PACE 改编吸收；分层估计也不是新方法。 |
| V2：规则/经历的跨时间 2x2 交叉 + 组件选择 | **PASS，仅作为待证伪研究方向进入第 2 轮** | 跨时间组件互补与整库回退的损失是具体、可检验的问题；当前草案已有能否证它的控制。但 factorial intervention、混搭和 pilot 本身均不是可发表贡献。 |

**总判定：V0/V1 否决，V2 作为待证伪方向推进到第 2 轮；不放行已成立的方法创新主张，也不放行编码。** 按用户最新指定的评审对象，这个 PASS 只回答“是否值得继续审查并设计证伪实验”，不回答“方法是否有效、新颖性是否已被结果证实、是否可发表”。近期实验范围应限于机制 pilot，且仍须第 2、3 轮通过后才能编码。

选择 V2 的理由不是它更复杂，而是它能回答一个 V1 无法回答的问题：完整快照是否是过粗的恢复单位，旧规则与新经历的组合能否保留有用的新证据，同时恢复被规则更新损伤的能力。

当前草案已纳入纯经历控制、固定组件预算、独立 dev 选择和历史数据仅作 discovery 的限制，因而有明确的失败出口。暂时缺少实验结果不应成为禁止检验该问题的循环门槛；同样，值得检验也不能替代结果或贡献。若最后只重复“抽象会坏、原始经历更好”，正式贡献仍判 FAIL。

## 3. V0 为什么否决

1. **问题不新。** 记忆演化的非单调、负迁移和旧能力损失已被 SeqMem-Eval 与 Faulty Memories 直接研究。
2. **解决部件不新。** 最佳快照回退不是新概念；PACE 已把配对 anytime-valid 验收放进自进化循环。改成外部记忆不自动形成贡献。
3. **MIR 的迁移没有具体机制。** 参数更新中的干扰判据不直接等价于文本规则、检索排名或上下文截断引起的干扰。仅改名为“局部回放”没有说明怎样选样、成本多少、为何优于普通验证。
4. **组合没有可否证的额外预测。** 目前没有说明哪些记忆更新会使通用 replay/回退失效，以及 A+B 会在哪个预注册条件下产生不可由简单控制解释的收益。
5. **统计保证不能补偿方法重合。** 新置信序列并非目标；已有项目中估计对象错配也不能靠换一个 e-process 名称解决。

## 4. V1：数学成立，但方法贡献不成立

### 4.1 零效应证书的准确含义

固定旧/新快照 O、N 和一个与构建独立的题目池 Q。令 P_v(x) 为最终送入生成器的完整输入，Y_v(x) 为正确性，定义：

```text
C(x) = 1[P_N(x) != P_O(x)]
p_Q = |{x in Q: C(x)=1}| / |Q|
Delta_Q = mean_Q E[Y_N(x) - Y_O(x)]
mu_C = mean_{x in Q, C(x)=1} E[Y_N(x) - Y_O(x)]
Delta_Q = p_Q * mu_C
```

当 C(x)=0 且两个调用具有相同输出分布时，期望差严格为零；独立随机作答仍然可以出现一对一错。证书针对**更新的期望效应**，不是每次实现值、每题潜在伤害率或后续学习轨迹。如果 p_Q=0，直接有 Delta_Q=0，无需定义空集合的 mu_C。

必须固定实际模型/权重、tokenizer、chat template、系统消息、解码分布、输出上限、停止条件、评分协议，以及所有输入外的行为配置。比较应发生在最终模板展开和截断之后。仅比较记忆 ID、字符串摘要或检索集合不够；固定随机检索种子也不等于服务端没有隐藏状态。首轮只覆盖冻结的单次解题，不外推到会继续检索、调用工具或更新记忆的多步 agent。

均匀抽取变化子集可以估计 mu_C。但 p_Q 是**这个有限池**的精确比例，不是未来部署分布的已知比例；面向总体需另外处理题目池代表性及 p 的不确定性。正确性在 [0,1] 时还有 |Delta_Q| <= p_Q，因此 p_Q 很小有时足以排除超过容忍量的退化。这同样是直接界，不是新理论。

固定样本量下，用变化子集均匀样本的配对差均值乘 p_Q，可以得到无偏估计；在数据依赖的停止时点不能自动沿用“样本均值无偏”的表述，应使用与目标匹配的有效区间。即使遍历完有限题池，随机生成带来的均值估计不确定性也不会自动消失。

### 4.2 与缓存 PACE 的关键等价

必须区分两个缓存对照，不能将它们混称为原始 PACE 已有功能：

- 普通 prompt 去重缓存 PACE：同题两份输入相同时生成一次、共享输出，配对差为零。对新题通常仍有一次生成成本，V1 确实可能进一步节省它。
- 加零差跳过的简单改编：按均匀顺序取题，渲染两份完整输入；相同则直接记已知零差，不生成；不同才作配对评估，继续抽题直到耗尽真实预算。这是本评审要求额外加入的强对照，不是本轮已核验的 PACE 原论文功能。

第二个对照不偷看答案，是从共享输出必然给出零差得到的直接优化。均匀序列中遇到的变化题仍是变化子集的均匀样本；在相同变化题顺序和解码样本下，基于 discordant pairs 的 PACE 收到相同证据。V1 的“全池预扫描后只抽变化题”主要改变查找变化题的开销，而非每次有效生成的信息量。

需要区分三个结论：

- 相比不利用相同性的独立双生成，V1 能避免噪声和计算浪费，这是真的。
- 相比固定抽 m 道原题、不给缓存基线再投入节省预算，V1 可能更强，但这是不公平预算口径。
- 相比允许跳过零差、继续抽样并复用同一证书的缓存 PACE，**当前没有独立的方法优势**。对于零阈值符号检验，基线甚至不必先知道全池 p_Q。

若增加变化子集内部的异质性分层，必须比较“缓存 + 同一分层/已有 Neyman 分配”，不能把现成抽样技术占为 V1 独有贡献。可验证影响稀疏性仍可作为测量结果或系统优化，但仅发现 p_Q 小不足以成为本项目方法主线。

### 4.3 若保留为辅助机制测量，必须执行的条款

1. 同预算至少比较全量配对、uniform PACE、普通 prompt 去重缓存 PACE、额外加入零差跳过的缓存 PACE、V1；缓存基线必须能重新投入节省的生成预算。全量配对既报告完整成本，也报告预算受限下的固定样本配对版本，不能把超预算 oracle 当公平方法。
2. 计入旧新全池检索、embedding、tokenization、模板渲染、哈希/精确核对、索引与缓存维护、prefill/输出 token、评分和记忆更新成本。缓存命中、query embedding 复用等优化应对所有方法开放；生成调用数不是唯一预算。
3. 主结果是同成本下的错误决策、区间精度/检出能力或达到同一精度的总成本，不只是节省了多少双调用。全池预扫描必须与缓存基线按需检索比较冷启动及多次更新摊销成本。
4. 负控用 **全局规则确实发生改变、且改变保留在最终 prompt 中** 的 ExpeL 快照，预期 p_Q 接近 1；并非 ExpeL 的每次经历更新都满足该条件。低 p_Q 必须先排除没有真正学习、恢复丢状态等实现退化。
5. 先固定 Delta 的总体/有限池目标及回退容忍量。无放回、自适应分层、重复题目、跨版本重启不能直接套用 iid discordant-pair betting；总体均值的原假设也不自动给出每一步条件公平性。序贯有效性留给第 2 轮严格核对。
6. 构建流、评估题、dev、确认 test 分离。未来答案不能进入记忆构建、证书生成或抽样分层；评估信号不得反过来选择同一个 test 上的快照。

**停止条件：** 优势完全由去重缓存及其零差跳过优化解释，或计入全池成本后消失，就停止 V1 主线。不得通过限制缓存基线、改按调用数结算或只展示特别稀疏的更新来维持贡献。

## 5. V2：更值得检验的机制，但需缩窄主张

### 5.1 可操作性与真正的差别

本地 ExpeL-Online-ST 实现支持这个干预：`methods/expel_online_st.py:257-301` 将规则和经历分别放入 solver prompt；`:493-534` 按 query 与经历向量检索，不读取规则；`:612-641` 组合二者生成。因此在冻结推理时可以独立切换两部分，不需要发明新训练方法。

E_N 是新时点的完整经历池，通常包含 E_O，不是“仅最近新增的经历”。R_N 与 E_N 具有共同生成历史；人工交换不代表存在对应的自然在线历史。结论应表述为 **controlled intervention 下组件时间版本的效应与交互**，不是 natural mediation，也不是新因果定理。

相对 Faulty Memories，有希望的增量是：不止比较抽象和原始经历，而是检验**历史上有用的抽象是否能与持续更新的经历共同发挥作用，以及整库回退是否不必要地丢弃了新收益**。这个增量必须由混合臂、组件缺失臂、独立选择与独立验证共同支持。

### 5.2 必须同时报告主效应与交互

令 mu_RE 为同一目标题分布、固定预算和解码下的期望正确率：

```text
a = mu_NO - mu_OO                  # 更新规则，固定旧经历
b = mu_ON - mu_OO                  # 更新经历，固定旧规则
I = mu_NN - mu_NO - mu_ON + mu_OO
mu_NN - mu_OO = a + b + I
规则更新在新经历下的效应 = mu_NN - mu_ON
经历更新在新规则下的效应 = mu_NN - mu_NO
```

正 I 表示在正确率加性尺度上的正交互，负 I 表示负交互；不直接等于语义“兼容/冲突”的证据。结果应报告全体及预先指定能力组的效应，不能在 test 看完后挑组解释。

**混合臂胜出不证明交互。** 例如 OO=0.70、ON=0.80、NO=0.60、NN=0.70 时，ON 优于两个完整快照，但 I=0。这只是规则更新有害、经历更新有益的可加情形。也可能不同题组正负交互相消，使总体 I 接近零。

三类发现必须分开命名：

- 一组件主导退化：有机制价值，但与“faulty abstraction”的现有解释高度接近。
- 超过噪声、截断和选择偏差的组件交互：较有希望，但仍需定位可复现的条件。
- dev 选择的混合版本在 test 上同时保留新收益和恢复旧能力：才支持组件回退的实用价值；不等于未来闭环收益。

## 6. 第 2、3 轮必须落实的设计

### 6.1 快照、数据与恢复

1. 固定两个时点的具体题数和两个流顺序，在看 dev/test 结果前登记；每个顺序独立构建其 O/N，只在同一构建历史内混搭。不能寻找最差新版、最佳旧版后再称预先指定。若该时点没有真实规则差异，要报告干预缺失，不继续挑时间直到显著。
2. 保证构建、dev、test 及近重复题隔离。历史 E0 已参与诊断的题只能用于 discovery；把其后缀重命名为 test 不会恢复确认独立性。若日志曾用过所有题，应重新安排未接触评估题的构建流，不能仅换题目顺序。
3. 先定义稳定性组 S 与新增收益组 P，不能按 test 上 OO/NN 的答题对错分组。可用预先固定、答案盲的子主题划分和分阶段构建流；两个顺序可在同样阶段内部置换。若使用完全混洗的同分布 Engineering 流，只能研究继续更新效应，不能自动解释成“新能力学习”。
4. “新能力”仅指新构建阶段带来的能力收益，不是声称模型预训练时从未见过该知识。需要在独立 P 组实际验证 NN 相对 OO 有可保留收益；没有这项收益，就没有 plasticity-preservation 的实证对象。
5. `runner.py:175-183` 的通用 seed 路径会移除 `memory`；当前 `restore_state_from_memory` 又从中恢复 trajectory。现有评审已指出端点不保真风险。必须先证明冻结 OO/NN 的规则文本、案例、排序和最终 token IDs 与对应快照一致。此处只列前置要求，本轮不修代码。
6. 冻结推理能用忠实的渲染状态研究；后续闭环还需要规则票数、待处理成功批次等完整状态。当前恢复把规则计数设为 1，不足以证明继续更新保真，不能把离线混搭直接称为可部署的组件回退。

### 6.2 因子隔离与 prompt packing

7. R 和 E 使用预先固定的独立 token 额度、条目优先级和完整条目截断规则，不借用对方额度。固定 E 时，换 R 不得挤掉例子；固定 R 时，换 E 不得改变规则文本。否则 I 可能只是共享上下文容量竞争。
8. 同一题的 E_O/E_N 检索结果应分别固定，再供各 R 臂复用。固定模板、组件位置、top-k、模型、解码、评分；保存完整 prompt token IDs、实际长度、丢弃条目和版本信息。相同预算上限不等于实际等长，不能用所谓“无意义 padding”假定没有效应。
9. 如果新 packing 改变了原始 OO/NN，必须明确研究的是统一 packing 下的四个端点，并另核对其与原始端点的差别。不能把预算改造带来的收益归为组件回退。超长题应在生成前、按所有臂一致规则处理并报告覆盖率。

### 6.3 基线与独立 selector

10. 至少保留四个时间交叉臂、同 scaffold 的无记忆臂、仅新经历臂 `(R_empty,E_N)`。当前草案还加入仅新规则臂 `(R_N,E_empty)`，建议保留，形成 7 臂；如要声称旧规则自身的互补作用，可另做预登记的旧规则缺失/保留对照。不要把模板不同的官方 Baseline 当成唯一无记忆控制。
11. 完整快照 selector 只在 dev 选 OO/NN；组件 selector 只在 dev 选 OO/ON/NO/NN。固定目标权重、平局规则和一个整体选择，不在 test 做逐题选臂。组件 selector 选回完整快照也是合法失败结果，不强迫它选混合臂。
12. 同时比较固定 ON、固定 NO、始终 NN、仅新经历。若固定 ON 已解释全部收益，不能宣传数据驱动 selector 的额外价值；若仅新经历更优，优先接受“无需旧规则”的解释。
13. 方法性能比较必须计入 dev 选择成本。4 臂 selector 不能用双倍于 2 臂 selector 的评估预算却称同预算胜出；允许完整快照 selector 将省下的预算用于更多独立 dev 题或重复。固定策略也应显示其零选择成本。机制实验可共享各臂结果，但决策预算必须分别记账。
14. test 上的 `max(OO,ON,NO,NN)` 或 `max(OO,NN)` 是带选择偏差的诊断量，不是部署策略。主要效果应是 dev 已固定的组件选择对 dev 已固定的完整快照选择的配对差值，并报告固定策略对照。

### 6.4 稳定性、可塑性与停止条件

15. 预登记最小重要收益和非劣界限，不能在看到结果后调小。确认研究需要检验：所选策略在 S 上相对 NN 有恢复、对 OO 非劣；在 P 上相对 OO 保留正收益、对 NN 非劣；在预定权重的总体目标上优于完整快照 selector。仅总体分数更高不证明同时保留两种能力。
16. 两次回答估计平均正确性，不采用 pass@2 或从两次中挑最好。按题配对，将解码重复与构建顺序的随机性分开；两次解码不等于两条构建轨迹，两个顺序不足以可靠估计跨轨迹总体方差。交互尺度、多个对照和多个能力组的误差控制交给第 2 轮审核。
17. pilot 不能要求小样本显著才继续，也不能把不显著当无交互。应事先设定一次 pilot 的预算上限、可识别的大效应范围，以及“不确定时如何进行一次有功效的确认设计”；禁止不断换时点、任务和顺序追显著。
18. 若混合优势消失于恢复修正/分组件 packing，或仅新经历、固定混合策略解释全部目标收益，就否决相应主张。若无 NN<OO 的退化，不得称“恢复整库退化”；若无新增收益，不得称“保留 plasticity”。可记录诊断结果，但不据此自动续命方法主线。

## 7. 最小 pilot 与当前草案的差异

主代理曾提出的备选：ExpeL / MMLU-Pro Engineering，固定两个时点、两个流顺序，dev=48、test=96，每题每臂 2 次回答。若有预定义 S/P，可先按 dev 各 24、test 各 48 分配；这不是足够功效的保证。这些数字不是用户要求，已由后续 V3 唯一协议取代。

| 范围 | 独立求解调用上限，不含构建与评分 |
| --- | --- |
| 4 交叉臂 + 无记忆，2 顺序 | `(48+96) * 5 * 2 * 2 = 2880` |
| 加入必要的仅新经历对照 | `3456` |

本轮读到的 `docs/research_v2_draft.md` 已包含仅新经历/仅新规则控制、分组件预算和历史 discovery 限定，方向正确，不要求重复添加。其具体配置却是历史单条构建、20%/60% 时点、dev=64/test=96、2240 次求解，与最新“双顺序、dev=48”的提案不同。实施前必须合并成唯一版本；本轮没有修改该草案。

**功效警告：** 即使忽略题间异质性，仅假设四臂正确率约 0.5、各臂两次独立作答，96 题的 I 所含解码噪声标准误已约为 `sqrt(1/(2*96)) = 0.072`，正态近似 95% 半宽约 14 个百分点。这只是示意，不是完整功效分析；还未计入题目泛化与构建历史的不确定性。该规模只能探索大效应、验证干预是否真实、估计后续方差，不能据此发表一般性的兼容性结论。

## 8. 更强改案与交接

建议把 V2 修订为以下可落地问题，而不是再加一个通用算法组件：

> 在规则与经历独立限额、分阶段引入新任务经验的冻结 ExpeL 中，历史规则与更新经历能否形成优于完整回退和纯经历记忆的组合？收益来自可加的组件差异还是可复现的跨时间交互；独立 dev 能否选到保留新阶段收益的恢复策略，并在跨构建历史的比较中体现超出固定混合策略的选择价值？

这保留现有 ExpeL、2x2 干预和简单 selector，新增的不是代码复杂度，而是排除已有解释所需的控制与可否证目标。V1 可作为各臂评估的去重优化，对全部对照同等开放，不再挂成另一项创新。

第 2 轮重点审查：唯一的快照/数据/预算协议；S/P 或放弃双能力主张的明确选择；包含 episodic-only 和固定混合的主要比较；交互与策略收益分离的判据；功效、选择偏差以及失败/不确定结果的处理规则。第 3 轮应检查恢复保真、因子隔离、数据时序与执行可行性。这些条件仍是编码前的硬约束，不因本轮方向 PASS 而豁免。

本轮最终结论：**V0=FAIL；V1=FAIL；V2=PASS（仅待证伪研究方向，可进入第 2 轮）。方法贡献与可发表性尚未通过；实验最多先做机制 pilot，三轮通过前不编码。**
