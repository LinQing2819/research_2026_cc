# 第三轮统一审查稿：自然记忆更新的增量信息诊断

稿号：E4-D0，2026-10-27。这是研究诊断提案，非冻结执行协议。E3-R1已完成且筛查未达门槛，不重命名旧结果。

## 1．研究决策

当前不继续调E3的GP、不换RL、不增大候选数。保留唯一研究问题：

> 固定基础模型，在自然形成的外部记忆更新上，加入旧版本的参照信息是否有价值；在相同双端点信息集与计算预算下，关系表示是否比共同难度、独立端点预测和直接双端点输入更好地预测未见历史与题目族上的逐题收益差值？

长期用途是同预算下更精确地估计一次更新的有限题池平均收益。**第一阶段只检验预测信息，不做自适应选题、失败发现器、记忆修复或提交决策。** 目标收窄后不再用“发现更多失败”作为成功指标。此前各稿中的A/B命名以本稿的唯一问题为准。

这是可证伪的经验问题，尚无新算法贡献。若关系建模被简单端点或已有方法解释，则结束此算法方向；负结果也如实保留。源绑定作为当前主线退出，因为缺真实源谱系，且旧规则在新版本中保留。

## 3．估计对象与信息条件

定义`tau(h,q)=E_decode[Y_new−Y_old | h,q]`。`h`是独立构建历史中事先指定的一次自然更新；`q`为未进入构建和拟合的题；旧新分别冻结完整提示和评分。预测器信息改变不改变solver的真实干预。没有跨臂共同随机数假设。

冻结有限等权题池内主诊断为**按题中心化的有符号残差方差差**，辅助为signed平方预测损失差及分组不确定性。不是以残差均值或单独MSE下降作为省题证据。固定预测`m(q)`后，独立均匀无放回抽样审计可用既有模型辅助估计：

`全池平均预测 + 审计题平均(实际配对差−预测)`。

这是标准残差校正，不主张新发明；常数预测会消去，等价直接paired均值。故猜对更新总体好坏尚不够，必须有题间结构才能节省总体估计的方差。没有可靠全池真值时，本阶段不声称最终估计误差已降低。

合法对照共享训练/校准标签、简单预测头的容量与调参次数、可见题库、成本边界：

1. 零差值、开发任务常数、未见更新上16道共同校准题的paired常数。
2. 题目＋新版本，允许强单版本边界特征；另列廉价变化量（长度、条数等）。
3. 两端分别预测`p_new`与`p_old`再相减。两端共享合法配对数据，不能故意削弱旧端点。
4. 相同预算的旧新原文rawpair输入；直接diff＋CheckList行为测试思想的同题池评分适配，不恢复出题模块。排序分数如需转成有符号预测，校准映射只用开发/合法校准标签拟合，必须在审计前锁定。
5. 候选关系表示（仍待单独冻结具体模型）；真实版本与按任务、长度/格式匹配的置换关系作敏感性检查。

`diff=g(old,new)`是确定函数，不能宣称比双端点原文增加信息；只能比较有限计算条件下的表示帮助。只胜new-only或者不相关旧文本不够支持关系算法。若输入容纳不了同等双端点信息，记录预算不合格，不只截短强对照。

原E2/E3表上的拟合、参数选择和诊断只能属于开发，不进入独立评价。不能依旧test结果定义题族、挑规则或选“值得更新”的样本。

## 4．分离学习与测量

- 第一步只读资格：定位自然构建历史、真实父子版本、评分器及题族划分。缺数据是未知，不假定不存在或自动新建。
- 每个任务计划三条根历史，一条开发、两条留出，每历史一次预定进度窗内的首个合格自然变化；不按效果或错误挑更新。生成多快照不增加独立历史。
- 任务候选为MMLU-Pro Engineering和APIBench-HF，仅因为已有接口可核查。APIBench的AST匹配是评分代理，不等同真实工具执行；适配器历史反馈缺陷必须先核实，不能默认已修复。
- 新题族从构建、拟合、校准、审计间隔离；同模板换数字不跨集合。不确定同源合并。若工程题或API任务没有足够隔离材料，资格失败，不临时替换更容易出正结果的数据。
- 旧池重排独立构建，只能对固定池构建随机性推断；互不重叠来源支持更宽条件，必须区别报告。两任务各有开发历史不叫零样本跨任务迁移。
- 预测器禁止读取审计gold、旧后缀模型结果、qid、源ID和绝对时间等身份捷径；评分器独立持有gold。规则/适用条件族跨侧重合必须检查，无法隔离时限缩迁移主张。
- 每留出历史的16题校准使问题成为有限标注适配，不叫零样本未见更新。预测和全部超参数锁定后才看审计答案。
- 独立解码按预定时序交错，保留完整输入IDs、seed、后端身份。相同输入的重复负控制检查测量偏移，不用它来保证其他题的效应。
- 审计每版本4次回答预先拆2组，每组2次；聚合比较有符号差值、残差与组间复现。4次仍不足以给单题稳定回归标签。
- 对同一审计结果比较预测损失差时，预测必须与审计解码独立；噪声共同项在期望中可抵消，但测量方差仍报告，不得宣称潜在真效应逐题已知。
- 如果讨论平方效应，可用独立组乘积作聚合诊断，不把负的估计截成0。它不是主成功指标。

## 5．预算仅是规划上限

候选形状：2任务×3历史×(16校准题×2版本×2rep＋32审计题×2版本×4rep)＝1920条成功回答。

建议全路线不超过3072次已提交attempt，输入+输出预留至多24,379,392 tokens；另建议最多72 GPU小时和24人工小时，任何一项先到就停止并报告未决。**这些是拟议资源边界，不是用户已确认的资源配额，也不保证能完成。**

剩余1152次必须覆盖构建、全部全池特征/强对照、失败与重试、预先分配的同输入重复控制。逐项分配尚未落实；不能声称足够新建六条历史。全部方法合法共享同一solver表，不重复计真实生成，也不隐去各自如果独立部署的总成本。旧日志复用的历史成本另报，不叫方法免费。

| 必须分配的剩余额度 | 当前状态 |
|---|---|
| 新根构建及curator更新 | 待存量资产资格，不能按0计 |
| 全池特征、边界和强对照调用 | 待锁定模型与每方法上限 |
| 同输入控制、探测 | 待数量与请求身份表 |
| 失败、未知派发及重试 | 待统一计费和停止规则 |

四项合计不得超过1152；没有填齐前不实施。多轮逐次计attempt，curator或双端点输入超长时修订设计，不静默截断或借用更大上下文。

上述6条中只有4条留出；不做跨历史普遍性显著结论，不声称确认3pp收益或非劣。小样本结果可支持继续设计或停止；信息不足允许未决。未来完整效用/采集试验需要独立功效与成本方案，不能沿用这张表作为最终确认。

## 6．近邻决定了贡献上限

GBV-PD已有进化模型逐题增量预测与回归排序，区别是可微参数变化而非离散记忆；Testora/DiffTestGen/CheckList已有变更测试；FAQ/AEA/tinyBenchmarks已有高效评估；SELECT-LLM侧重标注预算；PACE已有配对验收；CounterMem/MemAdapter/SkillSmith/CMI/MemIR已覆盖条件、干预、来源与更新管理的重要部分。

本问题的黑盒、离散记忆、稠密提示变化和随机解码是适用条件，单靠这些词不构成新贡献。只剩下待检验的**自然更新下关系信息的有效性与失效边界**。任何正向诊断仍需具体算法差异或有价值的系统性实证，不能立刻宣称可投稿新方法。
