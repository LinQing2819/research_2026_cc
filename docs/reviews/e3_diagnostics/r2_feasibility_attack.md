# 第2轮：候选A/B的可执行性攻击

日期：2026-10-27。依据第二轮共同稿及三份R1分工笔记。
本轮只读现有导出、公共题库和源代码；新增模型调用为0。
未修改E2/E3实现、协议、数据、账本或共同候选稿。

## 1. 决定与首选

**首选A，但仅保留“版本信息审计 + 更新相关失败发现”；B暂缓。**
这里A/B严格采用[共同稿](r2_candidate_revision.md)定义：
A是用旧新版本信息选择冻结题池中的验证题，B是真实源经历绑定的特异保护作用。
不沿用本代理R1中对备选B的命名，也不再把生成新题作为A的第一步。

A的研究价值不是“配对差值、主动选题或回归测试是新的”，而是检验：
**在尚未购买候选回答时，真实旧新版本关系是否能提高更新相关失败的发现效率，
并且足以支付获取这些信息、筛选和独立复核的成本。**
若不能超过新版本信息和直接旧新文本提示，就不扩算法。

R3应明确分开两个目标：

- **Challenge收益，主目标：** 同总成本下，定向选出的任务中有多少更新相关损害，
  以及这些损害在新解码中能否复现。任务族去重，报告未决；不据此估计总体退化率。
- **总体效用，独立描述：** 另设随机审计集估计指定题池上的平均新旧差。
  不能用challenge均值替代；小审计集不能发安全、非劣或部署证书。

当前判断：**A研究诊断HOLD，B机制实施NO_GO，新增GPU运行NO_GO。**
这不是否定A/B的全部可能性，而是现有独立更新、源谱系和确认设计尚未合格。

## 2. 真实产物核查：源并非完全不存在，但粒度不够

### 2.1 导出与服务器封存的区别

本机真实包为`.cache/e3-r1-run.GEfoWE/e2-table.json.gz`。
包内有158题、2212条回答投影、两个快照；快照仅有
`completed/pool/prefix_sha256/rules`，池条目仅有`qid/question/trajectory`。
没有逐规则源ID，没有逐步curator原始输出，也没有当前回答正文。

但manifest列有服务器封存文件：

| 文件 | manifest中的文件SHA256 |
|---|---|
| `prefix_raw.json` | `ae520325ae87a994b7fd6c01fa1301921ca531ebd559fc000b3aaeaba66e8d57` |
| `old_prefix_raw.json` | `137c57528e7757e3a3c12986752ba02984cb644d291f51d74101122f609f6593` |

[导出器](../../../src/memgate/replay/export.py#L37-L51)在导出时逐一校验这些文件并解封，
但[最终投影](../../../src/memgate/replay/export.py#L184-L190)不把prefix原文装入包。
因此正确结论是：**导出时已验证其存在，本机尚无原文；不能说服务器没有来源记录。**
本轮未SSH，未确认这些文件现在是否仍可取回。

[导入器](../../../src/memgate/experiments/source.py#L91-L134)曾校验逐步
`insights_before/after`链、成功反馈、轨迹、池大小和8条成功经历的batch状态。
下一步只需读取封存prefix，不能通过重跑E0“恢复”原历史。

### 2.2 能恢复更新输入批次，不等于能恢复逐规则来源

本机`expel_online_st.py`哈希与真实manifest一致：
`8956fbeea3d9b8afe169a57883af17b377c2655272a148b57dc631bb1779cb3a`。
据此核查实际构建机制：

- [curator输入](../../../third_party/SeqMem-Eval/methods/expel_online_st.py#L353-L379)
  是当时整份旧规则和最近8条成功轨迹，不是每条规则各自独立归纳。
- [更新调用](../../../third_party/SeqMem-Eval/methods/expel_online_st.py#L475-L486)
  将原始输出解析成操作；[保存记录](../../../third_party/SeqMem-Eval/methods/expel_online_st.py#L644-L705)
  只有更新前后文本和状态，没有保存curator原始操作、逐规则引用或支持计数。
- `insights_batch_updated=True`也可能只是AGREE改变权重；
  不能把该标记数当作语义更新数。排序、截断、ADD/EDIT的最终结果还须按文本链核查。
- 从成功池顺序与代码可推得旧时点经过12个完整batch、新时点经过37个，
  端点间跨25个batch边界。它们不是25条独立历史，也不保证25次实质规则改变。

取回prefix后，可以确定“某次更新实际见过哪8条轨迹、前后规则是什么”。
**这叫可追溯输入批次，不叫某条新规则的唯一真实来源。**
旧规则本身也携带更早信息；语义上最相似的那条经历不能被倒填成来源。
若仅能恢复batch，B必须改称“真实更新批次证据对照”，这是另一种较弱命题。

### 2.3 独立更新不足是A/B共有门槛

目前已验证的只是同一历史193/581两个端点。
六条新增规则不是六个独立更新，七种组件组合不是七条独立历史，
多次读取顺序和重新抽seed也不会增加历史数。

取回中间链可支持**同历史自然变化的开发诊断**，却不能验证迁移到未见历史。
配置中列出其他任务不等于其运行已完成；本轮没有证据确认另有合格历史。
新建历史必须计入solver与curator成本；从同一旧快照分叉只能条件于共享祖先，
不能不加说明地当作独立从零构建。

## 3. 任务池：可评分不等于可做机制确认

本轮只读公共题库的`question_id/category/question/options`，未读取新增题的答案或CoT。
文件哈希`0e24a191921c2f453518a537a8b2117bd137e7714d4ef1565e9ba06c1ecb9ad8`
与真实manifest一致；158题公共题干逐项匹配。

| 可用对象 | 本轮核实 | 能做与不能做 |
|---|---|---|
| 既有E2表 | 工程158题，两rep/臂，成绩已看过 | 可开发审计；不是新题确认集 |
| 工程公共全集 | 969题；构建前缀581，后缀388 | 有确定选项评分；不是独立物理推理oracle |
| 未进入本次E2导出的后缀 | 230题，其中2题为已确认重复而排除 | 名义剩228题，尚未通过新的题族隔离和重复审计 |
| 同文件其他学科 | physics 1299、math 1351 | 文本在本机；源历史、跨学科重复与任务资格未验证 |
| HumanEval | 仓库适配器声明164题、子进程执行检查 | 本机未见对应数据；需沙箱和测试充分性审查，不是现成大题池 |
| APIBench | 仓库适配器使用AST子树和domain匹配 | 是可自动评分，不是执行真实API并验证状态的环境 |

工程剩228题只能称“没有本次E2回答”，不能称从未被系统见过：
原E0源文件覆盖969题；本轮没有读取其后缀结果，旧快照也不含这些后缀经历。
新增研究必须显式隔离这些旧结果，不能挑已知易受害题作为独立确认。

**最低任务合同：** 选择器只见公共题干/允许的版本信息；
评分器隔离答案；构建、开发、challenge和背景审计按语义题族隔离；
有争议的题目先裁定或排除，规则文本不得兼任答案oracle。
换数字、换选项或同一公式改写不增加独立任务族。

如果R3只研究选项正确率变化，MMLU可承担受限pilot。
如果要声称“修复前提误用”或“工具行为安全”，就必须另有条件明确的数值判据或状态检查器。
不能因为解析出字母，就宣称已验证推理、记忆适用条件或长期自进化。

## 4. 对A的核心攻击及必须修订处

### 4.1 差分不是凭空增加的信息

`D = diff(M_old, M_new)`由两版本确定。
相对只看新版本，增加的是旧版本信息；相对已看旧新全文，显式diff主要是表示和计算便利。
因此至少区分：

1. 任务 + 新版本。
2. 任务 + 旧新原文，直接提示；这是必须击败的强简单对照。
3. 同样原文 + 显式变更表示；只能把超过2的部分归于表示/使用方式。
4. 新版本 + 错配旧版本，作为关系破坏负控制。

错配旧版可能增加干扰；击败4不能证明优于1，更不能证明diff本身有独立信息。
必须避免截断使主方法比基线多看有效正文。每种条件都计特征生成tokens和延迟。

### 4.2 当前版本变化稠密，不能直接套用稀疏RTS节约

所有题都保留全部旧14/新20条规则；ON/OO的经历top3在test93/94题改变。
“命中变更项才测”几乎等于全测；完整输入相同也仅提供极少数跳过机会。
暴露关系有价值，但“被暴露”不是“受害”，相同记忆ID也不代表相同完整上下文。

而且A必须明确版本对象：规则更新固定经历，还是规则与池一起更新。
整体版本可用于端到端失败发现，但不能把结果归于单条规则内容。
新规则14的孔径公式、继承规则5的海水公式和经历11697错误均只能提供开发假设；
它们没有证明E2的具体退化由相应内容引起。

### 4.3 失败发现、总体估计与修复是不同目标

建议R3以**更新相关损害发现**为主，收益发现单独列为次要结果。
不以`abs(新旧差)`为唯一目标，否则改善和退化会被混在一起。

先固定少量候选任务，再用全新独立解码复核。至少区分：

- 新旧都常错：通用难题，不能记作更新新增失败。
- 选项变化但对错不变：行为差异，不是准确率退化。
- 旧对新错的一次样本：待核查候选，不是已确认因果标签。
- 新旧期望正确率的负差获得支持：更新相关损害；仍不自动定位单条记忆机制。

题11985的相同输入、ON两对/OO两错反例已说明：两rep内部一致不足以贴标签。
同题配对消除题目组成差，不会自动消除解码噪声；E2跨臂rep也不是共同随机数。
保留同版本独立解码控制，不能删掉“不稳定”题来制造清楚的机制。

**没有全题参考表也能检验发现收益：** 独立复核各方法提名的并集，
按任务族去重并记录各自提名来源，不把别人的发现计入本方法。
但此时不能声称全题失败召回率，因为未测任务中有多少真失败尚不知道。
独立随机背景样本可提供另外的总体描述，不能填补全部遗漏标签。

### 4.4 “迁移”不能用一个更新里的随机分题替代

固定新规则后分训练题/测试题，只检查题目泛化；
让同一规则家族的改写跨集合，也不能检查未见更新。
当前表可检验信息特征是否有开发信号，不能验证真实旧新关系的跨更新价值。
若新方案必须依赖大量参考历史才能工作，就应先支付并报告建表成本，
而不是用七臂旧表冒充丰富的历史模型库。

## 5. 为什么不优先B

B有较清楚的交互目标，但当前缺三项前提：

1. 没有逐规则的可验证来源绑定；恢复8条输入batch不解决唯一源归因。
2. 端点旧14条语义全部保留，没有观察到共同稿最想研究的“旧前提丢失”。
   新增错误和继承错误不能替代这种自然变化。
3. 真实源往往更贴近内容或更完整，匹配非源只能控制可见相关性。
   把全部差异命名为“来源性”会过度归因。

即使将来有来源，仍要区分“附加了有用证据”和“正确绑定本身有用”。
可用同一证据集合置换绑定关系，保持长度、格式和位置尽量一致；
但模型可能从正文恢复语义对应，置换无效也须解释实际干预是否发生。

B若用旧新规则×真实源/匹配非源/置换源，再加经历单独与ZZ，
至少8种条件，且8条源batch通常不能原样装进现有经历预算。
筛哪条、如何压缩又成为新干预。其构建、匹配、packing和确认成本明显高于A的两版本验证。
**停止线：** 只能靠人工删前提或语义检索倒填来源时，不实施自然源绑定机制主张。
不能先制造符合假设的错误，再用正结果为真实持续记忆更新背书。

## 6. 预算：省的是新回答生成，不是标注

MMLU标准答案已在评分侧，自动评分很便宜。
所有候选全量生成后再挑“值得标注的题”，不会节省本项目的主要成本。
全文diff、CPU检索和token计数不需要solver，但CPU时间也要报告；
LLM语义打标、边界卡、批次压缩、预试、裁判和失败调用均须计入。

最低成本式：

`C_total = C_build + C_features + C_discovery + C_confirm + C_background + C_controls + C_failures`

同时报告两本账：
物理实际调用账允许合法缓存复用；每种策略的独立部署成本账不能免费借别人的回答。
历史回答可在严格相同请求身份和预定信息边界下复用，
但独立确认必须用新的保留样本，不能把已用于提名的回答再次记作确认。

### 有限pilot的上界形状，不是准入协议

供R3取舍：最多2048 attempts，单GPU；每attempt若满足输入<=5888、输出<=2048，
则总预留上界为16,252,928 tokens。多轮、超长curator输入不能偷偷算作一次合规短请求。

例如最多2条合格构建历史、每历史1个预先选定自然更新，6个策略槽位：

| 用途 | 最坏不重叠情况下的调用数 |
|---|---:|
| 每策略选8题，旧新各4rep | `2 * 6 * 8 * 2 * 4 = 768` |
| 每策略预定最多2个提名，旧新各8个全新rep | `2 * 6 * 2 * 2 * 8 = 384` |
| 提名题的ZZ参照各4rep | `2 * 6 * 2 * 4 = 96` |
| 每历史16道独立背景题，旧新各4rep | `2 * 16 * 2 * 4 = 256` |
| 构建、特征、同版本控制、探测、失败和重试共享余量 | 544 |

合计2048。六槽可为随机/分层、任务embedding加暴露、多条件中的新版本、
直接旧新全文、显式diff、错配旧版；**这是信息pilot，不是已覆盖全部论文基线的正式比较。**
去重节省不得变成追加提名追显著。8rep不是单题确认保证；不够则记录未决。
两历史也不支持跨历史总体统计结论，更不能包装成长期闭环。

仅从零构建两条各96题的单次尝试历史，就可能需要192个solver调用和最多24个curator调用，
还不保证出现合格自然更新。若到预定上限没有合格更新，就停，不继续找阳性历史。
若要求R1原形状的四条581题历史，仅solver已需2324次，远超其构建余量；
不能把已有一条历史免费复制成四条。

建议另设48 GPU小时、16人工小时的硬停止线，先到即停；这不是完成时间预测。
curator八轨迹输入若无法在冻结限制内合法处理，先修订设计再审，
不能运行时静默截断或改写记忆。正式单GPU预算仍须由R3冻结。

## 7. 少量近邻的最终约束

本轮仅增加2次一手页面请求，用户要求收束后不再检索：

- [AEA，2410.05952v1](https://arxiv.org/html/2410.05952v1)，实际读到摘要、§1、
  §2.1–2.2、§2.3前段。它已明确只获取选中prompt的评估结果，
  用历史模型结果学习题间关系；并非仅节省人工标注。
- [FAQ，2601.20251v3](https://arxiv.org/html/2601.20251v3)，实际读到摘要、§1–2、
  §3.1前段。它明确对固定题库减少模型推理调用，使用历史结果和主动选题，
  并区分评分标签成本与inference成本。不能以“我们节省生成”否定这个近邻。

本轮没有重审两者证明或复现代码；FAQ的固定结果题库保证不能自动套给随机解码期望差。
对A更直接的变更测试威胁仍见[R1](r1_problem_reframing.md)中的
FastCI、Testora、DiffTestGen；对B见[记忆文献稿](r1_memory_literature.md)中的
Faulty Memories、CounterMem、CICL和SkillSmith。本轮不冒称再度独立全文核验。

因此，**节省生成、同题配对、版本差分、选受影响任务均不能单独构成创新。**
只保留一个待检验命题：真实版本关系能否在新回答购买前提供超出简单强对照的发现价值。

## 8. 最小诊断、停止线与R3交接

**D0：现在可做，新增生成0。**

1. 取回并核对封存prefix，列出实际语义更新、重排、输入batch和可追溯性缺口。
   不改服务器checkout，不重跑构建，不补造单规则来源。
2. 对名义228题及其他候选公共输入做题族隔离、重复与评分资格审计；
   不查旧后缀答案来挑受害题。明确哪些仅能测选项分数。
3. 写一个信息可见性表和六槽策略规格，明确相同掩码下先比信息，
   后续才研究自适应分配。本轮不实现预测器。

**D1：仅在R3同一修订稿通过后，才可申请有限生成诊断。**
先固定自然更新、题池、提名数、重复数、误报/未决规则和全部预算。
以challenge发现与独立复核为主，不求选出ON，不自动修复记忆，不自动提交新版本。

**停止或降级：**

- 无可审计自然变化，或只有一条历史：不能进入跨更新/跨历史确认；最多保留条件性案例。
- 找不到足够独立题族或独立评分条件：停止机制确认，不以换数字补分母。
