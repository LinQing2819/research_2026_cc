### 2.2 评分资格的准确边界

[评分实现](../../../third_party/SeqMem-Eval/tasks/apibench_ast_eval.py#L183-L233)先寻找候选库中首个匹配条目：函数名相同，要求参数文本作为子串出现；HF参数提取保留位置参数和关键字参数的值，[不要求关键字名称一致](../../../third_party/SeqMem-Eval/tasks/apibench_ast_eval.py#L98-L125)。最后比较[匹配项domain与gold domain](../../../third_party/SeqMem-Eval/tasks/apibench_ast_eval.py#L280-L294)，不要求与样本金标准调用完全相同。

因此只能称“冻结候选库上的AST/domain代理正确率”，不能称真实工具调用成功、参数合法性或状态正确性。其他需冻结的评分细节包括：候选库顺序、同名多个调用只检查首个候选调用、解析失败计错、缺domain可能出现`None == None`。后者要求数据资格先拒绝缺失domain，不能把缺失元数据当有效真值。本轮没有执行官方一致性测试，代码注释所称保留官方规则不等于已验证与上游实现逐例等价。

[数据加载](../../../third_party/SeqMem-Eval/tasks/task_apibench.py#L76-L95)同时要求`huggingface_eval.json`和`huggingface_api.jsonl`，并按行重新赋1-based qid。[E1切片](../../../scripts/e1/snapshot_study.py#L162-L178)保留外层原qid映射，说明新协议也必须保存原样本身份，不能用切片后的序号作为跨集合ID。`build_inputs`和记忆记录含gold字段，见[接口](../../../third_party/SeqMem-Eval/tasks/task_apibench.py#L139-L145)；未来预测器不能直接消费完整字典，须只接收允许字段。

## 4. 最小自然更新协议：能限定什么，不能保证什么

建议仅对Engineering提出下述新采集合同，保留完整“规则＋经验池”版本对象。它不是复现旧581题构建，也不是现成可直接运行的冻结实现。

1. **输入封顶。** 事先按公开语义题族分配3条从空状态开始的构建根，每根最多32道不同构建题；顺序、角色（一开发两留出）及随机性登记后不得按结果更换。每根一次新进程/新状态，无manual fewshot、无旧seed、无resume。任一根未合格，不能再抽第4根补齐。
2. **单次调用。** 固定ExpeL-Online-ST非交互路径、`top_k=3`、`batch_update_size=8`、`max_num_rules=20`、空初始规则；每题solver最多一次，无反思、纠错、追加尝试。每8条成功触发一次curator，每根最多4次，因此每根生成调用上界为`32 + floor(32/8) = 36`。成功不足时curator更少，而非循环直到成功。
3. **预定更新窗。** 第一批用于形成初始规则；只在第2至第4个成功batch中取首个“旧规则非空、更新前后渲染规则文本不同”的更新。资格只看完整输入可容纳性、记录完整性和文本变化，不看校准/审计效果，不挑负收益或某条规则。仅计数变化而渲染文本不变不合格；纯重排单列，不伪称语义编辑。若研究必须排除纯重排，应在采集前固定该规则。到32题仍无合格更新即失败停止。
4. **真实父子版本。** 选择对应在线步骤之前和之后的完整状态：规则、计数、成功池、待更新batch、排序与检索配置均保留。该步骤可以同时加入经验及改规则；估计对象就是整个自然步骤，不归因于单条规则。不要把curator前后的人造固定池对照冒充在线父子版本。
5. **上下文和输出。** 提议本诊断统一solver/curator最大输出512 tokens，预测调用也不超过512；每个完整chat-template输入不超过5888 tokens，且输入加输出不超过冻结后端上下文上限。8条完整成功轨迹即使各至多512 tokens，仍有8个题干、旧规则及格式开销，**不能保证curator装得下**。在每次派发前用同一tokenizer计数；超长即停止该根，不截轨迹、不摘要、不缩成rules-only、不换大上下文。512是新协议约束，可能降低成功率，不以旧2048-token结果保证可行。
6. **无保证停止。** curator空输出/无有效操作是一次已花费调用，不重问；可继续至预定窗末，不能扩大窗口。超时、未知是否派发、状态写入不完整或上下文不合格则停根，不带不完整状态继续。最后只报告合格/失败/未决及调用数，不保证三个根或任何更新形成。

现有代码支撑与缺口：

- [`generate`](../../../third_party/SeqMem-Eval/methods/expel_online_st.py#L612-L642)只有一次`llm_generate`；[批次更新](../../../third_party/SeqMem-Eval/methods/expel_online_st.py#L475-L486)也只有一次，curator输出上限为`max(max_new_tokens,512)`。[CLI](../../../third_party/SeqMem-Eval/main.py#L390-L395)实际向ST传入batch参数；[runner](../../../third_party/SeqMem-Eval/runner.py#L424-L429)支持任务数上限。`--max-tries`不是限制ST网络重试的开关。
- [客户端](../../../third_party/SeqMem-Eval/utils/llm_client.py#L248-L276)外层默认最多15次尝试；SDK内部重试在[初始化](../../../third_party/SeqMem-Eval/utils/llm_client.py#L164-L174)已关闭。选此后端时`OPENROUTER_MAX_RETRIES=1`才是外层最多一次，不是0。旧[E0入口](../../../scripts/e0/run_matrix.py#L60-L81)自动加resume，且[环境](../../../scripts/e0/run_matrix.py#L107-L110)默认3次尝试，不能照搬。
- [恢复函数](../../../third_party/SeqMem-Eval/methods/expel_online_st.py#L711-L770)把规则权重重置为1，未重建pending成功batch；`reset_task_state`使用`setdefault`也不是清空。故上述三根需要真正新状态；中断后按当前恢复路径续建不能宣称是原样自然历史。
- [当前存储](../../../third_party/SeqMem-Eval/methods/expel_online_st.py#L677-L705)没有curator原始响应与完整计数状态，也没有逐attempt预扣账或完整输入token拒绝机制。未来实现前须补合同验收，本轮不补代码。[检索embedding](../../../third_party/SeqMem-Eval/methods/expel_online_st.py#L150-L172)另计CPU推理/内存/时间，不因为不是生成请求就记为免费。

主代理补充的旧test规则单组件跨rep covariance近0/负，应作为开发风险保留，本轮未重新计算。它既不证明潜在信号不存在，也不能支持“切成rules-only就可学习”。输入不容纳完整强对照时应退出该协议，不借缩输入改换估计对象。

### 4.1 完整双端点上下文：尚未合格

主代理本轮提供、本文不重复计算的旧E2统计：158题OO/NN完整prompt IDs长度，old均值3100.47、new均值3561.75；逐题两长度之和最小3536、最大9885，128题之和大于5888，8题大于7936。**这是两条完整prompt各自token长度之和，不是真正rawpair去共享前缀、重新套模板后的长度；不能写成128题rawpair必超长。** 这些开发资产统计足以反对“完整双端点默认可装”，但不是新根长度分布的保证。

代码层面的确定事实：

- [旧E2预算](../../../src/memgate/experiments/common.py#L24-L26)是单端rules上限1024、experiences上限3072，而非经验块硬上限约2k。两端组件额度相加为`2*(1024+3072)=8192`，尚未计共同题干与预测指令；这只是额度和，不是实际token数。
- [packing](../../../src/memgate/experiments/prompts.py#L59-L76)按完整规则/完整经历条目截取；[最终验收](../../../src/memgate/experiments/prompts.py#L105-L134)才对完整chat文本tokenize并检查5888。两个单端各自通过不推出双端通过，也不能直接把已有两串IDs拼接当作新请求。
- 新32题或64题构建、512输出上限可能使经历更短，但题干、curator产生的规则、模板以及双端重复内容仍未知。旧E2 packing不是ExpeL-ST自然构建自带的限制；不能把旧上限自动套到新状态。

未来只接受无损且可核验的rawpair输入：共同题干和逐字相同的固定solver说明可以只保留一次，旧新各自实际可见规则、经历、顺序及版本标记完整保留；所有双端点方法获同一信息集。最终完整预测指令、chat模板、输出预留一起计数，才决定是否符合5888输入上限。输入上限是5888，不是把7936总预留当作输入上限。

本轮未冻结该序列化格式，也未对它重分词，故1536方案和下述3072候选均保持**context HOLD**。若无损去重后仍超长，停止该根的完整方法比较；不得只截rawpair、只留rules、只挑短题或短transition。统一缩小两端solver可见记忆也会改变真实干预，必须另立协议，不能作为这次预算闭账技巧。CPU probe可在无LLM上下文截断的文本上做受限线性诊断，但不替代缺席的强LLM rawpair胜负证据。

## 5. 预算：从六历史规划降为单任务诊断

### 5.1 为什么1920＋1152尚不成立

六条历史若各96题、batch=8，从零构建最多`6*(96+12)=648`次，只剩504次覆盖全池特征、控制和失败。原形状共有`6*(16+32)=288`个历史-题单元；即使每单元只做六次语义调用也要1728次，已超过全部1152。端点分别调用还可能增加成本。若各581题，仅solver即3486次。已有一个根不能按复制六份来扣除构建成本。

### 5.2 可核算替代：1536次上限，全部强对照保留

只保留Engineering，3根各最多32构建题，每根冻结32题评价池：16校准、16审计；开发根同形状提供开发标签。留出根审计题族不进入构建、拟合或校准。最保守的跨根也不重用题族分配，需要`3*32 + 3*32 = 192`道合格题，低于R2名义228，但228尚未通过语义分族，因此**192仅为必要数量核算，不是已验收供给**。控制直接重用池内预指定公开题，不新增题族需求。

| 项目 | 硬上界attempts | 说明 |
|---|---:|---|
| 三根构建 | `3*(32+4)=108` | 包含solver与curator，失败根不补抽 |
| 三根校准 | `3*16*2*2=192` | 每版本2次 |
| 三根审计/开发诊断 | `3*16*2*4=384` | 每版本4次，预拆2组各2次 |
| 全池语义特征和强对照 | `3*32*7=672` | 下列7个请求槽，不另出新题 |
| 同输入控制 | `3*4*4=48` | 每根4个预定完整prompt，各两时段2次新解码 |
| 接口探测、失败余量 | 132 | 所有已提交/未知派发均记账；不允许借此补根、补题或追显著 |
| **总计** | **1536** | 上界，不是1536条成功回答保证 |

常规表项本身包括其失败派发；132仅供预登记的额外探测及非构建环节有限重试，不能重复计账或无限替补。构建不重试；其他同一逻辑请求最多一次额外尝试、先扣132额度，仍不完整则整表未决，不按方法删缺失题。建议同时以12小时生成运行时间、8人工小时为拟议硬上限，先到即停；不据此承诺完成时间或资源配额。

### 5.3 为什么不能把该预算称为省生成

固定预测`m(q)`和有限题池N，随机抽n题、每端点r次独立解码时，残差校正估计量的方差可分解为：

`(1-n/N) * S²[tau-m]/n + mean_q[sigma_new²(q)+sigma_old²(q)]/(n*r)`。

这里假定预测与审计解码独立、两端无共同随机数，第一项用有限总体样本方差定义。**预测tau只能降低题目抽样项，不能消除第二项独立decode noise；即使n=N，第二项仍在。** 少抽题还会放大噪声项。报告中心化有符号残差及分组复现，不把低/负跨rep协方差截为0，也不把“均值方向猜对”当作省题证明。

单一部署方法若全池每题要b次语义调用，attempt回本的必要条件是`N*b < 2*r*Δn`，还未包括开发/构建成本及不同请求tokens差异，且必须先保证同等估计精度。对于N=32、r=4，rawpair的32次特征成本至少要少测超过4题才净省调用；6槽联合需192次，要少测超过24题，已经超过本方案16道审计题。实际全池语义比较672次也大于校准加审计576次，故该表**没有当前省生成的经济性证据**。

两本账分别报告：方法比较允许合法共享标签的物理账；各方法单独部署时，单独计构建、拟合、全池特征、校准与独立审计。不能把比较全部方法的672次都归给一个rawpair方法，也不能把它从研究总成本中抹去。

建议先在旧开发资产做零新增生成的CPU可识别性/成本检查，仅用于决定是否值得购买这次诊断，不能作为新题成功证据。若CPU probe已解释全部信号，或预计噪声主导导致不存在可支付的省题空间，就停LLM关系路线。没有明确的限定信息价值目标和愿意承担的诊断成本，不应仅为保住某个关系模型而启动1536方案。经批准的完整比较若容纳不了强对照，则结束比较，不删对照来制造便宜的正结果。

### 5.4 主代理3072候选：算术成立，资格未闭合

补审候选为一任务三根，每根16cal、32audit，每个版本cal两rep、audit四rep；另每根对64query做六次预测调用，source最多64题和8次curator：

| 项目 | attempts |
|---|---:|
| 评价 | `3*(16*2*2+32*2*4)=960` |
| 全池预测 | `3*64*6=1152` |
| 构建 | `3*(64+8)=216` |
| 同输入控制 | 48 |
| 探测 | 6 |
| 失败/重试预留 | 690 |
| **总计** | **3072** |

这是合法的**数量规划**，但不能据此批准：

1. 六调用可具体落实为new-only、new边界、old端点、rawpair、diff/行为评分、置换rawpair；独立端点相减复用与new-only身份完全相同的新端点请求。若端点请求不同或某方法需多轮，六槽即不成立，应重算，不能缩弱对照。没有必要再塞入未具名关系模型。
2. `64query`不等于48道有标签评价题。可明确为16校准＋48目标池，目标池预先均匀抽32审计，另16题无审计回答；所有64题只做合法公共输入特征。若估计目标是48题池，校准题不能同时当作其中的独立随机审计样本。
3. 最保守的跨根题族完全分离需要`3*(64 source+64 query)=384`题，超过本地名义228余量。一个数量可行但较弱的替代是固定64题source池供三根各自从空独立构建，另64题开发评价池、64题供两个留出根共用评价，共192题；仍须分族验收。它仅支持条件于固定source池的构建随机性，且两个留出根共享评价题，不能称来源独立或把两组题当独立样本。不能为凑384题读取旧结果挑可用样本。
4. 64题并不保证足够成功、非空旧版、合格自然变化或curator输入合规。若采用该候选，须预先把第4节窗口改定为成功batch第2至第8次、任务上限64；不是在32题失败后临时扩容。更新选择仍不得依赖效果。
5. 六方法1152次特征成本已经超过960次评价。单部署rawpair在N=64、r=4时至少要少审计超过8题才净省调用；六槽联合需少测超过48题，超过32道审计题。它最多是一次明确付费的信息诊断，不是当前可省题路线。token成本还可能更不利。
6. 690只是总预留，不允许每个请求自动循环690次。构建仍不重试；其他请求最多一次额外尝试，先记账、用尽即停，未知派发计费。若统一输入5888、输出2048，包络为`3072*7936=24,379,392`；若另批准512输出，则为`3072*6400=19,660,800`。两者均是每条请求实际满足上限时的预留，不证明rawpair、curator或评分特征上下文已经通过。

**选择建议：** 不优先3072候选。先保留零新增生成的CPU开发诊断和完整文本长度资格核查；若以后确有购买信息的理由，再在1536小诊断与3072较宽诊断中只冻结一个。所有强LLM对照不能合规进入时，只能交付标明范围的CPU诊断并退出LLM表示优越性主张，不能把它称为“完成全部强对照”。

## 6. 独立性与最终交接

| 构造方式 | 能成立的独立性/推断范围 |
|---|---|
| 一个历史的多快照、多个batch、同一导出多次读取 | 历史不独立；只作该路径内开发 |
| 从同一旧快照分叉 | 共享随机祖先，无条件一般不独立；条件于固定祖先、固定分配及互不共享的后续随机流，可讨论条件独立分支 |
| 同一固定构建题池各自从零、独立顺序与随机流 | 条件于池、模型和协议的构建随机性；不是独立数据来源，也不是新任务分布迁移 |
| 互斥题族的从零构建根 | 减少来源重合；条件于预先固定的划分和模型，独立随机流可支持条件独立。有限全集无放回划分本身仍耦合，不能自动宣称无条件iid |
| 共用开发训练器/校准规则比较两留出根 | 须条件于已冻结训练器；共同任务规则族、后端时变和共享题仍可能相关 |

所有条件独立说法都要求无跨根自适应反馈、无共享可变记忆，并核对后端与时序；仅换seed不足以证明独立。匹配题族不足时合并族或退出，不把近重复跨侧放置。更新选择按第4节预登记窗口，不读取旧test效果、不按新校准表现选transition；连贯两端完整版本始终保留。
