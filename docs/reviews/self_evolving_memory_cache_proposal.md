# 自进化记忆方案V3：逐题重组规则与例子，按重组后价值维护内容

日期：2026-11-04。状态：V3完成14轮递进自审；§9记录旧库准备不足，§10给出11R／14E的新初始化与9题缩量诊断。用户已批准72次正式回答＋8次共享预留，合计最多80次新尝试，并要求自动推进，授权记录见§11。执行前置验收尚待完成，没有新模型回答、训练或算法效果证据。评审与结果集中于本文件。

用户修正：**一个问题一个组合**；用神经网络或其他方法打分，把当前有用的经验／例子排到前面；答错后由子Agent总结和修正；继续使用原数据集并比较baseline。

这里沿用原ExpeL项目的含义：**经验R是抽象规则／策略，例子E是具体任务的解法／执行轨迹。** solver保持冻结；记忆正文与检索打分器可以随反馈更新。若训练打分器，需明确“solver不训练”，不能声称整个系统没有参数更新。

**判断：方案值得保留，不能仅凭“检索＋图＋更新与别人相似”否决。** 但“每题一个组合”“失败后修补”“反事实价值学习”已有直接方法和实验。V3把待检验问题缩小为：**规则与例子可独立重组时，读取、改写和淘汰能否共用一个经过验证的集合价值标准，保住真正需要的支撑内容、去掉可被替代的内容？**

不再强绑Caffeine；采用有界内容库、小候选缓冲、版本关系表和固定curator。先验证逐题组合预测，再检验它对持续更新与保留是否有额外价值。原MMLU-Pro／ExpeL资产可作开发材料，但§9显示仍需内容与来源资格处理；**2212条旧回答不能直接充当任意条目组合的训练标签**。不承诺求出全库真实最优，也不默认迁移到BigCodeBench。

## 1. 从原设想保留什么、修正什么

| 原设想 | V3中的具体含义 |
|---|---|
| 一个问题一个组合 | 输入题目q，输出本题的规则子集R_q与例子子集E_q；允许只用一种或都不用 |
| 网络打分、好内容放头部 | 打分依赖q以及已经选择的内容S；本题生成临时优先队列，下一题重新计算 |
| Caffeine维护和淘汰 | 不限定实现；先用固定FIFO隔离读取，后比较删除／替换后重新选组合的损失 |
| GraphRAG减少冲突 | 第一版只用有界关系表记录来源、范围、版本及有证据的组合关系 |
| 答错后子Agent修正 | 子Agent提出局部修改，生成新版本；检查后才影响未来任务，不直接覆盖旧正文 |
| 用原数据和baseline | 主起点仍是MMLU-Pro Engineering／ExpeL；旧回答作开发证据，新增组合另采反馈 |

Caffeine不是一个把“最好内容”全局排序的堆。TinyLFU比较近期访问频率，W-TinyLFU再用窗口处理新条目和突发访问。它解决命中率问题；检索到一个错误规则也会产生“命中”。因此，访问频率只能提示需求，不能代替正确性或边际贡献。[1]

阈值也已有先例：ExpeL原文已经有ADD、EDIT、UPVOTE、DOWNVOTE和计数降到零删除规则。[4] 原项目代码还已经按**每道题**的embedding检索top-3成功案例；E2固定的是R/E的库版本，不是每题使用完全相同的例子。本项目新增的决策是逐题选择规则，并联合判断规则与例子是否值得同时使用。

## 3. 要解决的具体失效

对某一道题q，假设提示只能容纳两项，四项记忆的单独价值为：

| 条目 | 规则r | 例子e | 条目a | 条目b |
|---|---:|---:|---:|---:|
| 单独价值 | 0.10 | 0.05 | 0.35 | 0.35 |

再设只有r与e具有额外0.75的互补价值，其他组合价值可加。按单条价值选择a、b得到0.70；选择r、e得到0.90。该有限集合例子已用枚举核算，**只证明逐条评分可能失败，不代表LLM自然任务已经有这样的效应**。换一道题q′，这些值可以全部改变。

一个工程题中的示意场景是：规则提醒“代入理想气体方程前使用绝对温度和绝对压力”，例子展示“摄氏度转开尔文、表压加大气压”的具体计算。例子可能帮助模型正确应用规则，也可能已经足够独立解决问题。后者情况下，应省掉多余规则，而非强行保留组合。此例用于解释假设，不是从旧回答中确认的机制。

需要区分三件事：

1. **来源关系**：规则由某个例子提炼而来。
2. **使用依赖**：当前模型只有同时看到两者才能稳定受益。
3. **适用条件差异**：两条表面冲突的规则其实用于不同任务。

来源关系不能自动证明使用依赖；模型把两条规则同时说出来，也不能证明它们在因果上互补。

还有一个更强的反例：r需要e1或e2中的任意一个；两例同时存在时，各自被删除都不影响结果。如果按一次计算的删除损失批量淘汰，会把两例一起删掉；如果把两条正交互简单相加，又会高估同时使用它们的收益。R6—R8给出数值和枚举结果。**它同时约束已有逐项方法和本方案，不能只拿来攻击baseline。**

## 4. V3方法：一个价值模型，分阶段接入读取与维护

### 4.1 两类内容和有界状态

规则节点保存：稳定ID、版本、适用条件、策略正文、来源ID、状态。

例子节点保存：稳定ID、版本、任务条件、解法／关键轨迹、外部验证结果、来源ID。失败案例可以作为反例保存，不把原失败操作当正例。

关系只保留三个用途：来源／版本追踪、候选适用范围、测得的正负组合效应。后者还要记录任务范围、样本数和有效版本。语义相似度只用来提名待检查的边，不直接充当组合收益。

采用普通内容表、向量索引和邻接表即可，不需要图数据库。关系按`derived_from / version_of / scope_related / measured_effect`分别记录，`measured_effect`带任务范围、背景集合和样本数。每项至多保留8条活跃关系；过期关系可删除，正文不依赖全图才能读取。跨类型来源可以多对多，不能强行给每条旧规则找一个唯一例子。

所有方法固定以下四类资源，原型默认值须在生成前绑定真实tokenizer与manifest：

| 资源 | 计入范围与开发起点 |
|---|---|
| 内容`B_store` | 所有可检索R/E、草稿、新旧版本的正文与内容字段；草稿预留10%，其余90%活跃。以共同初始库实测大小T0的1/4、1/2、1倍设容量档，阶段B固定一个预先选定档 |
| 输入`B_context` | 沿用R≤1024、E≤3072、完整输入≤5888；输出预留2048、总窗口8192及256余量。先不跨块借额度 |
| 辅助状态`B_aux` | 可再访问的查询、轨迹、训练／回归样本等文本总量≤0.25·B_store；完整记录装不下就淘汰，不静默截断。向量、关系、统计、数值特征和队列另限16 MiB并实测峰值；训练器参数／优化器内存另列固定上限 |
| 费用`B_cost` | 首次回答、curator、额外对照、工作记忆合成、失败发送、重试全部计费；embedding、训练、CPU检索和输入输出tokens单列。调用上限不能代替总成本 |

32条近期查询表示＋32条历史reservoir表示估计需求，不含正确答案；最多32条完整在线轨迹供训练或回归，且仍服从上述token限制。任一缓冲满时使用预先固定规则删除，不能绕到审计目录恢复。正文去重只收费一次；索引向量不能因正文已计费而免除辅助容量。

审计日志可持续落盘，但不能成为推理、筛选、重写或在线再训练时免费访问的无限记忆。源ID只用于追踪；淘汰正文不能通过指针取回。初始离线训练数据和其费用公开，在线只保留有界训练状态。模型参数会保留历史信息，本稿研究**有界外部状态下的学习**，不主张严格信息遗忘。固定库实验的离线监督不伪装成在线免费获得。

### 4.2 每道题怎样生成一个组合

首先用固定embedding做粗召回，最多4条R和8条E；各类至多保留一个位置供来源关联或新晋升条目曝光，未启用时退回相似度召回。草稿只用于额外验证，不进入首次答题的候选池。关系扩展始终计入4/8上限，顺序和去重规则冻结。原Qwen3-Embedding-0.6B可继续使用。共同候选池用于主受控比较；候选召回的改进单独消融，不能归给组合评分。

第一版只允许**总条数≤3、每类≤2**，且同ID新旧版本互斥。这覆盖1R1E、1R2E、2R1E、同类双项、单项和空集；不声称是所有任务的最佳规模。最多239个组合可在CPU上枚举，之后再剔除超长／不合法集合。

采用共享特征的正则化二阶评分器作为可否证的起点：

```text
Fθ(q,S) = bθ(q) + Σi∈S uθ(q,i)
          + Σ同类(i,j)∈S hθ(q,i,j) + Σr∈S_R,e∈S_E vθ(q,r,e)
Jθ(q,S) = Fθ(q,S) - λ · memory_tokens(S)
本题组合 S*q = argmax可行S Jθ(q,S)
某项在当前组合中的分数 sθ(q,i|S) = Jθ(q,S∪{i}) - Jθ(q,S)
```

`u`预测单项，`h`处理同类关系，`v`处理跨R/E关系，`b`吸收题目难度并在同题比较中抵消。最关键消融是**同样保留h、仅令v=0**，不能把同类去冗余的收益冒充跨类型组合收益。各类参数跨条目共享，不为每个ID或每条边训练独立自由参数。

初始特征：query与条目的embedding相似度、条目间相似度、相似度乘积、类型、长度、适用条件匹配、来源已知／未知。单项和每类二项特征各≤16维；使用冻结内容表示形成这些标量，避免在百题数据上直接拟合数千维。在线实验可另加入**答题前已有**的曝光和反馈统计，所有比较方法一致。当前题答案、反馈、答后解释及题号禁作输入。来源关系不直接赋正收益。

匹配特征使用已存范围标签和固定embedding，不对每个组合调用LLM判定“是否适用”。实际特征表、尺度和缺失值处理在开发协议冻结；网络参数、训练时长和CPU推理延迟均实测报告。

这实现用户说的“一个问题一个组合”：优先级依赖q和已选内容，最终可为`{r1,e3}`、`{e2,e5}`、`{r4}`或空集。枚举避免两项单独不值得选而贪心过早停止；它只优化候选池内的预测目标，**不是239次solver调用，也不保证真实最优**。

第一轮`λ=0`，在硬预算内按预测准确率选，同分取更短集合；避免另引一个未校准的“每token值多少正确率”旋钮。成本敏感曲线后续才预先设非零λ。用真实chat token IDs复核**最终渲染**，超长重选完整集合，不事后截掉已计分内容。采用固定R块在前、E块在后、块内共同召回次序；提示位置优化不与集合选择混在一起。

必须在开发留出中检验组合大小、类型、长度和相似度范围的覆盖，以及三项残差。未覆盖的结构不交给枚举最大化；先回退到已验证的无跨类型模型或进入有额度的探索。`F`不是校准概率，出现不合理大值时不能简单clip后宣称校准；检查其排序误差及模型失配。

二阶式无法一般表示三项以上的条件替代，这是本方案已知限制。若自然数据中该误差足以改变最佳选择，应采用已有条件序列／集合模型或收窄动作，不能先许诺二阶式普适有效。小MLP只作为同输入、同监督的容量对照；当前不引入GNN、solver训练或新的强化学习框架。

### 4.3 打分器的监督从哪里来

训练记录的单位是`(q, 实际注入集合S, 内容版本, prompt身份, 外部得分Y)`。一条成功回答只说明该组合这次成功；不能把其中每条规则都标成“有用”，也不能把未入选项标成负例。

旧E2记录可用于**已有七种完整配置**的收益预测、组件消融和开发参照。其中`ZZ/RZ/ZE/NN`构成新R块与新E块的2×2对照；E块在不同q上本来就不同。这些是整块效果，不是任意单条R/E的标签。旧日志中的成功轨迹可作例子正文，不能凭成功就生成检索最优标签。

本轮核对的旧14R和新20R合计21种不同正文，规则包含矩阵的秩只有2；所有旧规则整块出现、所有新规则整块出现。因此增加网络容量不会从旧标签中变出21项可识别的独立效应。

条目组合监督需要另采。阶段A先做单对四配置诊断；阶段B从共同候选池**在看结果前**选一个自然三项组，按预设配额平衡1R2E与2R1E，对其全部8子集取反馈；另最多加入独立打分与模板打包各一个正常集合，共≤10个不同集合。同一prompt、生成配置和预设重复编号只运行一次并按身份复用，不为了凑数换候选；两次预定重复仍是两个计费身份。抽样兼顾来源关联、相似但非同源、普通共同召回，记录比例，不能只选人工确信互补的例子。

这样可以获得局部单项、同类／跨类型二项、三项残差与LOO标签；仍不能覆盖全库全部组合。小模型用带正则的集合回归，并以同题差值检查排序：

```text
集合目标：   Fθ(q,S) 预测同一配置重复回答的平均得分
差值目标：   Fθ(q,S_a)-Fθ(q,S_b) 预测 Y_a-Y_b
```

差值回归可以削弱题目难度混淆，但不消除解码噪声。每题在损失中归一化为相同总权重；重复解码先在同一输入内求均值，不把全部两两差值再次当独立样本。所有同题、近重复题及其直接派生记录须同组切分。参数和标准化只从训练组拟合；开发验证选择ridge强度、模型容量和动作范围，确认集只用一次。

冷启动先用固定相似度／MMR策略，跨类型效应视为未知。线性模型只有在新组合标签的分组开发验证支持时才启用。在线按32题窗口更新一次；只用当时已获得的历史反馈和保留的数值特征，最多512条集合记录并服从辅助容量。旧版本标签仍可教共享模型，但必须保留其当时特征，不能改绑到新正文或用答题后的新utility回填旧特征。

日常在线回答只产生被选集合的反馈。原型开发起点为`ε=0.1`：从适用、可装入提示的候选动作中按已记录分布探索，其余采用当前冻结评分器；探索也占首次回答并计入成绩。只有额外局部检查才增加调用。ε在开发确定后冻结，概率日志包含候选池、策略和版本；不具备支持的全库动作，不能据此做无偏离线评估。未知不标成负例，未被召回的内容也不因“从未成功”受罚。

### 4.4 如何检查真正的组合效应

对一个事先选定的开发任务q、规则r、例子e，冻结其他背景记忆B、模型、环境和生成配置，比较：

| 配置 | 发送给模型的记忆 |
|---|---|
| 00 | B |
| 10 | B＋r |
| 01 | B＋e |
| 11 | B＋r＋e |

以外部评分得到的平均任务收益记作`Y00,Y10,Y01,Y11`，定义：

```text
规则单项效应       ur = Y10 - Y00
例子单项效应       ue = Y01 - Y00
组合交互效应       vre = Y11 - Y10 - Y01 + Y00
给定规则后例子价值 Δe|r = Y11 - Y10
```

`vre>0`表示相对于该背景的互补，不保证11优于所有方案；还必须比较11、10、01、00的实际收益与token成本。`vre<0`可以来自冗余、竞争或冲突，不能仅凭负值就宣布文本逻辑矛盾。

做这组干预时，被拿掉的条目不由其他条目补位，避免把“R/E效应”混成替换内容的效应。随后，实际缓存换入换出的验证必须恢复正常packing和补位，衡量真实替换收益。前者测局部机制，后者测部署行为。

候选对来自自然写入、来源关系和实际共同召回，不穷举全部R×E。成功与失败任务都要抽取，抽样概率及触发条件先固定。只看失败会漏掉“有用规则被成功例子掩盖”等情形，也会高估失败区域的重要性。

终局对错不足以给每条记忆分配可靠credit。日常结果可更新普通utility估计；有限的四配置检查用于校准争议节点和边。小样本交互向零收缩，未测量的相似边不直接当作正收益。改写版本不得沿用旧版本的交互估计。

这些效应只对检查过的任务范围、模型、背景和版本有解释力。可以在固定的可见任务类别内汇总并随时间老化，但不能假定一条边对所有未来背景恒定。需要记录在新任务上预测误差是否变大。

阶段B的完整三项检查还计算`Δ123=Y111−Y110−Y101−Y011+Y100+Y010+Y001−Y000`。显著或稳定影响选择的三项残差意味着二阶假设不够；它不是另一个可任意堆加的模块。对照选择在同题中固定，重复回答顺序随机化；相同随机种子不能自动保证不同prompt的噪声彼此配对。

### 4.5 容量维护：看删除后还能组成什么

**第一版不做W-TinyLFU主架构。** 内容状态仅为`draft / active / retired`；draft共用10%预留空间，最多保留两个32题窗口。只有通过§4.6的检查才进入active；无检查机会而到期的条目标记“未验证到期”，不判为有害。`retired`正文离开可访问存储，仅留有界身份记录；审计原件不参加算法运行。

固定库阶段不写入、不淘汰；先研究演化时，所有受控方法统一采用按token腾空间的FIFO，只用于隔离选择和curator的作用。FIFO不是最佳政策的主张。最后才比较FIFO、变长W-TinyLFU、单项utility与下面的集合价值准入。

“本题排头部”只改变本次读取。长期保留需按查询需求与可替代内容另算，候选曝光、实际注入、外部结果分别计数。不能将检索器自身造成的高频直接解释为高价值。定义开发用预测目标：

```text
D_t = 32条近期查询表示 + 最多32条历史reservoir表示
Vθ(C) = 加权平均q∈D_t [max Jθ(q,S)，S∈从C重新召回后的可行集合]
换库动作a = (准备加入的P, 准备移出的E)
Δθ(a) = Vθ((C \ E) ∪ P) - Vθ(C)
```

两部分查询池各占一半权重；某池为空则将其权重交给另一池，两池都空时不执行学习型替换。这里只读取答前query表示、长度及可见特征，不用未来题或确认答案。`Vθ`是近似的需求加权预测效用，没有真实未来收益保证；近期分布可能不代表未来，所以另报稀有题族的保留损失。重召回会改变候选，因此不能假定`Vθ`单调或次模，也不借用相应贪心近似保证。

对D_t中的每个历史query，重召回前排除源自该query及其近重复题族的记忆，避免用“保住这道旧题自己的答案”抬高保留价值；新规则继承其输入材料的来源集合。来源不明且不能证明时间／题族隔离的条目不参与该query的维护评分，C与C′使用同一过滤规则。该目标只近似下一阶段的可迁移读取价值，**没有计算更新策略对多年期学习轨迹的最优回报**；持续演化的价值必须由在线实验补证。

每个维护时点至多提出单项或一个R/E双项包P；从至多8个可淘汰候选中枚举≤256个E，逐个检查正文容量并重算`Δθ`。淘汰候选由年龄和低单项utility确定性产生、所有动作使用同一规则；因此仍可能漏掉全局最优换法。总量最多约`256×64×239`次轻量集合评价，需实测CPU成本；达到计算上限就保留现状，不追加solver搜索。

只有完整换库动作的改进超过预先冻结的滞回阈值才执行；阈值参考开发数据的预测误差，不把它称为置信下界。删掉一项后必须重新计算下一动作，不能排序一次就批量删。新版本视为加入＋旧版退出的同一事务；新旧正文、草稿和临时状态都计费。

例子e1、e2可互相替代时，可以删除其中一项，但删除第二项前会发现规则已失去支撑。反过来，规则和唯一支撑例子也可成包申请，避免单项准入都失败。对压缩／改写后的内容同样重算，因为新例子可能不再支持原规则。其价值须以真实流上的后续效果检验；不能只报告自己预测的`Vθ`提高。

### 4.6 回答错误后，curator子Agent怎样工作

每次保存实际的“候选→召回→图扩展→选择→packing→回答”记录。进入候选、被检索和真正进入模型输入必须分别记录。

有外部可验证失败后，先定位已使用条目和直接相关边，再作小范围检查：

| 检查结果 | 对应操作 |
|---|---|
| 正确内容未进入输入 | 调整召回／准入候选，不惩罚未被使用的内容 |
| 规则适用范围不匹配 | 修改范围或拒绝本次使用；新内容版本进入draft |
| 单项有益、共同使用变差 | 降低对应范围内的组合权重，避免该组合 |
| 删除某例子后规则应用变差 | 提高该组合的保留价值，或用更短、经验证的替代例子 |
| 无记忆也失败、各配置差异不明确 | 保留未知状态；可能是解题能力、环境或随机性问题 |

LLM对失败原因的解释只是检查候选；外部评测和受控差异才提供效果证据。没有可靠反馈的普通线上回答，不自动按“模型觉得错了”扣分。

第一版只用一个固定curator角色，可与solver共用基础模型、采用独立提示。其输入包括失败题、实际使用的R/E、完整回答轨迹、允许的反馈和有界相关历史。输出限于`ADD_RULE / PATCH_RULE / ADD_CASE / PATCH_CASE / MARK_SCOPE / NOOP`；每32道新题至多调用一次，选择已记录的失败来源，提出至多两项相关改动作为一个候选事务。成功轨迹可进入同一有界draft区，不强制额外调用curator；同样竞争每窗口一次的验证／准入机会，不能绕过总容量和验证预算。

curator不修改检索代码、奖励、评分器结构和验证阈值。没有有意义的错误证据时可NOOP；不能为了保持“自进化”名义制造更新。该角色是待实现算法的组成部分，不代表本轮评审用了多个独立Agent。

工程选择题中，答案字母正确只能验证最终选项，不能证明整段推理可靠。原成功案例需标明此验证层级；给定正确答案后写出的修正版更不能自证正确。修正先作为候选，需在其他开发题或可执行子检查上验证；检查不足则不宣称已修复。失败案例若保存为反例，必须显式标注错误部分。

候选先做结构、长度、来源、答案泄漏和版本冲突检查，并按当前容量政策确定**包括所有victim的完整拟议状态C′**，再验证C与C′。不能先验证新内容、通过后再另外淘汰一批旧内容。开发原型起点：从有界回归池按预先固定规则选4道**非当前题、非近重复、非候选派生来源**的旧开发题，其中2道相关题、2道原先成功的题；用同一冻结选择器重新召回、packing／替代，每状态一次，共至多8次solver。实际prompt相同则复用同身份结果，不把重解码波动当更新收益。相关题不足或预算不足就保持draft，不偷偷用当前错误题代替迁移验证。

原型经验门槛为“至少一个改善、无观测退化”，允许拒绝后续证明有用的修改；这不是统计安全保证，四题一次解码尤其容易受噪声影响。它只用于限制草稿直接污染活跃库，真正收益看未来首次成绩。独立确认前须结合开发噪声另定检查规模和门槛，不能把此门槛当已验证的最终参数。

内容改写后重新编码，旧版本统计和组合边保留在原版本上、对新版本不生效；共享网络可给冷启动预测，但不能冒充新版本已获验证。同一题不能同时使用一个条目的新旧版本。文本相似或curator声称冲突，只能提出检查候选，不能自动硬删。验证通过后只提交刚才检查的C′，原子切换正文、向量和关系；状态变动则本次验证失效，中断恢复以该事务和请求账本为准。

固定库阶段不执行curator写入；进入演化阶段，可先让各选择器共享固定候选写入流以隔离选择效果。端到端比较则各自先答后评、依自身轨迹触发同一个curator，体现真实自进化。另设冻结curator对照，避免将更强的改写收益归功于组合模型。批量更新而非每个失败立即改网络，以降低反馈噪声与版本漂移。

### 4.7 怎样判断系统稳定，而非只看库里内容越来越多

读取每题执行；模型训练和内容维护每32题才执行，窗口内冻结评分器。每窗口最多一个curator事务、一次集合局部检查、一次容量替换。维护计算使用同一评分器版本；训练后不能一边改分数一边选择victim。没有足够新反馈、验证题或费用时跳过相应操作。

开发原型每32题的额外生成上限为`1次curator＋8次版本验证＋4次单对检查＝13次`，还不含重试；可复用同身份回答时实际更少。该开销约为32次首次回答的40.6%，不能宣传维护近乎免费。是否值得必须看成本—准确率曲线和减少检查的消融，最终总账本优先于窗口配额。

固定检查点报告首次准确率／学习曲线、集合预测排序误差、已检查三项残差、每窗口内容替换率、版本寿命、稀有题族成绩和实际内存／费用。库大小稳定不代表性能收敛；预测分数提高也不代表真实成绩提高。若替换频繁但未来成绩无收益，先冻结内容或回到较简单读取策略，而非自动扩大网络和生成预算。

**目前没有理论收敛保证。** 非平稳任务、部分反馈与curator生成会使目标不断变化。这里的“收敛”仅指预先设定观察窗口中的经验稳定性；多次复播同一历史不能当作独立收敛证据。

## 5. 一条任务如何走完

```text
输入新任务q
    从当前活跃内容库召回R和E，在共同上限内补入关系／探索候选
    按q及组合内容评分，在token预算内选本题组合，也允许不用记忆
    生成首次答案，先记录成绩，再接收允许的外部反馈
    保存实际输入、条目版本、完整输出；轨迹加入有界写入缓冲
    达到32题时点且有额度：用已获得的反馈更新打分器，并冻结维护用版本
    固定curator为有证据的失败提出候选；检查不足则保持draft或NOOP
    用共同FIFO或集合价值政策提出满足容量的完整替换状态
    达到预设检查条件且仍有预算：做局部对照或完整替换状态的回归检查
    验证通过后原子提交被检查的同一状态；否则保留旧状态
    持久化全部状态，进入下一任务
```

自进化发生在未来任务上。不能把当前题经过反馈、重试后的最好答案替换首次成绩，也不能让独立确认答案参与选择阈值。

## 6. 怎么验证，才能知道值不值得继续

### 6.1 已核对的旧资产：能复用什么

一个具体发现：旧版14条R、新版20条R，在全部158题中都完整进入相应规则块。新E块实际注入3／2／1个例子的题数分别为106／47／5；旧E块为104／46／8。因此不能将现有现象预设成“规则太长被截断”，也不能把名义top-3当作每题确实用了3例。

按条目去重后，旧99例中94例曾实际注入，新302例中202例曾召回、193例曾实际注入。其余例子缺少相应曝光证据，不是已证明无用。E2最终回答导出不等于完整推理轨迹，curator所需轨迹应来自合格前缀或新运行的完整记录。

旧数据支持两种有用的零生成分析：比较七种已有配置；检查新R/E整块2×2的任务差异。它不支持直接回答“删掉r7、改用e21会怎样”。任意新子集、重新排序、压缩或改写后的提示，只要输入身份不同，就需要新回答。

旧ON测试为108/188＝57.45%，ZZ为99/188＝52.66%，但E2结论是INCONCLUSIVE；旧E3六方法共96次选择都未选ON。见[真实回放结果](../E3真实回放结果与逐题诊断.md)。这说明高分配置未必可预测，既不否定所有逐题方法，也不能用事后逐题挑最好配置的“oracle”支持新方法有效。

### 6.2 如何继续用原数据而不把旧测试重新当确认

**默认路线仍是Engineering开发，后续才考虑同属MMLU-Pro的Physics／Math。** V1的BigCodeBench候选[12]退出当前默认路线。

1. 从已封存的新快照正文初始化一个**新的开发运行**；初始utility、队列、来源不明标记和缓冲状态显式设定，对照方法一致。它是内容热启动，不是原ExpeL状态的无损续跑。
2. 旧158题全部视为开发材料；可按语义题组做交叉验证和诊断，不能再给新算法提供独立确认结论。旧E2的原协议和报告不改名，开发复用在新记录中另行声明。
3. 新采集组合标签时，当前题及其近重复不能已存在于所用记忆或规则的派生来源中。按真实时间使用旧前缀时，也只能使用该题出现之前的内容；不能用最终快照预测其自身构建题。
4. Engineering中未进E2的题不自动算新题：原E0源校验要求完整969题轨迹，而且后续分析已有多次暴露。确认资格要审计所有历史构建、调参和人工阅读，不能简单用“969减581减158”算出来。
5. 若同数据集能形成合格新题组，预先冻结开发／确认与语义隔离，再重新构建确认运行；若不能，Engineering结果限于探索。Physics／Math可供寻找新题组，但其名称与数量不构成未暴露证明，也不保证跨学科迁移成立。

确认分为两种清楚标注的成绩：新任务流上先答后评再更新的在线成绩，以及冻结检查点上**不回传答案给选择器／curator**的留出成绩。确认结果不用于改提示、换阈值或再挑模型。多条历史须从合法初始状态独立构建；改读取顺序或同一快照重播不算新历史。

原ExpeL恢复函数把规则计数置为1，且不恢复完整pending成功批次。该问题不妨碍冻结正文做新开发，但阻止声称“接着旧实验原样演化”。新运行需完整保存正文、条目版本、计数、队列、关系、训练缓冲、模型状态、随机状态及请求账本。

### 6.3 baseline怎样设置

旧数字用于历史背景；新方法的正式比较统一使用新协议的solver、题组、评分器和费用口径。只有完整prompt、模型、生成配置等身份兼容时，旧回答才可在开发回放中复用，不能用旧ON的57.45%与另一设置的新分数直接宣称提升。

先选定**七个固定库比较对象**，避免在小预算中塞入十余套完整系统：

| 对象 | 具体比较什么 | 公平性边界 |
|---|---|---|
| ZZ无记忆 | 同scaffold；检验复杂系统是否实际改善答题 | 旧表可分析；新题需新回答 |
| ExpeL冻结NN | 原规则簿＋逐题top-3成功例子，保持原packing | 运行参照；保留原规则块，不强制≤3项，因而不用于隔离组合评分因果作用 |
| NoCross | 同特征、同标签、同候选／枚举，保留单项与同类交互，只移除跨R/E项 | 第一主对照；比简单独立top-k更强 |
| 固定成组 | 开发期冻结规则与支持例子的配对，逐题只能按包选择；允许例子独立项 | 检查解耦价值；称成组机制对照，不冒充完整MemAPO |
| LOO单项价值 | 用共同三项检查产生的LOO及组合反馈训练`g(q,item)`，再取集合 | BEAM机制适配；改变其网络或去掉合成就不能称原BEAM复现 |
| 条件DPP | 采用CEIL式相关性／多样性集合选择，从相同集合结果学习 | CEIL机制适配；正确率标签与原答案概率标签的差别明确披露 |
| V3读取 | 同类＋跨类型二阶集合模型 | 尚未实现；用相同候选池、硬预算和实际token检查 |

相似度／MMR是冷启动与开发参照，简单独立模型`h=v=0`用于拆解NoCross；它们若要另采solver结果，同样追加预算，不能免费多跑。当前优先CEIL式而非同时实现CEIL和RetICL；若二阶模型的三项残差明显，应把RetICL式条件序列模型作为替代候选，重新冻结比较，不能看确认成绩再换。

旧R来源不明时，固定成组对照使用预先声明的相似度配对并标记“非真实派生来源”；不会捏造来源。若构造MemAPO式CTM，须让相同curator从共同可见材料构建，并将同样正文开放给解耦方法，计入费用。否则一次比较混入了内容质量和检索单位两个变量。

**机制适配的胜出不等于超过原论文方法。** 形成超越已有方法的结论前仍要核验至少BEAM原机制（含Beta模型、LOO、抽样及工作记忆合成）和一个演化近邻，优先MemAPO；GSEM作为图反馈对照，在明确声称胜过图方法时加入。若资源无法支撑，应缩小论文主张，不能把弱化适配写成完整SOTA结果。原算法复现与统一资源版本分开报告。

实验分三步：

1. **固定库比较读取。** 用共同R/E库及上述七对象，冻结curator和淘汰；主比较预定为V3对NoCross，另报告对固定成组和强集合方法的差值。
2. **固定容量下比较演化。** 选择器“NoCross／V3”×curator“冻结／更新”做2×2，统一FIFO。共享候选写入流检查同内容条件；之后各自按真实轨迹更新，检查端到端成绩。两者不是同一种证据。
3. **最后研究长期保留。** 固定curator，先用“NoCross／V3读取”×“单项utility／集合价值保留”的2×2检验耦合收益；FIFO、变长W-TinyLFU作容量基准。若集合价值保留只改善自己的预测分数、不改善未来答题，不能主张保留算法有效。

有约束和无明显容量压力的条件都要报告。存储预算先按真实token测量设几个固定档位，不能看结果后只留下最有利的窄容量；所有窗口、图、训练缓冲和旧版本占用均计入对应预算。

同数据比较让方法共享组合监督，并逐方法报告若独立部署所需的采集成本；实际账本只记真正发生的调用，避免重复收费。另做同总费用比较，让原方法把预算用于自身标签、合成或训练。相同调用数不等于相同tokens或GPU成本。测试时允许合成或多次推理的原方法，计入对应费用曲线；不能给V3多次检查却只允许baseline一次回答。

### 6.4 分阶段验证与停止条件

| 阶段 | 要得到的证据 | 不满足时怎样处理 |
|---|---|---|
| A：资产与机制诊断 | 自然R/E的有效干预、局部效应与噪声尺度；不是只造一个互补例子 | 区分“精度足以排除实用收益”与“样本少、无法判断”；不自动加预算 |
| B：冻结库上的选择 | 分组留出中的预测排序和真实收益，尤其对NoCross与强集合适配；检验三项模型失配 | 保留简单baseline，或据开发证据重新提出模型；不直接转入确认 |
| C1：内容持续更新 | 同容量政策下有在线收益，版本更新后评分仍能预测；原方法强对照 | 不将静态检索收益称作自进化算法优势 |
| C2：长期保留 | 完整删换后重选的保留法，比单项保留改善未来成绩；存在容量压力且代价合理 | 去掉保留贡献，仅保留通过验证的读取／更新结论 |
| D：独立确认 | 合格新题组、独立构建历史、冻结主比较与充分检测能力 | 只报告探索性工程结果 |

主要指标是固定资源下的首次准确率、随任务数变化的在线学习曲线、冻结留出成绩和总费用。附带报告延迟、实际记忆tokens、更新／检查成本、预测排序误差，以及收益是否仅集中在看过的题族。

消融包括去掉R/E交互、强制固定成组、冻结curator、取消局部检查和取消关系候选。增加MLP时须比较同输入的线性模型。图和保留等价关系信息的表没有算法区别，不能将存储格式算贡献。

不能把一条轨迹中的所有题视为完全独立：统计分析需体现语义题族与构建历史依赖，重复解码嵌套在题内。确认前固定主要比较、实际有意义的最小收益和不确定性分析；当前没有足够方差估计来承诺确认样本量。几十题的小诊断不能确认几个百分点的提升。

量级核算：假设每法每题一次、题间独立、成对不一致率d，双侧5%／80%功效检测相对零的真实差值δ，粗略`n≈(1.96+0.84)²d/δ²`。d为0.1／0.2／0.4时，检测3pp约需872／1743／3485个独立题对；检测5pp约需314／628／1255。它不含多重比较、题族／历史相关或参数估计误差，也不等于“区间下界超过3pp”的设计。故不能用32或48道题承诺证明小幅提升，更不能用增加同题解码冒充增加独立题。

若收益由更多调用、测试泄漏、无限历史或更强curator解释，则不支持组合选择主张。若MemAPO式打包或已有条件检索达到同样效果，就采用它作为方案结论，不继续把外围模块堆成新算法。

## 7. 本版决定

**保留并优化这个方向，建议先做有限机制诊断；不因整体相似否决，也不提前宣布新算法成立。** 当前最清楚的研究问题是：有界记忆中，规则与例子的可替代／互补关系，是否值得在逐题读取、局部改写与长期保留中统一考虑？

V3保留动态组合与失败curator，去掉Caffeine依赖，补全真实token容量、草稿准入、版本隔离、有限探索、三项失配检查和完整删换后的重新选择。首先检验读取价值，随后才能证明演化与保留价值；不是同时要求十几个模块全部成立。

| 审查维度 | 同一V3的结论 |
|---|---|
| 问题与逻辑 | 通过讨论级评审：反例成立，且已反过来约束自身模型；自然效应仍待测 |
| 具体新颖性 | 保留候选：已明确MemAPO／CEIL／RetICL／BEAM的覆盖，尚不能把整个联合实验判成已做过；也未证明独立算法增量 |
| 可实现性 | 有可执行原型设计：轻量评分、有限枚举、单curator、有界状态；尚未实现或性能验收 |
| 数据 | 旧内容与开发可复用；任意组合标签、完整来源隔离、独立确认资格尚未具备 |
| 成本与统计 | 320次仅够小诊断，完整选择实验需另设预算；小幅确认可能需数百至数千独立题 |
| 当前动作 | 旧库准备结果保留于§9；新11R／14E与9题固定配对诊断见§10。用户已批准最多80次新尝试，继续完成独立执行与分析；不启动训练或旧实验续跑 |

如果最后结果是MemAPO式打包或BEAM已足够，应采用该结论；若二阶模型失败但已有条件集合模型有效，也应承认收益来自已有组合检索。若读取、改写和保留的耦合确有独立作用，才沿这个窄问题继续扩展。

本节是同一助手的14轮递进自审，不代表14位独立评审人。以“问题→证据／反例→修改→复核”为一轮，不把列出论文名称算一轮。R1—R12形成修订，R13—R14对统一后的V3终审。

### R1：重新规定“已有工作覆盖”的判据

问题：V2把“组成部分已有先例”直接连接到“新颖性不足”，容易让读者误以为具体实验已被做过。

修改：分别核对四项：研究对象、决策／监督机制、资源约束、实际实验对照。只有机制相同才能判该机制已覆盖；只有实验操纵和主要对照对应，才能判实验问题已覆盖。不同论文分别拥有组件，不能直接证明其联合问题已解决。反过来，换数据集、模型规模或条目名称，也不能单独确立新机制。

复核：后续使用“明确覆盖／局部覆盖／所读部分未见／未核实”的措辞。未检索到不能写成世界范围不存在，论文未报某个消融也不能证明其方法不具备该能力。

### R2：核对组合检索与模板记忆的实际实验

证据：补读MemAPO[16]§4、Appendix A.5—A.6。Table 3是CTM／EPM消融；CTM本身包含策略和支持案例，Figure 5提示每个检索模板提供一个好案例。Figure 4改变top-k模板数；Table 4改变optimizer模型。未在这些实验中见到“固定同一规则、独立交换支持例子”的对照。

补读CEIL[13]§4：Table 3研究组合泛化，Table 6比较相同编码器下top-k与DPP；这是实际组合检索证据，不能说它只处理独立相关性。RetICL[14]§4.2—4.5在固定训练语料上选择T=2个例子，并做去除LSTM条件依赖等消融；训练200例候选库、测试全训练库的变化也不能被遗漏。

修改：模板内R/E解耦的实验尚未被上述MemAPO消融直接覆盖；集合／条件选择本身则已被CEIL和RetICL明确研究。禁止以“都叫记忆”否决，也禁止以“我们多一种条目类型”直接认领创新。

### R3：核对反馈归因，发现比V2更直接的证据

证据：补读GSEM[7]§4—5；式8—10依检索排名与共现分配反馈，§5.3比较50／150／250次演化快照。它确有关系更新及联合检索，但这些式子没有实施逐项移除干预。

新增BEAM[18]，完整核读Methodology、Experiments和Appendix A—B：式8执行leave-one-out，式9混合条件边际贡献和保留该项的上下文表现，训练`g(x,m)`；推理对每项抽样后top-k，并额外合成工作记忆。Figure 2／式15直接比较“在实际组合中移除一项”与“单项对空集”，包括MMLU-Pro Philosophy。因此“用组合上下文的反事实反馈训练逐题价值模型”已有实证，V2不能把它作为剩余空白。

新增TIDE[19]，核读§3—4：§4.3在20个、含五类注入噪声的受控episode中做确定性leave-one-out归因和定向改写；另有未来任务与容量治理实验。它覆盖“有干预证据才编辑”的机制，不能简单归入共现奖惩。

修改：保留待检验区别为**推理时显式评价可变R/E集合，以及该集合价值如何影响有限容量下的保留与改写决策**。BEAM推理评分的条件是`x,m`，不含待选择的其他集合成员；但其合成模块可以处理组合，不能据此断言它必然失败。TIDE有编辑／容量，尚不能据所读实验断言它已覆盖本项目的R/E集合选择。二者须进入强对照审查。

### R4：旧数据能否识别单条记忆价值

只读检查E3导出：旧14条R与新20条R共有13条完全相同的规则正文，总计21种规则正文；实际规则包含模式只有旧／新／空三种，包含矩阵的秩为2。因此2212个输出不能识别21条规则各自不受约束的效果；侧信息模型可以拟合，但其泛化来自模型假设，不能称为已有条目干预监督。

旧99例中94例曾实际注入；新302例中202例曾被召回、193例曾实际注入。未曝光例子不能据旧成绩标为低质量。所有计算仍是同一158题表的结构诊断，没有新增题目或模型回答。

修改：保留旧数据作正文初始化、整块消融和开发材料；新训练必须记录实际候选、选择概率、注入集合和版本，并采集必要的独立删换。后续评审要避免只给模型增加参数，却不补足监督覆盖。

### R5：容量政策的近邻与目标是否对应

证据：补读SkeMex[8]§4.3、Appendix F/H/I.5。Table 12确实分别移除deprecation、merging、capacity control与maturation；Appendix F规定分支条数上限、每两个学习窗口治理。这是实际容量治理证据，不可因其医学场景不同而忽略。所读实验没有固定正文token容量下的R/E解耦重组对照。

新增核读Retain or Consolidate?[20]的Methodology、实验Q3和Appendix B.6。其OAS用离线四动作结果训练11维ridge，在query到来后选择保留／抽象／合并／重写。原文明说这是query-time packing，而非query-agnostic长期维护。独立full-history实验中固定Merge为45.7%，direct ridge为44.7%；说明动作效用不同和oracle有空间，不等于可迁移的选择器已经有效。

修改：不再指定Caffeine为主系统。第一步使用简单有界内容库，固定政策隔离读取效果；后续保留决策比较“删换后重新召回、重新选组合”的效用损失。缓存频率、ridge动作预测、候选校验都视为已知构件；长期R/E保留问题与OAS四动作路由分别表述。

### R6：移除归因能否直接解决组合选择

CPU枚举反例：令`U(S)=0.05·1[r∈S]+0.1·1[a∈S]+0.1·1[b∈S]+0.65·1[r∈S且{e1,e2}至少一项在S]`。在全体五项的背景下，LOO credit为`r:0.7,e1:0,e2:0,a:0.1,b:0.1`；若只能取两项，照此排序取`r,a`得0.15，而`r,e1`得0.70。原因是两个可替代例子在全背景中互相掩盖。

这只否定“某一背景的LOO分数可直接用于所有较小集合”的推论，**没有证明BEAM会失败**：其训练混合其他反馈，推理还有抽样与合成；逐项模型也可能学出最优集合的成员。修改：比较的是归因标签、推理时条件化与集合大小变化的实际差别，不能宣传“逐项打分表达不了任何最优集合”。

### R7：同一反例是否也击中自己的二阶模型

复核R6：只用`r,e1`与`r,e2`的四配置各学到0.65的正交互，会把`r,e1,e2`预测为1.35，实际为0.70。即使补普通E/E项，也不能一般表示仅在r出现时发生的三阶替代作用。V2用少量单对检查后枚举4096子集，存在严重的未支持外推。

修改：第一版候选仍为4R＋8E，但动作先限制为总数≤3、每类≤2，共至多239个集合（还要扣除超长与版本冲突集合）。训练包含自然三项候选的全部8子集，平衡1R2E与2R1E，并直接检查三阶残差。加入同类交互作为共享强对照，主消融只移除跨R/E项。没有观测支持或三阶误差严重时，收窄动作或采用已有条件集合方法；不靠加大网络掩盖问题。

### R8：保留是否真的考虑了可替代内容

反例：R6中`{r,e1,e2}`里的e1和e2单独删除损失都为零，但同时删除两者损失为0.65。一次算好每项分数、再批量删掉低分项会误删整个支撑集合。反之，只有一个支撑例子时，按其单独成功率也可能错误淘汰它。

修改：定义缓存价值为近期查询上重新召回与选集合后的预测效用；每提出一个**完整可行换入／换出动作**就重算差值，多项删除不能累加单项旧分。候选可包含一个规则及一个支持例子，避免两者单独准入都失败。小规模局部枚举设计算上限，失败保留原状态；有限查询池和评分误差仍限制结论。先用FIFO隔离读取，只有联合选择有效后才比较这种保留机制。

### R9：错误修补会不会把错误原因和答案写进记忆

问题：选项正确不证明推理正确；当前错误题上修好不证明可迁移；旧边不经检查迁移到新正文会把过去证据冒用到新版本。

修改：curator只提有限草稿，不修改检索器／奖励；使用非当前题、非派生来源的开发回归池，恢复正常packing比较新旧状态。旧标签保留原版本，不销毁但不继承为新版本已验证证据。来源、长度、反馈等级和原子切换写入协议。四题的经验门槛只作原型过滤，不声称安全保证。

复核：没有合格回归题时draft可到期，系统允许NOOP；不靠“每次出错都必须更新”维持表面的自进化。

### R10：学习闭环是否存在泄漏、自强化与无界历史

问题：只用已选集合会自强化，未曝光不等于无效；用更新后的utility回填旧特征会泄漏反馈；训练缓冲和审计日志可能成为无容量上限的第二记忆库。

修改：加入有界相关动作探索、答前特征快照和概率日志；每题总训练权重一致。内容、轨迹文本、向量／关系及模型状态分别计量；审计目录不允许在线回读。读每题、写／训每32题，限制修改频率，提出经验稳定性指标而非理论收敛宣言。

复核：这些只是可审计的控制，不能保证无偏全库评估，也不能保证在非平稳任务中收敛。原型辅助容量若不够，减少可访问记录而不是转存无限库。

### R11：baseline是否被设计成容易输

问题：只比较top-k无法判断胜过已有组合学习；去掉BEAM合成、换小模型后仍叫BEAM不公平；来源未知的旧R/E不能伪称MemAPO原CTM。

修改：固定库七对象纳入NoCross、固定成组、LOO单项价值、CEIL式DPP及原ExpeL。机制适配与原论文复现分开，明确强原方法准入要求。受控组共享候选、监督和枚举约束；原ExpeL保留自身规则块作为运行参照。新增读取×保留2×2，避免把分别有效的组件自动当联合创新。

复核：共享标签的实际采集费用只记一次，独立部署成本逐方法公开；合成、额外标签和CPU开销都进入同费用比较。当前七对象是计划，不宣称已经跑过。

### R12：诊断规模是否被误当确认能力

CPU核算：A为256＋16＋32＋16＝320；B按96×10×2＋48×7×2＝2592次solver规划，仍未含原方法全部费用。按独立题、单次成对二元结果的近似功效，3pp差异常需约872—3485题，不能拿少量同题重复取代。

修改：A仅诊断，B仅开发学习曲线，C检验演化与保留，D另做独立确认；旧158题全部按开发材料使用。少量样本未显著必须标“无法判断”，只有精度足够才可排除实用效应。阶段A的局部版本比较不完成在线准入。

复核：继续使用原数据集可行；用原Engineering数据重新包装独立确认不可行。Physics／Math仍需来源与暴露审计，不能凭题数宣布足够。

### R13：对统一V3做端到端反例复核

发现两处跨模块不一致：草稿若提前进入首次回答，就绕过了“验证后晋升”；先验证新内容、再决定victim，则验证的不是最终部署状态。另有同prompt复用与预定重复解码身份未分清的问题。

修改：draft只用于额外验证，新晋升内容才参与在线探索；先确定含全部victim的C′，比较C与C′并提交同一事务。同prompt的同一重复身份复用，不吞掉计划内的两次独立解码，也不把无实际prompt变化的随机波动算成修补收益。成功案例写入与失败curator共用准入配额。

复核：读取—监督—提案—腾空间—验证—提交形成一致链条；辅助容量和查询池为空时都有明确处理。重召回目标不具有已证明的单调／次模性质，删去可能暗示贪心保证的解释。

### R14：同一最终方案的新颖性、数据和总成本联合终审

再次发现：保留目标使用历史查询池，如果允许某条记忆参与其自身来源题的评分，会偏向记住旧答案，未必保住可迁移经验。即使该一步目标提高，也不能推出长期自进化策略最优。

修改：维护评分增加逐query来源题族排除，新内容继承来源，未知来源采用保守过滤；明确`Vθ`只是有限查询池上的下一阶段读取代理目标。当前主张收窄到可检验的读取／维护耦合，不声称全局最优或理论收敛。

终审：问题和原型设计保留，具体新颖性待强对照；旧资产只够热启动与开发，独立确认尚不具备；320与2592的用途和未覆盖成本已分别标明。已核对20条引用编号、局部文件链接、239集合上限与预算算术，README同步。14轮都是同一助手递进自审；完成的是评审与方案修订，没有训练、效果确认或新增模型回答。
