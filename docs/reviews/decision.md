研究问题：**旧规则与新经历能否组合成比旧整库、新整库、仅新经历更有效的提示？**

A 是 ExpeL 的双组件外部记忆；B 是受控因子干预与组件版本回退。
候选 ON=(旧规则,新经历) 是预先指定，不能在 test 上四选一后当成方法结果。
如果固定 ON 的收益成立而选择器没有额外价值，报告机制发现；
如果仅新经历不差，或效果只能由 packing 变化解释，停止相应方法主张。

目前仅实现一次历史 ExpeL/Engineering discovery：
20%/60% 前缀；dev64/test96；七臂各两次独立回答；固定上下文8192，
输入最多5888、输出预留2048、余量256。
求解最多2240（含正式dev前四题smoke），无答案探测最多2，传输重试储备44，
总提交最多2286。先离线验收，再服务器 preflight/smoke，最后完整 discovery。

该样本量对普通差值的保守同时区间半宽约16.9个百分点，
不能可靠判断三个百分点的小效应；不确定是合法出口，不会自动扩跑追显著。
本机没有服务器源数据和模型，不能据这份评审声称真实运行已验证。

## 三轮通过后的实现验收

已实现独立 `scripts/e2` 与 `src/memgate/experiments`；不调用在线 Runner、
restore、generate/update 或 curator，不改官方子模块。
新增冻结导入、真实官方纯函数复用、分组件 packing、token IDs 传输、
实际服务身份接口、SQLite 持久尝试账本、受限 dev 选择与六对比分析。

本地 `pytest -q`：**46 passed**，包含原有测试及 E2 的 R3 T01–T13 类别。
测试调用真实官方纯 builder/检索/评分定义，用合成数据、fake tokenizer、
可计数 HTTP 服务及突然退出的子进程验证边界。
源码编译、shell 语法和 diff 空白检查通过。
这不代表真实数据、4090 显存、两端 tokenizer、实际模型输出或 ON 效应已验证。

下一步是服务器 [prepare → preflight → smoke](../E2组件交叉实验.md)，
通过技术验收后才继续同一协议的 discovery。
