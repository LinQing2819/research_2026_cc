# E4-D1：当前资产验收与服务器运行

当前可执行的是**旧资产只读导出与核验**。E2已完成，E3真实回放也已完成；E4限定设计见[最终稿](reviews/e4_diagnostic_design/r6_final_candidate.md)。新构建、正式审计与完整请求账本尚未实现和验收，不能运行旧E0/resume代替E4。

## 本次工具做什么

`e4-assets-v1.pyz`复用E3严格导出路径，读取已完成E2的原产物、请求账本和有效WAL，核验原始响应与评分。它补充导出manifest封存的旧／新构建前缀原文，核对前缀链与端点状态，并整理旧158题NN−OO、632份开发回答到实际记忆文本及完整输入的绑定。

工具没有生成、训练或联网入口。输出只写入新目录，不更改已完成实验的checkout、账本或预算，也不覆盖已有压缩包。

成功状态为`ASSETS_EXPORTED_NOT_QUALIFIED`：历史资产核验完成，仍不是新实验运行资格。真实64模板族清单、两条新构建清单、CPU拟合产物、模型／检索／打包身份和新状态／请求实现仍需后续验收。

前缀可以补足旧材料暴露核查和逐步变化诊断，不能作为新增独立历史，也不能据其反推不存在的逐规则唯一来源。

## 工作站：构建并上传

以下路径和`researcher@SERVER`均为公开说明用占位值，先替换为实际工作站目录、数据盘目录和SSH目标。不要把占位值原样执行。

在工作站仓库根目录：

```bash
set -e
python3 scripts/e4/build_zipapp.py
scp .cache/releases/e4-assets-v1.pyz scripts/e4/export_server.sh \
  researcher@SERVER:/data/experiment/
```

这两个独立文件即可运行。服务器不必访问GitHub或更新旧实验仓库；只读工具升级也不需要改已完成E2的版本。

## 服务器：在screen中导出并自动核验

先进入已有服务器仓库，初始化数据盘缓存和screen：

```bash
cd /data/experiment/research_2026_cc && \
source scripts/e2/env.sh && \
export SCREENDIR="$PWD/.cache/screen" && \
mkdir -p "$SCREENDIR" && \
chmod 700 "$SCREENDIR" && \
screen -S e4-assets bash
```

进入screen后执行：

```bash
bash /data/experiment/export_server.sh \
  /data/experiment/research_2026_cc \
  /data/experiment/e4-assets-v1.pyz \
  /data/experiment/e4-assets-v1
```

包装脚本进入指定仓库、重新source环境，再自动执行`version → export → inspect`，任何一步失败即停止。服务器解释器固定为`.venv-client/bin/python`；本次不启动`.venv-vllm`，不安装依赖。

最后应出现`ASSETS_EXPORTED_NOT_QUALIFIED`及`E4_ASSET_EXPORT_COMPLETE`，产物为：

```text
e4-assets-v1/
├── assets.json.gz
└── run.log
```

摘要应包含原E2的2212份正式回答、158道开发题／632份NN−OO旧回答，以及193／581题前缀。保存日志中的文件与代码身份供取回后核对。原始评分失败、前缀或输入绑定不匹配、缺账本时都不会产生有效新包。

已有输出目录会被拒绝。先查看原日志；确需重做只读导出时用另一个新输出目录，不删除旧账本或实验记录。

启动后按**Ctrl+A，松开，再按D**离开screen。重新连接后：

```bash
SCREENDIR=/data/experiment/research_2026_cc/.cache/screen screen -ls
SCREENDIR=/data/experiment/research_2026_cc/.cache/screen screen -r e4-assets
```

## 工作站：取回并继续

在工作站仓库根目录：

```bash
set -e
mkdir -p .cache
scp -r researcher@SERVER:/data/experiment/e4-assets-v1 .cache/
.venv/bin/python scripts/e4/assets.py inspect \
  --input .cache/e4-assets-v1/assets.json.gz
```

此处`.venv`仅指工作站测试环境。收到包后继续核对封存值、真实开发绑定与旧材料暴露范围，随后落实题族清单和冻结拟合。本次导出不自动消耗任何新生成额度。

## 接下来怎样进入真正的E4实验

| 顺序 | 必须形成的实际产物 |
|---|---|
| 1 | 旧开发回答、题面、实际规则／经历、完整输入及packing身份的绑定 |
| 2 | 64个评价模板族及两条各至多64题的构建清单，附与已用材料的交集核查 |
| 3 | 按R6定义拟合的唯一CPU主探针和全部预定对照，不按新审计表现调参 |
| 4 | 模型、评分器、检索器、渲染器、状态事件、预算预扣与拒绝／重试机制的实现验收 |
| 5 | 预测锁定、随机抽样／顺序／控制种子与运行清单；随后按冻结合同采集 |

题料不足、无法形成合格更新或完整curator输入超长，都允许结束该诊断。832次提交尝试和6,602,752预留tokens是未来新采集的总上限，包含构建与失败成本，不能与旧E2账本互相挪用。
