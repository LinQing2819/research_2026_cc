# 候选研究方案 V2：组件版本交叉与选择性回退

状态：待三轮评审；此文档不代表方案已通过，不是实验结果。2026-10-20。

## 文献依据与边界

- SeqMem-Eval，2026-05-14：[论文](https://arxiv.org/abs/2605.15384)。
  固定模型、外部记忆经提示影响预测；已诊断遗忘、负迁移和有用状态被后续更新破坏。
  附录 G 列出任务顺序、机制覆盖、诊断成本的局限。重复证明非单调不算贡献。
- Useful Memories Become Faulty When Continuously Updated by LLMs，
  [v2，2026-08-29](https://arxiv.org/pdf/2605.12978v2)，引言与 §2–3：
  区分 episodic traces 与 consolidated abstractions；同轨迹不同更新日程产生不同结果；
  episodic-only 已是重要控制；作者明确指出原始经历无限增长不是长期答案，
  展望是保留证据、区分经历存储与抽象形成。附录 I 已有 memory surgery，
  附录 L.2 已做更新步骤归因。不能声称首次研究抽象失败或首次记忆手术。
- [MemSkill](https://arxiv.org/abs/2602.02474)：已有 hard-case buffer、
  规则演化与基于稳定奖励的快照回退，不应把这些组件当创新。
- [PACE](https://arxiv.org/abs/2606.08106)：已有配对 anytime-valid 接受检验；
  摘要明确是 per-decision guarantee。加上置信序列不自动产生新颖性。
- [ChronoMem](https://arxiv.org/abs/2607.27773)：已有语义版本控制与整库回退。
- [Scope Before You Persist](https://arxiv.org/abs/2609.29144)：已有按任务族限定
  记忆部署范围的固定输出干预，不能将按任务族隔离当新贡献。
- [SkillSmith](https://arxiv.org/abs/2606.01314)：已有预算内技能选择、
  故障定位与冲突学习，通用 delta-debugging + 技能记忆不足以区分。

以上是针对性检索，不是穷尽检索或保证可发表。网页全文抓取常被目录截断，
具体论点以已读摘要、正文/PDF或可定位章节为限，不编造“作者没有做过”的断言。

## 被否决/待否决的粗方案

V0：快照回退 + 置信序列；或记忆演化 + 通用 replay。
与上述工作重合过多，且原 H3 估计对象有错配，不能沿用为新贡献。

V1：用完整 prompt 相同性证明一部分查询的期望更新效应为零，
把配对评估预算移到变化部分。可能只是缓存/分层抽样的直接应用，
必须与普通 prompt 去重缓存比较；没有超出这个控制的收益则不做主线。

## V2 的 A+B

A：ExpeL 的两个可分离提示组件——抽象规则 R 与成功经历池 E。
B：受控 2×2 因子实验，以及在独立验证集上选择组件版本的策略。

问题：在固定上下文预算下，混合版本能否超过最佳完整快照，
以较少旧能力损失保留新经历的收益？研究假设不是“混合必然好”。

固定旧时点 o 与新时点 n，四个干预：

| 名称 | 规则 | 经历 |
|---|---|---|
| OO | 旧 | 旧 |
| ON | 旧 | 新 |
| NO | 新 | 旧 |
| NN | 新 | 新 |

同一批后续题、同样模型/模板/检索器/解码与预算，先渲染所有提示，
再独立随机生成并配对比较。新经历是新时点的完整成功经历池，
包含旧池，不能解释成只包含最近经历。

交互量 I = μNN − μNO − μON + μOO。它描述人工可执行组件组合的交互，
不宣称识别自然间接效应，也不把 ON/NO 当成真实在线历史产生的状态。
如果旧新规则相同或检索结果相同，应报告干预实际相同的比例。

额外控制：无记忆、仅新规则、仅新经历。后者检验混合收益是不是“丢掉全部规则”即可达到。
完整快照选择器在 dev 选 OO/NN；组件选择器在同一 dev 选 OO/ON/NO/NN；
test 冻结选择、不再按 test 挑赢家。另与所有固定策略报告配对差值，
不把 test oracle 最佳值冒充可部署收益。

研究成功需要“组件选择的额外价值”，仅发现某一组件有害不够；
若仅新经历更强，按原假设失败记录，不能删除该控制来维持方法优势。

## 最小实验提案（待评审改定）

首轮用 MMLU-Pro Engineering 的历史 ExpeL-Online-ST 日志，
预先固定 20% 与 60% 构建前缀，之后依公开题目 ID 划分 dev/test。
不以 E0 H1、论文 ±3 点或新实验效果筛选进入资格。
由于 E0 已分析过这些题，这是机制 discovery，不能称独立确认。

只有完整、无重复、顺序可核对的 memory 记录才可导入。
冻结评估直接保留 memory.rollout.attempts 的 trajectory 与原始 insights_after；
不调用会删除 memory 的通用 seed 流程，不恢复后继续更新。
HumanEval、DC-RS 不在该首轮实验范围。不能把不显著当作无效应。

候选规模：dev 64、test 96、每题每臂两个独立回答，共 7×160×2=2240 次求解，
另加后端一致性检查。它只能发现大效应并估计方差；
小效应判为不确定。确认阶段必须有新记忆构建轨迹、独立数据与至少两个任务，
样本量由配对差值方差和预定最小重要差异决定。

## 上下文与计算限制

模型 Qwen3-8B，冻结参数，temperature=0.7、thinking=false、输出最多 2048。
不能用字数或 token≈字符/4 估算硬限制。
使用服务实际 tokenizer/chat template 计数，检查：

`prompt_tokens + max_new_tokens + safety_margin <= context_limit`。

实验默认研究预算 8192（即使服务支持 32768 也不放大），余量 256；
完整问题与模板不可截断。规则与经历有各自固定额度，超额丢弃完整最低优先级条目，
不删除答案格式、不截断代码、不在组件间借额度，以避免因素相互改变打包方式。
所有臂记录实际 tokens、被丢弃条目与 prompt hash；称相同预算上限，不称实际等长。
若问题本身不适配，整个题所有臂在生成前标为不支持，并报告覆盖率；
不能按某臂生成失败挑选比较样本。400 类上下文错误立即失败，不长时间重试。

只有评审通过后才实现 prepare/preflight/run/analyze；先跑小 smoke，再由服务器跑完整 discovery。
本机没有服务器数据/模型，离线测试不等于真实模型实验成功。
