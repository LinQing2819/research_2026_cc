## 一次导出，之后本机完成

当时已生成单文件工具 `.cache/releases/e3-r1-tools.pyz`。
它包含所需Python代码，沿用服务器`.venv-client`的numpy等已装依赖。
无需GitHub、无需修改服务器Git checkout、无需pip安装或新建环境。
可用`.venv-client/bin/python /data/experiment/e3-r1-tools.pyz version`核对协议、源码hash和运行库。

**1．本机终端上传工具：**

```bash
scp /path/to/research_2026_cc/.cache/releases/e3-r1-tools.pyz \
  researcher@SERVER:/data/experiment/e3-r1-tools.pyz
```

**2．服务器终端执行只读导出：**

```bash
cd /data/experiment/research_2026_cc && \
source scripts/e2/env.sh && \
.venv-client/bin/python /data/experiment/e3-r1-tools.pyz export \
  --repo /data/experiment/research_2026_cc \
  --output /data/experiment/e3-r1-e2-table.json.gz
```

成功显示`Verified E3 export`和`rows=2212`。源账本由SQLite只读一致事务读取，包含WAL；
不直接复制可能漏WAL的主数据库文件。导出核对所有原manifest产物和逐题评分，
错误会停止并显示原因。已有同名输出不覆盖；保留旧包，核对后再选择新输出文件名。
正常导出不启动模型；时间取决于本地文件读取与校验，一般远小于一次生成实验。

**3．本机终端取回：**

```bash
scp researcher@SERVER:/data/experiment/e3-r1-e2-table.json.gz \
  /path/to/research_2026_cc/.cache/e3-r1-e2-table.json.gz
```

传回后agent可直接继续回放；也可以在本机执行：

```bash
cd /path/to/research_2026_cc && \
.venv/bin/python scripts/e3/replay.py run \
  --input .cache/e3-r1-e2-table.json.gz
```

`.venv`仅为本机测试环境，服务器仍使用`.venv-client`。
输出目录为`reports/e3_replay/<输入及实现身份>/`，
包括`report.md`和封存的`replay.json`。

## 在服务器 screen 中自动导出并回放

上传最新工具后，也可以直接在服务器完成两步，无需更新E2 checkout。
工具包入口将失败状态传给shell，导出失败时不会继续回放。

**服务器终端：**

```bash
cd /data/experiment/research_2026_cc && \
source scripts/e2/env.sh && \
export SCREENDIR=/data/experiment/research_2026_cc/.cache/screen && \
mkdir -p "$SCREENDIR" && \
chmod 700 "$SCREENDIR" && \
screen -S e3-replay bash
```

**进入screen后，整块执行：**

```bash
cd /data/experiment/research_2026_cc && \
source scripts/e2/env.sh && \
E3_WORKDIR="$(mktemp -d /data/experiment/e3-r1-run.XXXXXX)" && \
(
  set -e
  .venv-client/bin/python /data/experiment/e3-r1-tools.pyz version
  .venv-client/bin/python /data/experiment/e3-r1-tools.pyz export \
    --repo /data/experiment/research_2026_cc \
    --output "$E3_WORKDIR/e2-table.json.gz"
  .venv-client/bin/python /data/experiment/e3-r1-tools.pyz run \
    --repo /data/experiment/research_2026_cc \
    --input "$E3_WORKDIR/e2-table.json.gz" \
    --output-dir "$E3_WORKDIR/reports"
) 2>&1 | tee "$E3_WORKDIR/run.log"
E3_EXIT=${PIPESTATUS[0]}
printf 'E3 exit=%s; output=%s\n' "$E3_EXIT" "$E3_WORKDIR"
```

每次创建独立输出目录，导出文件、报告和日志都写入该目录。
成功应同时出现`Verified E3 export`、`rows=2212`、筛查状态及`E3 exit=0`。
非零退出表示失败，保留日志排查。程序正常完成时也可能得到无增量筛查状态。

启动后用**Ctrl+A，松开，再按D**离开screen，任务继续运行。
重新连接时在服务器执行：

```bash
SCREENDIR=/data/experiment/research_2026_cc/.cache/screen screen -ls
SCREENDIR=/data/experiment/research_2026_cc/.cache/screen screen -r e3-replay
```

完成后将`output=`显示的目录取回，即可进一步核对真实结果。

## 会比较什么

六种方法：实际提示表示、检索后未packing表示、原始存储表示、
只加性、独立候选、不使用模型的均匀分配。
统一七个候选、搜索/复核预算、16种预定读取顺序。
每次都先用40道dev搜索，再用24道dev中的预算可负担前缀复核，
最后才读取94道test作描述性评价。

结果只有：

- `WORTH_INDEPENDENT_TEST`：此表上达到事先约定的实用筛查条件，
  值得继续设计新数据验证；不是论文机制GO。
- `NO_INCREMENTAL_SIGNAL_ON_THIS_TABLE`：当前表示/分配没有显示足够增量，
  不自动追加生成。
- `ERROR/INVALID`：数据、评分或预算校验失败，保留证据并排查。

16种顺序共用同一批旧回答，不算16次独立实验。
程序不会计算伪造的跨历史p值，也不会用本结果替换E2的主置信区间。
