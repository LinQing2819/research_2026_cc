# 自进化 Agent 外部记忆：研究进展、实验结果与后续方向


本研究关注一个问题：Agent 不断积累案例、改写规则后，怎样判断哪些记忆更新值得保留？模型参数保持固定，变化的是答题前提供给模型的外部文字记忆。

已完成的 E2 实验将记忆拆成规则和成功经历，比较两个历史版本的七种组合。“旧规则＋新经历”在94道测试题上的准确率为57.45%，高于旧整库的50.00%和新整库的49.47%，但预先规定的统计区间未确认可靠收益；根据开发集选择配置的算法也没有取得收益。

E3已完成真实数据上的离线比较，新增模型调用为0。“实际进入提示的记忆表示”对应平均测试准确率50.83%，原始存储表示为51.00%，未达到预设增量条件。进一步诊断提示：题目本身的难度较容易预测，但记忆变化造成的细小差异更难与随机回答波动区分。

当前收敛到 **E4：自然记忆更新的可测性与廉价预测诊断**。先判断更新差异能否被可靠测量，以及简单预测能否减少剩余评估误差，再讨论用更少测试判断更新好坏。限定设计已完成评审，真实题族、输入与执行记录仍待验收，尚未开始新生成。简要汇报见[导师汇报](导师汇报.md)。

## 1．研究问题：积累更多记忆，为什么不一定更好？

Agent 可以把做过的题和总结出的规则保存下来，在后续任务中查阅。这样不必重新训练模型，就可能利用过去的经验。但新增案例可能不相关，规则可能总结过度，输入也可能因记忆增多而变长。因此，“记忆更多”和“答题更好”之间没有必然关系。

例如，一个系统从几道直流电路题总结出“直接用电压除以电阻求电流”，随后把这句话用于包含电抗的交流电路题，就可能忽略适用条件。与此同时，新积累的交流电路案例可能很有帮助。如果把整份新版记忆全部丢弃，有用的新案例也会一起丢掉。

这个例子是用于解释问题的假设情境，并非本轮已经定位的错误。它引出两个研究问题：

1. **组件问题：** 规则和案例是否需要分别管理版本，而不是一起更新、一起回退？
2. **选择问题：** 即使存在更好的组合，算法能否仅凭有限的验证题把它选出来？

E2分别测量固定组件组合的表现和配置选择的效果。E3进一步研究选择过程中应当如何表示配置、分配评估预算。

## 2．先理解几个基本概念

### 2.1 Agent 的“记忆”是什么？

可以把大模型想象成一个能力固定的学生，外部记忆是他做题时可以翻看的笔记。

- **模型权重**：学生原本掌握的知识与能力。我们没有训练或修改这部分。
- **外部记忆**：写在文件或数据库里的文字，做题前被取出来，放进模型的输入。
- **自进化记忆**：做完题后，系统继续增加案例或修改总结；变化发生在笔记里。

因此，本项目测量的是同一个模型在不同笔记条件下的表现。

### 2.2 我们关心两种笔记

| 组件 | 通俗理解 | 内容 |
|---|---|---|
| 规则 R，Rules | 方法总结本 | 从历史任务中归纳的文字规则，例如解题注意事项 |
| 经历 E，Experiences | 例题本 | 历史成功任务的题目和模型解答轨迹 |

例如，“计算前先统一单位，检查题目条件是否满足公式要求”属于规则；“某道题的题干、选项，以及模型当时逐步求解并得到正确答案的记录”属于经历。前者尝试概括方法，后者保留一次具体任务的上下文。这里的文字示例不代表实际快照中存在同样的条目。

这里的经历不是外部教材标准解析，而是当时被固定评分器判成功的模型轨迹。判最终答案正确，不等于证明整段推理每一步都正确。

规则可能压缩很多案例，也可能过度概括；案例保留细节，但占输入空间。两者都可能帮助模型，也可能干扰模型。

### 2.3 从“存着的记忆”到“模型看到的记忆”，还隔着几步

```text
整个记忆库
    ↓ 检索：按当前题目找相关成功案例，最多取3条
检索出来的案例 + 选定版本的规则
    ↓ 打包：按token限额保留完整条目
真正放进提示的规则和案例
    ↓ 加上当前题目、选项、格式要求
模型收到的完整输入
```

**记忆库很大，不等于模型每道题都能看到全部内容。** 这一区别是E3表示比较的出发点。

例如，经历池有100条案例，但一道天线题只检索出3条相关案例；如果其中一条过长，打包后可能只保留2条。模型这次作答受到的是这2条案例与规则的影响，而不是直接读取全部100条案例。

### 2.4 本文会用到的术语

| 术语 | 初学者解释 |
|---|---|
| 快照／版本 | 把某一时刻的记忆保存下来，之后不再修改 |
| 冻结实验 | 固定记忆后只答题，不继续学习和更新记忆 |
| 实验臂 | 一种实验条件，例如“旧规则＋新经历” |
| dev／开发集 | 用来比较候选、选择配置的题 |
| test／测试集 | 配置选定后，用来评价表现的题 |
| token | 模型处理文本的计数单位，不等于一个汉字或一个英文单词 |
| packing／打包 | 为了满足输入上限，按固定规则装入文字 |
| 点估计 | 这一次实验实际算出来的分数或差值 |
| 置信区间 | 在规定统计假设下，用来表达估计不确定性的区间 |
| 探索实验 | 帮助发现现象、判断后续方向；证据范围通常较窄 |
| 独立确认 | 用没有参与当前方案选择的新数据和预先冻结的设计验证假设 |
| 冒烟测试 | 先跑一小部分正式请求，检查服务、输入、评分和保存流程 |
| 回放 | 不再调用模型，而是按某个算法的读取顺序取出已保存结果 |

| 阶段 | 当时的问题 | 做过的工作 | 当前如何看待 |
|---|---|---|---|
| E0：记忆伤害筛查 | 使用记忆会不会把题答错？能否提前预测？ | 多任务／多记忆方法筛查、无记忆噪声对照、预测与监测分析 | 有探索线索，但部分实现和统计解释有缺陷 |

| E2：组件交叉 | 整库回退是否太粗？旧规则能否配新经历？ | 冻结七臂，完成数据复核、上下文验收和完整生成 | 已实际完成；主结果 INCONCLUSIVE |

| E4-D1：当前准备阶段 | 自然更新的影响能否测清、能否被廉价预测？ | 收敛唯一主探针、两条新路径、统计量与完整预算 | 限定设计通过；资产和执行资格待验收 |

项目总问题没有变：**怎样让不断变化的外部记忆真正有用，同时避免被噪声、错误更新和有限预算误导。**
研究切入点从逐题识别伤害，收窄到固定组件比较与配置选择，再回到省评估成本所必需的前提：更新差异是否可测、可预测。

## 4．最早的 E0 思路：先找“记忆造成伤害”的证据

### 4.1 当时想解决什么？

最初想法是：记忆并不是每道题都该用。如果能提前判断“这道题会被记忆带偏”，就可以在答题前决定用不用记忆。

为此设计三个问题：

1. **H1：有没有额外伤害？** 同一道题，无记忆答对、使用记忆答错的情况，是否超过模型本身的随机翻转？
2. **H2：能否提前预测？** 只看答题前已有的信息，如检索相似度、历史位置、案例数量，能否预测这种风险？
3. **H3：能否低成本监测？** 不给每道题都跑完整对照，只抽查部分题，能否发现记忆拖后腿？

为了估计随机噪声，原设计让无记忆模型独立跑两遍。即使输入条件一样，大模型也可能一次答对、一次答错，所以不能把所有翻转都归因于记忆。

例如，若100道题中有12道出现“无记忆答对、用记忆答错”，但两遍无记忆之间也有9道同方向翻转，那么12道不能全部算作记忆造成的稳定伤害。无记忆重复对照用于衡量背景随机波动。这些数量是解释设计的示例，不是E0实测结果。

### 4.2 E0 涉及哪些材料？

使用 SeqMem-Eval 的任务与方法接口，模型为 Qwen3-8B。早期任务包括：

| 数据集 | 大致内容 |
|---|---|
| MATH500 | 数学解题 |
| MMLU-Pro Engineering | 工程类选择题 |
| MMLU-Pro Physics | 物理类选择题 |
| HumanEval | 按要求写 Python 函数 |
| APIBench-HF | 根据要求调用 HuggingFace 相关接口 |

记忆方法包括原始经历检索 ExpRAG／HistoryRAG、动态小抄 DC-RS、工作流记忆 AWM、规则加经历的 ExpeL。不同方法并非只是名字不同，它们存什么、怎么更新、怎么恢复状态都不同。

### 4.3 早期数字是什么？为什么不能直接当成最终结论？

| 历史记录中的数字 | 当时的线索 | 现在能讲到什么程度 |
|---|---|---|
| 18个任务×方法格中，6格出现超过5个百分点的超额伤害筛查信号 | 记忆负效应值得研究 | 尚受日志完整性、方法反馈等问题影响，不能当成已完成审计的稳定结论 |
| 生成前预测 AUC 约0.56，未达到0.65门槛 | 当时那组特征和预测器信号较弱 | 特征时序存在泄漏问题，尚不足以判断生成前风险预测是否可行 |
| 当时监测区间半宽约0.126 | 原监测量的精度较粗 | 监测目标有错配，不能直接解释成当前版本收益的检出限 |
| APIBench本地无记忆75.30%，论文参考64.5%，高10.80个百分点 | 复现口径需核对 | 不能仅因为本地更高就断言代码错，也不能当作新方法提升 |

**这些是历史探索数值，原始 E0 明细尚未重新完整审计。**
“超额伤害”是一个对翻转现象作噪声校正的筛查指标，不直接识别每一道题被记忆稳定损害的概率；不能把所有被计数的翻转都解释成已确认的个体因果伤害。

AUC 可以粗略理解为预测器排序风险的能力；0.5接近随机排序。约0.56说明当时没有得到足够强的可用信号，不是不可预测性定理。

### 4.4 审查发现了什么问题？

早期实现有几类影响科学解释的问题：

- **续跑时旧日志可能被覆盖**：最后看似跑完了，明细却可能只保留后半段。
- **某些任务反馈格式与记忆方法期待的格式不一致**：题做对了，却没有正常学入成功经历。
- **恢复快照时可能丢失方法专有字段**：恢复出来的“旧记忆”不一定就是原来那份。
- **预测特征的时间顺序不对**：已经看过当前题答案、更新过的规则，被当成答题前的特征。
- **监测的量与解释的量不一致**：代码计算的是一种加权历史均值，却被解释成当前记忆或普通累计收益。

这些问题使我们停止直接扩展“逐题用不用记忆”的路线，转而寻找更容易控制、解释和核验的实验。
这些历史问题尚未全部修复。E2另建了较窄的冻结执行路径，避免依赖有问题的在线恢复和监测流程。

## 5．中间的 E1 思路：如果新记忆坏了，能否退回旧记忆？

一个自然想法是保存旧版本。最新笔记如果变差，就退回以前表现好的笔记。

E1主要想回答：**在同一批后续题目上，较早的完整记忆快照是否优于较新的完整快照？**

这条路线有两个不足：

1. 恢复必须保真，否则不是在比较真实旧／新记忆。
2. “保存版本、验证、回退”本身已有相关工作，并不自动构成论文新贡献。

还有一个更具体的问题：**整库回退会把所有组件一起退回。** 如果坏的是新版规则，而新增经历有用，整库回退就会同时丢掉有用的部分。

这使我们转向 E2：把规则和经历拆开比较。

## 6．E2 到底在做什么？

### 6.1 将“一份记忆”拆成两部分，做交叉对照

E2不是让模型边考试边学习，而是先从同一条历史中取出较早和较晚的两份记忆，再固定它们，比较后续答题表现。

假设较早快照是“规则本第1版＋例题本第1版”，较晚快照是“规则本第2版＋例题本第2版”。整库比较只能回答第1版和第2版谁更好。E2增加两种搭配：

| 配置 | 笔记本类比 | 具体改变 |
|---|---|---|
| OO | 规则本第1版＋例题本第1版 | 保持旧整库 |
| ON | 规则本第1版＋例题本第2版 | 只替换经历池 |
| NO | 规则本第2版＋例题本第1版 | 只替换规则 |
| NN | 规则本第2版＋例题本第2版 | 同时替换两部分 |

对于同一道后续题，四种配置分别生成回答，模型、题干和评分规则相同。这样可以检查：新增经历是否有用？新版规则是否有用？一种规则的效果是否随搭配的经历而变化？另外三个缺失组件的对照用于判断是否需要规则、是否需要经历，以及是否需要记忆。

例如，若ON优于OO，说明“保留旧规则、换用新经历池”在当前设置下有正向差值；若ON还优于NN，则保留旧规则可能比换成新规则更合适。但这种结果仍需要统计支持，也不能单凭准确率差就确定是哪条规则造成了错误。

### 6.2 预先关注的假设

**可能出现这样的情况：旧规则仍然好用，而更大的新经历池带来了有用案例，两者搭配优于旧整库、新整库或只用经历。**

这是假设，不是实验前已经知道的事实。

实验使用 ExpeL 的规则＋成功经历双组件记忆，在两个时点冻结状态，交叉搭配版本，并在开发集上选择配置。组件交叉本身是实验设计，尚不构成已经验证的新算法。

本轮预先指定主要关注 ON，即“旧规则＋新经历”，不是看完 test 才从七个条件里挑最高分命名方法。

### 6.3 为什么需要七个实验条件？

字母 O 表示 Old／旧，N 表示 New／新。第一位对应规则，第二位对应经历。
ZE、RZ是特设的组件缺失控制，含义以表格为准。

| 臂 | 规则 | 经历 | 解决哪个比较问题 |
|---|---|---|---|
| OO | 旧 | 旧 | 旧完整快照 |
| ON | 旧 | 新 | 预先指定的主要混搭 |
| NO | 新 | 旧 | 反方向混搭 |
| NN | 新 | 新 | 新完整快照 |
| ZE | 空 | 新 | 如果删掉全部规则就够了，还需要旧规则吗？ |
| RZ | 新 | 空 | 只用新规则是什么表现？ |
| ZZ | 空 | 空 | 这些记忆配置是否优于不用记忆？ |

七臂使用同一个求解提示框架。ZZ是“同框架下不放记忆”，不等于另一个模板的官方 Baseline 复现分数。

**“新经历”是较新时点的完整经历池，包含旧经历，不是只有最近新增的案例。**

以ON与ZE为例，两者用同一个新经历池，区别是ON增加了旧规则。如果只比较ON与NN，即使ON较好，也无法排除“删掉全部规则同样好”的解释；ZE就是为了检查这个可能性。ZZ进一步检查：使用这些记忆是否比完全不放记忆更值得。

### 6.4 它为什么仍然只是探索实验？

这次只有一个模型、一个任务、一条记忆构建历史、两个时点。
冻结测试题没有进入这两个构建前缀，但项目早先已分析过这些题的 E0 结果。

因此，本轮可以帮助研究固定条件下的组件效应，但不能声称：

- 已在全新任务上泛化；
- 已对多条独立记忆历史确认；
- 已部署在线部分提交；
- 已证明任意时候回退都安全；
- 已经拥有可以投稿的完整方法贡献。

### 7.2 题目怎样划分？

```text
969道原始工程题
├─ 前193题：形成旧快照
├─ 继续到第581题：形成新快照
└─ 剩余388题：按固定seed打乱
   ├─ 64题dev：选择配置
   ├─ 96题原test：预定评价题
   │  └─ 共同排除2道确认重复题 → 实际test 94题
   └─ 其余228题：不补入本轮
```

固定seed为20261020。排除重复题后没有补位，也没有改变历史案例和规则。

### 7.3 为什么测试集从96题变成94题？

V4准备阶段检查出3对跨越“记忆构建前缀／test”边界的近重复候选。
这里的“候选”只是文字相近，必须检查内容，不能全部当作重复。

| 构建前缀题 ↔ test题 | 复核结论 | 处理 |
|---|---|---|
| 11528 ↔ 12215 | 同一道电磁题，1000 Mc/sec与1 GHz只是单位换写 | 排除test 12215 |
| 11568 ↔ 11872 | 拉普拉斯表达式不同，模板相似但不是同题 | 保留test 11872 |
| 11804 ↔ 11932 | 同一天线题，方向性50、波长4m，选项变化 | 排除test 11932 |

为什么这是问题？如果“例题本里已经有几乎一样的考试题”，考试结果就很难代表对未进入记忆的问题的能力。

所以V4先停止，之后在**新E2生成之前**修订为V5：固定公共内容复核、七臂共同排除、不补题，保留原始审计。不是看到某题答错后才把它删掉。
这一流程解决了当时检测到的候选，不等于证明全库没有任何未发现的语义重复。

### 7.4 数据保存为哪些东西？

| 数据层 | 保存内容 | 用途 |
|---|---|---|
| 原始任务 | 题号、题干、选项；另存标准答案 | 提供任务、固定评分 |
| E0记忆日志 | 历史题目、反馈、成功轨迹、规则变化、池大小 | 核对历史来源，构造两个快照 |
| 每题准备产物 | 七臂检索案例、打包文本、完整token IDs和长度 | 确保比较的是实际输入 |
| 请求账本 | 每次尝试、payload、seed、原始响应、接受结果 | 计费、断点恢复和复核 |
| 结果表 | phase、qid、arm、rep、score、usage等 | 按题、按臂统计结果 |
| 汇总分析 | 七臂准确率、六个对比、选择器结果、成本 | 结果解释依据 |

当前分析同时依据已校验的汇总 `analysis.json` 和完整2212条逐题导出。导出核对了原始请求、响应、评分与账本，并保存每题实际输入及选择结果；可以定位观测上的受益／受损题。导出投影没有保留当前回答的完整推理正文，因此不能单凭对错变化归因到某条规则。

单条实验记录可理解为：

```text
题号：某道未进入记忆构建前缀的工程题
配置：ON（旧规则＋新经历）
重复编号：第1次独立回答
输入：旧规则＋从新经历池检索并打包的案例＋当前题干和选项
输出：模型的解答和最终选项
评分：正确为1，错误为0
用量：本次输入和输出的token数
```

同一道题还会有ON的第2次回答，以及另外六种配置各2次回答，共14条正式记录。评分答案不参与当前题的案例检索或提示构造。

### 7.5 为什么是2212次正式请求？

每道题有7种条件，每种条件独立答2次：

```text
dev：64 × 7 × 2 = 896
test：94 × 7 × 2 = 1316
合计：896 + 1316 = 2212
```

冒烟测试是dev前4题：

```text
4 × 7 × 2 = 56
```

这56次包含在896次dev里，完整运行时复用，不额外再算一遍。
此外有2次服务探测和2次传输／恢复重试，总计2216次attempt。
重试不依据答对答错择优；未知是否已发送的尝试也计入预算。

## 8．E2 的实际结果

### 8.1 七臂准确率

每臂94道题、每题2次，共188条回答。准确率按两次独立结果平均计算，不采用“有一次答对就算整题对”的pass@2。

例如，一道题在ON条件下第一次答对、第二次答错，这道题的平均得分是0.5，不是1。每道题按这一方式计算，再在94道题上平均，等价于用正确回答数除以188。这测量的是独立作答的平均准确率。

| 排序 | 臂 | 记忆组合 | 正确回答／188 | 准确率 |
|---|---|---|---:|---:|
| 1 | **ON** | **旧规则＋新经历** | **108** | **57.45%** |
| 2 | ZZ | 无记忆 | 99 | 52.66% |
| 3 | NO | 新规则＋旧经历 | 96 | 51.06% |
| 4 | ZE | 仅新经历 | 95 | 50.53% |
| 5 | OO | 旧规则＋旧经历 | 94 | 50.00% |
| 6 | NN | 新规则＋新经历 | 93 | 49.47% |
| 7 | RZ | 仅新规则 | 90 | 47.87% |

ON比OO、NN、ZE分别多14、15、13条正确回答，比ZZ多9条。
**这是正确回答总量的净差，不等于有14、15、13或9道题被稳定修复。**
有些题可能受益，有些题可能受损，汇总后才得到这些净差。

### 8.2 三个预先规定的主对照

| 对比 | 回答的问题 | 差值，百分点 | 同时95%置信区间，百分点 |
|---|---|---:|---|
| C1＝ON−OO | 换上新经历后，是否优于旧整库？ | +7.45 | [−9.63, +24.52] |
| C2＝ON−NN | 保留旧规则，是否优于新整库？ | +7.98 | [−9.10, +25.05] |
| C3＝ON−ZE | 旧规则是否比完全不放规则更有用？ | +6.91 | [−10.16, +23.99] |

“+7.45个百分点”表示50.00%到57.45%的绝对差，不是相对提升7.45%。
这三项共享同一组ON回答，不能当成三次互相独立的重复实验。

### 8.3 INCONCLUSIVE 到底是什么意思？

预先规定最小重要收益为3个百分点：

- **GO**：C1、C2、C3三个区间下界都严格大于3个百分点。
- **NO_GO**：至少一个必要对照的区间上界严格小于3个百分点。
- **INCONCLUSIVE**：既没有满足GO，也没有满足NO_GO。

本轮三项区间都跨过零，也跨过3个百分点，所以主结论是 **INCONCLUSIVE**。

通俗地说：这次考试看起来ON更好，但误差范围足够大，真实平均优势可能很小，甚至方向相反。现有数据无法排除这些情况。
它不是程序报错，不是“证明方法没用”，也不是“只差一个统计手续就算成功”。

运行、校验和报告生成已经正常完成；这与统计上是否确认收益属于不同判断。

### 8.4 为什么区间这么宽？

本轮使用预先固定的保守有界变量区间，同时覆盖六个对比。94题时普通差值半宽约 **17.07个百分点**。
因此，要让单项下界超过3个百分点，观测差值需要超过约 **20.07个百分点**。

这不是结果出来以后才发现的要求。实验前已明确：该规模主要用于大效应／可行性探索，不能可靠确认几个百分点的小提升。
96题变94题只把半宽增加约0.18个百分点，低功效的主要原因不是删了两题。

本轮区间的对象还很窄：条件于固定历史、固定题集、模型、提示与选择结果，研究新的独立解码均值，并假设请求条件独立、后端稳定、评分固定。它不直接涵盖换任务或重新构建记忆的全部不确定性。

### 8.5 无记忆对照给了什么提醒？

ZZ有52.66%，高于除ON外的所有记忆组合的点估计。
ON相对ZZ只有 **+4.79个百分点**。

ON相对新整库有约8个百分点的差值，相对无记忆的差值则更小。后者是描述性补充，尚没有按本轮主检验确认可靠优势。

这说明下一阶段必须保留无记忆基线。复杂记忆系统需要证明带来的净价值，不能只挑较弱的记忆配置比较。

## 9．自动选择器为什么没有取得收益？

### 9.1 “某个固定组合好”与“算法能把它选出来”是两回事

E2同时研究了两个选择器：

- **F，完整快照选择器**：只在OO和NN中选。
- **S，组件选择器**：在OO、ON、NO、NN中选。

都只能根据获授权的dev结果选一个配置，选定后固定用于test。
不能到test上看到ON最高，回头把S的选择改成ON。

例如，考试前有一小批练习题，算法只能根据练习题成绩选一本笔记；考试结束后发现另一本文档分数更高，也不能把它追认为算法当时的选择。E2中，固定ON的成绩和选择器的成绩分别回答“这个组合怎么样”和“算法能不能提前选对”。

### 9.2 为什么F看64题，S只看31题？

两个选择器的预留token预算相同：**1,366,532**。
F每道题比较两个候选，S每道题比较四个候选；S每题更贵，所以只能读取固定dev顺序的前31题。

等预算比较因此存在一个取舍：增加候选范围，会减少每个候选能够获得的验证信息。

### 9.3 dev上的真实分数

| 选择器 | 获授权dev题数 | OO | ON | NO | NN | 最终选择 |
|---|---:|---:|---:|---:|---:|---|
| S：组件选择 | 31 | **56.45%（35/62）** | 38.71%（24/62） | 48.39%（30/62） | 38.71%（24/62） | OO |
| F：整库选择 | 64 | **57.81%（74/128）** | 不属于候选 | 不属于候选 | 50.00%（64/128） | OO |

S在它看到的dev上，OO比ON高17.74个百分点。选择OO符合预定“均值最高”规则，不是平局处理、候选漏掉或程序选错最大值。
test上则是ON比OO高7.45个百分点，出现了开发集与测试集的相对排名反转。

这说明本次选择没有在test上选中点估计最好的组合。
**但不能仅凭一次反转就断言发生了分布漂移、过拟合，或者31题太少就是唯一原因。**
题目组成和随机解码等因素都可能参与，需要逐题数据及独立历史进一步区分。

### 9.4 辅助指标怎么解释？

| 指标 | 结果 | 含义 |
|---|---|---|
| D_F＝S−F | 0，区间[0,0]，NO_GO | S和F都选OO，引用同一臂，所以差值精确为零 |
| D_ON＝S−ON | −7.45pp，区间[−24.52,+9.63]pp | 选择OO相对预定固定ON的本次表现，仍不确定 |
| I＝NN−NO−ON＋OO | −9.04pp，区间[−33.19,+15.10]pp | 加性尺度的交互，符号仍未确定 |

D_F的NO_GO只是否定**本次两个已实现选择之间有超过3pp的收益**，不等于所有组件选择方法都无效。

交互指标可以理解为“新规则的作用会不会随着经历版本而改变”。在旧经历条件下，新规则的观测差值是NO−OO＝+1.06个百分点；在新经历条件下，该差值是NN−ON＝−7.98个百分点。后者减前者就是−9.04个百分点。区间跨零，意味着目前没有确认这种差异稳定存在。

## 10．这轮数据对“机制”能说明多少？

### 10.1 有一个值得追问的模式

把旧规则换成新规则：

| 搭配的经历 | 比较 | 点估计变化 |
|---|---|---:|
| 旧经历 | NO−OO | +1.06pp |
| 新经历 | NN−ON | −7.98pp |

这提出一个问题：规则的效果是否取决于它与哪份经历搭配？

但交互区间跨零，因此目前只能叫**模式或线索**，不能说已经证明“新规则与新经历冲突”。
新规则也比旧规则更长、更复杂，效应可能同时涉及内容、长度和注意力干扰。

### 10.2 本轮没有显示明显的整库退化

NN为49.47%，OO为50.00%，只差约−0.53个百分点。
因此，把结果概括成“我们成功恢复了明显退化的完整记忆”并不准确。

更贴近数据的说法是：

> 在同一条历史和这批题上，固定组件混搭有较高点估计，但完整快照间的差距很小，且混搭优势尚未确认。

### 10.3 不能忽略“只是更少干扰”的解释

由于ZZ不弱，ON的优势既可能来自有用知识，也可能来自相对其他记忆条件更少的干扰，还可能含随机波动。
七臂实验帮助排除一些解释，但不能一次就把具体语言机制全部识别出来。
要讲“内容冲突”或“旧知识保留、新知识吸收”，还需要相应的独立控制和分组定义。

## 11．实验控制与计算成本

### 11.1 已经完成的执行流程

```text
核对代码版本
→ 数据审计
→ prepare：冻结检索、打包、完整输入、请求清单
→ 启动服务
→ preflight：检查真实tokenizer／服务与两个探测请求
→ smoke：正式dev前4题
→ 剩余dev
→ 封存两个选择器的选择
→ test
→ 生成统计报告
```

正式运行前检查数据、完整输入、服务和评分流程；每一步通过后进入下一步，失败则停止。请求账本保存所有尝试，避免续跑时遗漏结果或重复计算预算。

### 11.2 为什么没有再次出现上下文无限变长？

每次请求硬限制为：

```text
总窗口8192 = 输入最多5888 + 输出预留2048 + 安全余量256
```

规则块最多1024 tokens，经历块最多3072 tokens；两者分别按固定顺序保留完整条目，不互相借额度。
最终还用实际完整chat token IDs检查，不能靠字数估算。
任一臂超限就事先共同排除该题，不能生成失败后临时改提示再算同一实验。

真实汇总：

| 项目 | 结果 |
|---|---:|
| dev合格题 | 64/64 |
| test合格题 | 94/94 |
| 因上下文额外排除 | 0题 |
| dev最大输入 | 4599 tokens |
| test最大输入 | 5688 tokens |
| 旧规则 | 14条，535 tokens，全部保留 |
| 新规则 | 20条，902 tokens，全部保留 |
| test中ON／OO输入不同 | 93/94题 |
| test中ON／NN、ON／ZE输入不同 | 各94/94题 |

所以本轮没有因为规则被删空或主对照完全相同而失去输入干预。
但部分检索案例确实按预算被删除，结果应解释为**当前固定packing下的配置表现**，不是无限上下文下整库内容的表现。

### 11.3 请求与token成本

| 项目 | 结果 |
|---|---:|
| 正式逻辑请求 | 2212 |
| 服务探测 | 2 |
| 重试 | 2 |
| 总attempt | 2216 |
| 正式回答输入tokens | 5,648,802 |
| 正式回答输出tokens | 1,736,711 |
| 正式已接纳回答总tokens | 7,385,513，约739万 |
| 因输出长度上限结束 | 34/2212，约1.54% |

加上有usage记录的探测等，全部已知token用量为7,393,921；另有两次attempt的usage未知，因此不能把这个数字称为全部实际消耗的精确总量。
汇总文件没有完整运行时长，暂不能给出精确耗时。

### 11.4 实现验证与结果复核

- E2 v0.2.0曾通过86项测试，v0.2.1补充执行环境定向验证。
- E3工具通过14项测试，包括完整合成数据导出／回放、两次重试、WAL、篡改检查、预算与数据隔离。
- 测试通过支持“这些实现路径按预期工作”，不能代替“科研假设成立”。
- 已核对E2汇总封存值、选择器绑定及统计算术；真实导出已按原始响应和固定评分器重核全部正式结果，真实回放已完成。

## 12．为什么没有直接把 E2 扩大成更复杂的新方法？

我们先后考虑过几种方案：

| 候选 | 初步想法 | 为什么没有直接采用 |
|---|---|---|
| 四组合验收＋部分提交 | 新规则坏、经历好时，只保留经历更新 | 普通全组合搜索也能做，尚无独立算法增量 |
| 贝叶斯交互图＋失败记录 | 估计组件冲突并记住失败组合 | SkillSmith v2已有相近组件效用、交互估计和版本化失败约束 |
| 多版本效用矩阵＋低秩搜索 | 用少量组合预测其余组合，减少评估 | 低秩bandit已有；记忆矩阵低秩尚无证据，可能漏掉个别重要组合 |
| 结构核＋贝叶斯优化 | 同时表示规则和案例再主动选配置 | HbBoPs已联合建模指令与示例并分配验证资源 |

代表性近邻及本文使用的边界：

- [Faulty Memories v2](https://arxiv.org/html/2605.12978v2)：选择性／延迟抽象、保留原始经历和快慢存储已被讨论。
- [PACE](https://arxiv.org/html/2606.08106v1)：配对验收、可提前停止的单候选控制已有。
- [SkillSmith v2，2606.01314](https://arxiv.org/html/2606.01314v2)：交互效用估计和版本作用域失败约束已有。
- [低秩bandit](https://arxiv.org/html/2402.15739v1)：通过结构共享信息做策略识别已有。
- [HbBoPs](https://arxiv.org/html/2412.07820v2)：指令与示例结构表示、GP和多保真选择已有。

上述文献核验覆盖了主要近邻，尚非穷尽性检索。已有研究使“拆组件、验收、回退”不足以单独支撑新颖性，需要进一步明确可测量的差异。

后续方案需要明确可检验的差异，并与简单选择方法及相关结构方法比较。增加组件数量或更换应用场景，不能替代方法增量的证据。

## 13．从组件比较转向有限预算的配置选择

### 13.1 从“哪个组合看起来最好”，转到“怎样以有限预算选配置”

原E2的问题：

> 旧规则＋新经历，是否比几个固定对照更有效？

E3-R1的问题：

> 在相同候选与评估预算下，用真正进入提示的组件文本来建立配置之间的关系，能否比原始存储文本或不共享信息，更好地分配评估预算并选择一个配置？

长期方向仍是组件版本管理。E3执行了**实际提示表示的等预算离线回放**，没有实现在线部分提交系统；其结果和后续E4转向见下文。

### 13.2 通俗例子

设两本例题本A、B存了很多相同内容，因此从整本书看很像。
但面对当前一批题：

- A实际检索到的案例可能相关；
- B实际检索到的案例可能不同；
- 某些长案例还会因预算被删掉。

如果只看整本书，算法可能误以为A、B效果应当接近。
如果看这一批题真正翻到并读完的页，配置之间的“相似”关系可能不同。

**这只是解释新假设的比喻，不是已经观察到的因果结论。**
实际提示表示也可能同样预测不好，E3就是要检验这一点。

### 13.3 使用已有记忆记录，检验表示方式的价值

研究对象是 ExpeL 已保存的规则、经历及其实际检索／打包结果。算法依照这些组件的表示共享效果信息，主动分配有限评估预算，再在另一批开发题上复核候选。

字符特征、核方法、GP、探索和复核都是现成工具。
候选增量在于：**“存储表示”与“实际使用表示”的差别，是否对选择真正有价值。**
本阶段还不足以宣称这个差别构成已验证的新方法贡献。

### 13.4 配置选择算法的过程

1. 给每种配置构造规则和经历的文本特征。
2. 先查看每个候选少量已存回答，建立初步表现估计。
3. 根据估计的不确定性与下一批评估的token成本，决定先看哪一个候选的下一批题。
4. 定期看一下没有被模型优先推荐的候选，避免只追着自己的判断走。
5. 搜索结束后，选两个非空记忆候选，加上ZZ，在另一批dev题上复核。
6. 最终选定一个配置，再读取test结果评价。

GP（高斯过程）在这里是一个小型统计模型：根据已观察分数和配置相似度，估计其他配置的表现与不确定性。
它不训练Qwen权重，也不调用新的大模型。
其预测标准差描述工作模型内部的不确定性，不能直接作为收益保障。

例如，算法已经查看了OO和ON的一些成绩，发现两者实际提示相似，就可能把这一相似关系用于估计尚未充分评估的配置。但相似文本未必有相似效果；如果这种信息共享反而误导选择，不共享信息的对照应当表现得更好。E3因此不是预设复杂算法优越，而是测量共享信息是否值得。

文本表示采用字符三元组：将文本按连续三个字符切片并统计频数，再比较频数向量。例如“统一单位”会得到“统一单”和“一单位”两个片段。它计算简便，能捕捉文字重合，但不同措辞的同义规则可能被判断为不相似，因此仍需与其他方法作实测比较。

## 14．E3 具体怎么比较？为什么可以不花新的生成成本？

### 14.1 六个方法

| 方法 | 看到的表示／分配方式 | 想排除的解释 |
|---|---|---|
| rendered，主候选 | 检索和packing后的实际规则／案例文本 | 实际使用表示是否有价值 |
| unpacked | 检索后、packing前的文本 | 改善是否来自预算删减后的内容差异 |
| stored | 原始规则和整个经历池 | 只看存储内容是否已经足够 |
| additive | 实际表示，但不共享乘积交互部分 | 是否需要组件间的交互表示 |
| independent | 候选之间不共享效果信息 | 直接逐个评估是否已足够 |
| uniform | 按已看题数均匀分配 | 主动分配是否优于简单轮转 |

它们统一七个候选、数据顺序、预算和最终复核过程，主要改变表示或分配机制。
这些方法用于对照和消融分析，即一次改变一个设计因素，观察它对选择结果的影响；它们不是HbBoPs或SkillSmith的完整复现。

### 14.2 怎么“回放”？

可以把完整逐题结果想成一张已经做完、但盖住分数的大表：

```text
题目 × 七个配置 × 两次独立回答 → 已保存的对错和token用量
```

算法想评估“某配置在下一道题的表现”时，程序揭开相应旧结果，并按照原请求的输入tokens＋2048输出预留扣除虚拟预算。
算法没有权利直接看所有分数，预算不足就不能继续揭开。

举例来说，一次旧请求的输入为3000 tokens，协议预留输出2048 tokens，揭开这条结果就扣除5048个虚拟tokens。即使旧回答实际只输出了100 tokens，也不能因此多看其他题。各方法按同一预留规则付出评估成本，防止把短回答带来的差异混入选择算法的比较。这里的3000和100是说明性数字。

因此：

- 实际新增LLM调用为0；
- 每种算法自己的“假如重新评估要花多少tokens”仍逐条记录；
- 之前生成这张表的约739万tokens不会被隐去；
- 不能补造旧实验没有运行过的配置结果。

### 14.3 E3怎样分配旧数据？

| 阶段 | 数据 | 用途 |
|---|---|---|
| 搜索S | 原dev前40题 | 构造表示、主动评估候选 |
| 复核V | 原dev后24题 | 对两个候选＋ZZ作共同题目复核，按预算读取最长前缀，至少8题 |
| 测量T | 原test94题 | 配置冻结后读分数，作回顾性比较 |

这里的S指搜索数据阶段，E2中的S则指组件选择器，二者含义不同。

搜索预算为524,288 tokens，复核预算为393,216 tokens，总上限917,504 tokens／方法／读取顺序。
虚拟预算按预留tokens计，不能根据回答较短就给某个方法额外看题。

### 14.4 为什么做16种读取顺序？

算法先看到哪些题，可能影响后面的分配和选择。
因此固定16种seed顺序，对所有方法使用相同顺序，观察是否只靠碰到某几道题获胜。

**16种读取顺序复用同一批答案，只用于观察选择对题目顺序的敏感性。** 它们不提供16份独立实验样本，因此不据此计算独立样本的显著性检验。

### 14.5 什么时候值得继续？

协议先固定一个实用筛查条件：

- rendered相对stored、independent、uniform的平均test准确率差都至少为2个百分点；
- 同时至少8/16次选择非ZZ配置。

达到则记为 `WORTH_INDEPENDENT_TEST`：值得继续设计新数据实验。
达不到则记为 `NO_INCREMENTAL_SIGNAL_ON_THIS_TABLE`：这张旧表上没有足够增量信号。
任何完整性或预算失败则停止，不能当成零分继续。

**这个2pp条件不是统计显著性门槛，不证明方法提升2pp。**
所有旧题结果都已经在项目中被看过，因此即使筛查达到条件，也只能决定是否值得做独立确认。

### 14.6 这个实验有哪些明确限制？

1. 只用已有七个配置，不能证明多版本大规模搜索有效。
2. 不新建历史，不能证明跨构建顺序或任务泛化。
3. 最终始终选择一个固定臂；它在这张表上不可能超过“事后知道哪个固定臂最高”的理想上限。本轮上限对应ON的57.45%，并非实际可提前获得的选择信息。
4. 如果普通方法已经经常选到ON，复杂表示未必带来任何额外价值。
5. 字符三元组是轻量文本相似度表示，不是对语义相容性的证明。
6. 即使比当前控制更好，也未完成与完整HbBoPs等强方法的正式比较。

## 15．E3真实结果与转向依据

### 15.1 没有达到预设的增量条件

每种方法运行16种预定读取顺序。以下准确率是16次选定配置在原94题test上的准确率平均；每个配置仍是每题两次独立回答，不是新增了16份测试集。

| 方法 | 平均测试准确率 |
|---|---:|
| 实际提示表示，rendered | 50.83% |
| 检索后、打包前，unpacked | 50.83% |
| 原始存储表示，stored | 51.00% |
| 只加性，additive | 50.66% |
| 不共享信息，independent | 50.76% |
| 均匀分配，uniform | 50.30% |

主方法相对stored、independent、uniform分别为−0.166、+0.066、+0.532个百分点，均未达到+2个百分点。主方法11/16次选择非空记忆，满足另一项条件；失败原因是准确率增量不足。终态为 **NO_INCREMENTAL_SIGNAL_ON_THIS_TABLE**。

六方法全部96次最终选择中，没有一次选中ON。ON在搜索40题上只有41.25%，而OO为57.50%；开发结果并没有支持测试上分数最高的ON。表示共享也未补足这一差距。全部方法平均分均低于固定无记忆ZZ的52.66%，进一步提醒我们保留简单基准。

### 15.2 为什么需要研究“变化”，而不只预测“得分”？

逐题诊断中，将test的94题×7个配置共658个单元，按两次重复计算得分相关性，约为0.596；各次重复分别扣除每道题七配置的平均分后，相关性降到约0.112。

这意味着原始得分中有较强的共同题目难度成分，但不能将它全部解释为可迁移的记忆效应。上述中心化诊断使用同表数据，只提供描述性线索，也不是潜在效应相关性的无偏估计。

此外，题11985的OO与ON完整输入token IDs相同，却出现一个条件两次全对、另一个条件两次全错。观测到的配置差异可能包含显著随机波动，不能把一次答对、一次答错当成稳定的更新影响。

因此，继续把配置相似度模型做复杂，未必能解决根本问题。E4先检查：更新引起的题间变化是否足够清晰，能否被一个便宜且固定的预测器利用。

## 16．E4：自然更新的可测性与廉价预测诊断

### 16.1 要解决的实际问题

记忆持续更新时，每次都对所有测试题重复运行新旧版本，代价很高。长期目标是：根据题目与更新前后的记忆先预测影响，再抽少量题真正运行，用实际结果纠正预测偏差，估计整体收益。

例如，旧记忆在某题上的答对概率为80%，新记忆为60%，我们关心的变化是−20个百分点，而不是仅仅预测“新版本有60%的概率答对”。这些概率是说明性假设，并非单题两次回答就能准确得出的数值。

这里必须依次验证两个前提：

1. **可测性：** 多次回答后，能否区分真实更新差异与随机波动？
2. **预测可用性：** 不看评价答案时，预测能否减少题间剩余误差？

只有这两个前提得到支持，才值得进一步比较：相同总成本下，预测辅助评估能否比直接随机抽题更准确。

### 16.2 为什么采用自然更新、两条新路径？

E2的旧新快照相隔388道构建题，不能代表一次日常更新。E4从两个空记忆根开始，各在预定构建窗口内取首个符合文本与完整性条件的自然更新。

父状态固定在触发题评分后、进入记忆更新之前；子状态固定在经历加入、规则处理与整个更新完整提交之后。规则、成功经历池、检索和实际打包共同变化，不把它解释成某一条规则的单独作用。

每条路径最多64道构建题，每8次成功至多触发一次规则总结；只在第2至第8个成功批次中寻找首个合格变化。按文本和状态完整性选步骤，不按评价成绩挑更新。没有合格步骤或完整输入超长，就报告资格失败，不追加更有利的路径。

### 16.3 数据与重复怎样安排？

| 材料 | 固定安排 | 证据角色 |
|---|---|---|
| 旧开发材料 | E2的158题NN−OO，两端各2次，共632份旧回答 | 拟合固定探针；旧test明确改作开发 |
| 新构建材料 | 两条从空状态开始、构建题族互斥的路径，各至多64题 | 得到两个真实自然更新 |
| 评价池 | 固定64题，每题代表一个解题模板族 | 与新构建、旧开发及已用源材料隔离 |
| 新审计回答 | 各路径先锁定全64题预测，再独立随机抽32题，每端4次 | 共512份主审计回答 |
| 同输入控制 | 每路径4个固定完整输入，各在审计前后回答4次 | 共64份额外控制回答 |

“模板族”是同一母题或同构解题步骤的换数、改名、近重复；只共享物理定律不算同族。64个合格模板族仍须逐项验收，不能把名义剩余题数当成已经完成隔离。

两条路径共享评价池，抽样可以重叠。每端4次预拆为两组各2次，用于考察解码波动；这些重复组不增加独立历史数。两条路径也不足以证明普遍迁移。

### 16.4 固定的廉价预测器是什么？

主方法只用一个标量：比较题面与实际进入提示的规则／经历之间的字符三元组相似度，再计算新旧变化。用旧158题的题级平均得分差拟合一条固定正则、斜率受限的直线，不训练编码器、不搜索特征、不调用大模型预测。

这样做是为了先用很小的自由度检查有没有可利用信号。它只捕捉文字重合，失败只能限制这组特征、拟合方式和旧到新的迁移流程，不能否定所有语义方法。

预定对照包括零预测、开发均值、未拟合原始差值、只看新版、显式文本增删、长度变化，以及同时拟合旧新绝对得分的端点模型。端点模型与主方法对齐差值函数范围和正则，避免把训练目标不同误写成新增关系信息。完整定义以[E4最终设计](reviews/e4_diagnostic_design/r6_final_candidate.md)为准。

### 16.5 什么结果才值得继续？

主量记为Γ，检查“更新影响的题间方差”减去“扣除预测后的题间残差方差”。Γ为正，表示预测对区分哪些题更受影响有帮助；它不是准确率提升的百分点。一次总体有害的更新也可能是可预测的。

各路径报告点估计、标准误、近似区间及保守区间，并单列随机解码噪声。两条路径的Γ点估计均为正、代入的评估方差改善均至少10%、两组解码的等路径平均Γ也均为正，且资格完整，才建议继续设计独立等成本确认。

10%是后续投入的筛查条件，不保证真实节约率或统计显著性。区间宽时仍写未决；只有次级方法好，不能临时把它换成主方法。

关键限制是：预测可以减少“随机抽了哪些题”造成的误差，却不能消除“同一道题多次回答仍会不同”造成的误差。因此，即使预测很好，也必须核算其成本会不会挤掉必要的真实回答。

### 16.6 成本与停止规则

| 新增用途 | 最大提交尝试数 |
|---|---:|
| 两条路径构建，各64次解题＋最多8次规则总结 | 144 |
| 主审计，2条路径×32题×2端×4次 | 512 |
| 审计前后同输入控制 | 64 |
| 接口探测 | 8 |
| 非构建重试储备 | 104 |
| **合计** | **832** |

每次输入最多5888 tokens，输出预留2048，合计预留包络为6,602,752 tokens，约660万。另设拟议的24 GPU小时、8人工小时、2 CPU小时硬帽，任一先到即停止。这些是新阶段上限，尚不是已发生消耗或完成时间预测。

构建不重试；其他逻辑请求最多一次额外尝试。可能已发送的失败请求同样计费，余量不用来补根、换题或追显著。旧632份开发回答及更早构建成本另账，不能写成冷启动免费。

### 16.7 与已有研究的关系

| 近邻 | 本阶段借鉴 | 不能据此声称什么 |
|---|---|---|
| GBV-PD | 把更新方向与原有难度分开，核算预测成本 | 文本更新不继承参数梯度的近似保证；增量预测本身已有 |
| FAQ、PPI／PPI++ | 全池预测＋随机测量＋残差校正 | 这套统计思想不是本项目的新算法 |
| CheckList | 用解题模板族组织测试与隔离 | 它不是现成的记忆更新方向预测器 |
| tinyBenchmarks、PACE | 区分参考数据、测量预算和推断条件 | 不能直接移用其小样本精度或可靠性保证 |

本阶段希望获得的是自然更新下的可测性、廉价预测价值及失效边界证据。若信号太弱或成本不划算，可以结束该方向；当前尚未建立新算法或可投稿贡献。
