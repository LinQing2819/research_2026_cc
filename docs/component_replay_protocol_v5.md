# E2 V5：数据复核修订与生成前可行性检查

2026-10-24，V5。RC1 已完成本轮三轮评审，见[决定](reviews/e2_protocol_revision/decision.md)；
最终版只更新评审/实现状态，不改变获批的科研合同。RC1 原文 hash 记录在决定中。
基础合同：[V4](component_replay_protocol.md)，保留原文和旧运行，不回写历史协议。
V5 只替换下列明确条款；V4 其余冻结设计、推断范围和错误率控制继续适用。
软件版本为 `0.2.0`，软件版本与科研协议版本分别记录。

## 研究问题与本轮放行范围

A：ExpeL 的规则/成功经历双组件记忆。
B：旧/新组件的固定版本交叉及组件选择。

主问题仍是预先指定的 ON 是否优于 OO、NN、ZE。
完整回退、简单组件混搭或因子分析本身不是已经证明的新贡献。
原 E0 已查看过这些题的结果，本轮始终是单历史、固定题集的 discovery，
不宣称跨历史/新题泛化、通用选择器、在线回退或 3pp 的确认性证据。
有效结论可能是“仅经历已足够”，或“现有预算无法分辨”；不得据此换主对照追显著。

本次改动依据公共题干、选项及运行前资格检查，未获取新 E2 模型回答。
服务器零生成的交接声明须由升级后的只读账本检查核实，不能只凭聊天作为运行依据。

## 数据证据与适用范围

已在公开 MMLU-Pro Engineering 数据上独立核对以下候选：

| prefix ↔ test | 判定及依据 | V5 处理 |
|---|---|---|
| 11528 ↔ 12215 | 同题；1000 Mc/sec=1 GHz，同一铜板吸收功率问题，电场与条件相同 | 排除 test 12215 |
| 11568 ↔ 11872 | 非同题；1/[s(s²+1)] 与 1/(s−1)² 是不同的拉普拉斯表达式 | 保留 test 11872 |
| 11804 ↔ 11932 | 同题；directivity=50、波长4m、求最大有效孔径，选项发生变化 | 排除 test 11932 |

复核材料只使用公共题干/选项，没有读取新 E2 回答或用旧题正确率决定排除。
`configs/e2_duplicate_review.json` 存储有版本的复核记录，绑定：

- 有序完整公共题目投影 hash（qid、题干、选项）及完整原始候选审计 hash；
- 每一候选的两端阶段/qid 和两端公共内容 hash；
- 每一对的 duplicate/distinct 判定、依据、复核日期和证据来源；
- 只允许当前三个 prefix↔test 候选，候选不可缺项、多项、重复或未决。

只有上述全部绑定与服务器重新计算的证据一致，判定才能生效。
数据、文本、候选或复核文件不匹配时停止，不能按 qid 无条件跳过。
字符相似度筛查不是语义去重的完备证明；三个候选不代表全库只有这些重复。

保留旧 `duplicate_audit.json`，其 `qualified=false` 不被篡改。
新增数据资格产物记录原始候选、复核摘要和各阶段排除表。
其合格只表示符合 V5 的操作性数据审计，不表示效应、显存或 tokenizer 已验收。

## 固定题集及预算

保持 Engineering 的源顺序、20%/60% 快照、seed=20261020 的原 dev64/test96 列表。
只对两个确认重复的评估端题目作七臂共同排除，不补位，不修改历史案例/规则，
不调整 dev，不重建 E0，不从备用题或另一随机划分选取替代题。
其他类型的跨边界冲突不自动套用此例外，仍需重新审查。

重复排除后 test 至多94题，后续上下文排除继续按 V4 对七臂共同执行。
同时保存原始96、重复排除2、上下文排除数及最终 n，所有臂使用同一个分母。
原始划分用于溯源；检索、打包和实际请求只为数据合格题生成。

无长度排除时正式计划为 `(64+94)*7*2=2212` 个逻辑请求，包含 smoke。
V4 的预算上限2240、探测2、全局重试44及总上限2286保持；
少做的28次不构成追加题目/重复的额度。请求集合由封存 manifest 决定。

## 在生成前排除无效对照

继续检查旧/新规则和经历是否同题共同发生实际提示变化。
额外对固定合格 test 的三个必要对照逐一比较完整输入 token IDs：

- C1：ON 与 OO；
- C2：ON 与 NN；
- C3：ON 与 ZE。

记录每个对照实际不同的题数与比例。任一对照在全部合格 test 上完全相同，
则标记 `DEGENERATE_MAIN_CONTROL` 并停止生成，先报告原因。
例如旧规则整个块被预算删空时，ON 可以与 ZE 完全相同；
旧/新规则仍可能不同，因此原“两个组件共同变化”检查不足以排除此情况。

这一检查不查看回答、不删改单个 test 题，不改变主检验或挑选更有利的快照。
相同输入不意味着两个独立随机回答逐字相同；停止依据是无可识别的预定输入干预。
部分题提示相同仍保留这些题，按原两次独立生成与固定样本统计执行。

## 统计解释不变

仍报告 C1、C2、C3、I、D_F、D_ON 六个同时至少95%覆盖的固定样本区间，
零系数差值精确为零，主 GO/NO_GO/INCONCLUSIVE 门槛不变，delta=0.03。
仅对实际合格固定题集的新解码均值作条件推断；要求后端稳定、请求条件独立、
评分固定。排除规则在新生成之前冻结，不能按新旧正确率选择题目。

| n | 普通差值半宽 | 单项下界超过3pp所需观测差值 |
|---:|---:|---:|
| 96 | 16.8953pp | >19.8953pp |
| 94 | 17.0741pp | >20.0741pp |

减少两题只增加约0.179pp半宽；低功效来自原设计，并未被此次修订解决。
这是大效应/可行性预实验。若目标是可靠确认3–6pp改进，应另行完成
按语义题组隔离、多历史、多任务和充分功效的确认设计，再开始那一阶段。
不能把当前“区间很宽”解释成方法无效，也不能把点估计为正解释成方法已成立。

## 工程实施合同

1. 新增不加载模型、不请求服务的 `audit-data`；验证数据、源日志、上述复核绑定，
   只读现有账本并报告阶段/次数，输出单一可分享证据路径。
2. `prepare` 在大模型文件 hash、embedding 和打包之前完成同一数据审计；
   固定数据排除与复核文件进入 manifest/fingerprint。改复核文件后不能复用旧结果。
3. 保留账本 `runs/.e2-ledgers/component-v4.sqlite` 作为同一历史实验的预算槽，
   不通过改名建立新预算。V4→V5 迁移只允许零 attempts/零 results；
   当前 V5 的断点恢复继续验证同一身份。
4. HTTP 响应中途断开的 `IncompleteRead` 作为传输失败落盘计费，
   正式逻辑请求依原 payload/seed 及剩余重试预算恢复。探测仍不重试。
   完整但损坏的成功响应、400或上下文不匹配继续停止，不能包装成答错。
5. 保留强制 preflight→smoke→dev→封存 selection→test 的顺序；
   每条最终输入5888、输出2048、余量256，总窗口8192不变。
6. 提供软件版本、协议版本、Git提交及当前执行状态入口；
   README 首页说明最新科研问题、验证边界、当前服务器下一步，
   已知无 GitHub SSH 的服务器以 Git bundle 更新，不要求反复手写 Python。

## 第1轮：研究问题与数据修订评审（主代理）
