## 服务器操作

现有服务器目录 `/data/zlq/research_2026_cc`；不重新跑 E0，也不修改官方子模块。
先更新本仓库并安装轻量包装。客户端使用已有 `.venv-client`，vLLM 使用已有 `.venv`：

```bash
cd /data/zlq/research_2026_cc
git pull --ff-only
.venv-client/bin/pip install --upgrade "transformers==4.51.3" "tokenizers==0.21.4"
.venv-client/bin/python -m pip install -e .
.venv-client/bin/python scripts/e2/component_replay.py prepare
```

E2 客户端与 vLLM 0.8.5 环境必须使用相同的
`transformers==4.51.3`、`tokenizers==0.21.4`。更新后先检查：

```bash
.venv-client/bin/python -c "import transformers,tokenizers; print(transformers.__version__, tokenizers.__version__)"
.venv-vllm/bin/python -c "import transformers,tokenizers; print(transformers.__version__, tokenizers.__version__)"
```

两行都应输出 `4.51.3 0.21.4`；否则不要继续。preflight 仍会比较实际完整
token IDs，版本相同不是替代该检查。

`prepare` 不请求生成服务。它会验证完整 Engineering 公共数据与 E0
ExpeL-Online-ST rep0 memory JSONL 的 qid、顺序、题干及选项，复制到 60% 的原始前缀，
核对规则链和成功池，用 CPU embedding 冻结检索，检查跨边界近重复，
为 dev/test 的全部公开题目预计算七臂 token IDs 和资格表。
969 题时，旧/新状态分别是完成 193/581 题之后。
随后固定 dev64/test96；任何长度排除都不补题。

默认资源位置见 [配置](../configs/e2_component.yaml)。如本机路径不同，只改资源路径。
不要改论文参数；配置文件不接受样本量、快照、温度或上下文参数。
模型必须已下载到 `models/Qwen3-8B` 和 `models/Qwen3-Embedding-0.6B`。
模型内容 hash 需要读取权重文件，CPU embedding 也需要时间；这两步没有生成调用。

在原 vLLM 终端按 Ctrl-C 停止占用 GPU/8000 端口的 E0 服务，然后在该终端启动：

```bash
CUDA_VISIBLE_DEVICES=0 bash scripts/e2/serve_vllm.sh
```

若 vLLM 环境实际叫 `.venv-vllm`，显式指定解释器：

```bash
E2_PYTHON=.venv-vllm/bin/python CUDA_VISIBLE_DEVICES=0 bash scripts/e2/serve_vllm.sh
```

等待日志 `Application startup complete`。E2 使用 vLLM 0.8.5 的独立启动器，
单 GPU、TP=1、BF16、max_model_len=8192、max_num_seqs=1、eager。
它在原 API 上增加只读 `/e2/identity` 和 `/e2/chat_ids`，直接读取实际 engine 配置/tokenizer；
旧 E0 服务没有这两个接口，不能用它冒充通过 E2 preflight。

另一个终端：

```bash
cd /data/zlq/research_2026_cc
.venv-client/bin/python scripts/e2/component_replay.py preflight
.venv-client/bin/python scripts/e2/component_replay.py smoke
```

preflight 比较客户端、实际 engine 的完整 non-thinking template IDs，
并经根路径 `/tokenize` 验证。最多两次生成探测：短 sentinel 和接近 5888 输入的 sentinel，
都保留正式 2048 输出额度。模型、tokenizer、服务上限或 usage 不一致就停止。
smoke 是正式 dev 前四个合格 qid，共最多 56 个逻辑请求，
输出技术验收摘要，写入正式结果位置，不另起一个可择优拷贝的 smoke 实验。
程序会强制检查这份 smoke 证据；没有完成 smoke 时，`dev` 和 `run`
都会在发送完整 dev 请求前拒绝执行。

两步均成功、无需修改实验实现时，继续同一协议：

```bash
.venv-client/bin/python scripts/e2/component_replay.py run
```

`run` 继续剩余 dev，封存选择，再生成 test 并分析。也可以分开执行：

```bash
.venv-client/bin/python scripts/e2/component_replay.py dev
.venv-client/bin/python scripts/e2/component_replay.py test
.venv-client/bin/python scripts/e2/component_replay.py analyze
```

不依赖 E0 H1 筛选或论文 baseline 的复现容差，不会再因为 E1 的 `selected: []`
去读取不存在的 E1 manifest。原 E0/E1 的已知问题仍见 [历史审查](review_2026-10-20.md)。

## 上下文和请求预算

| 项目 | 硬约束 |
|---|---:|
| 研究总上下文 | 8192 |
| 最终输入（含完整 chat template） | ≤5888 |
| 输出预留 | 2048 |
| 余量 | 256 |
| 规则块（含标题/编号） | ≤1024 |
| 经历块（含标题/Similarity/轨迹） | ≤3072 |
| 正式逻辑请求，含 smoke | ≤2240 |
| 生成探测 | ≤2 |
| 全局传输重试储备 | ≤44 |
| 全部已提交/可能已提交尝试 | ≤2286 |

规则/经历分别只从尾部删除完整条目，不交换额度，不截断当前题或选项。
任何一臂超过 5888，该题七臂预先共同排除；报告覆盖率。
`/v1/completions` 发送已计数的整数 IDs，显式关闭额外 special tokens；
每条响应检查 `usage.prompt_tokens`，没有超长后临时截断重发的路径。

正常 `finish_reason=length` 按固定官方字母提取器评分并报告次数。
400、token 不一致、成功响应 schema 损坏均停止。超时、429、5xx 最多两次传输重试，
保持原 payload 和 seed，同时消耗全局 44 次储备。探测不重试，重启不能获得第三次探测。

## 产物与恢复

启动时打印具体产物目录：`runs/e2_component/<输入身份 hash>/`。
`runs/e2_component/active.json` 只提供目录索引。

| 产物 | 用途 |
|---|---|
| `manifest.json` | 冻结源、代码、协议、模型、库版本、split、资格、请求 seed/顺序、文件 hash |
| `prefix_raw.json` / `old_prefix_raw.json` | 原始前缀文本，不含未来 E0 回答 |
| `scoring_gold.json` | 单独评分数据，不进入 query、记忆或 selector |
| `embeddings.json` / `questions/` | 可核验的向量、排名、分块、全文、最终 token IDs 和跨度 |
| `duplicate_audit.json` / `intervention.json` | 去重候选、实际干预变化；不合格时明确停止 |
| `preflight.json` / `smoke.json` | 服务、token 和技术验收证据 |
| `selection.json` | 完整 dev 摘要、两个 selector 的授权清单/成本/选择、封存 hash |
| `analysis.json` / `report.md` | 六对比、判定、方差、覆盖率、成本、packing 和确认样本量情景 |

独立持久账本为 **`runs/.e2-ledgers/component-v4.sqlite`** 及 SQLite 的 `-wal`/`-shm` 文件。
账本保存每次请求、原始响应、接纳结果与封存绑定，进程锁阻止两个客户端同时生成。
预算在发送前事务落盘；不明是否执行的请求也计费。
已保存原始响应可恢复评分，无需再调用模型；已完成行从不重发。
不要删除或改名账本来恢复预算，备份时连同账本文件和产物目录一起备份。

中断后原命令重跑即可续缺失行。相同身份重复 prepare/preflight/smoke/run 都复核并复用。
任意一次提交后若代码、模型、源文件、模板、packing 或评分器发生变化，
程序拒绝续用，也不自动创建一轮新预算；必须按 V4 将旧运行作废并重新审查修订。
首次提交之前的离线 prepare 错误可以修复，原离线产物留档，不混入新身份。

## 如何读结果

主机制 GO 要求 ON−OO、ON−NN、ON−ZE 三个同时区间下界都严格大于 0.03。
其中任一上界严格小于 0.03 为主机制 NO_GO；其他情况为 INCONCLUSIVE。
选择器差值 D_F/D_ON 独立报告，不代替机制通过。S=F 或 S=ON 时对应差值精确为零。
交互 I 仅是正确率加性尺度交互。

主区间是六对比同时至少 95% 覆盖的固定样本 Hoeffding 区间；
推断只针对该固定合格题集的新解码均值，并以条件独立、后端稳定、固定评分为假设。
96 题时普通差值半宽约 0.169，无法可靠分辨三个百分点。
报告中的观察方差正态情景仅用于下一次确认设计，不能替换主区间。
不确定不授权本轮追加样本或重复追显著。
