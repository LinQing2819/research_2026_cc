## 上下文和请求预算

| 项目 | 硬约束 |
|---|---:|
| 研究总上下文 | 8192 |
| 最终输入（含完整 chat template） | ≤5888 |
| 输出预留 | 2048 |
| 余量 | 256 |
| 规则块（含标题/编号） | ≤1024 |
| 经历块（含标题/Similarity/轨迹） | ≤3072 |
| 无长度排除时正式逻辑请求，含 smoke | 2212（名义上限2240） |
| 生成探测 | ≤2 |
| 全局传输重试储备 | ≤44 |
| 全部已提交/可能已提交尝试 | ≤2286 |

规则/经历分别只从尾部删除完整条目，不交换额度，不截断当前题或选项。
任何一臂超过 5888，该题七臂预先共同排除；报告覆盖率。
`/v1/completions` 发送已计数的整数 IDs，显式关闭额外 special tokens；
每条响应检查 `usage.prompt_tokens`，没有超长后临时截断重发的路径。

正常 `finish_reason=length` 按固定官方字母提取器评分并报告次数。
400、token 不一致、完整成功响应的 UTF-8/JSON/schema 损坏均停止。
超时、传输截断、429、5xx 最多两次传输重试，
保持原 payload 和 seed，同时消耗全局 44 次储备。探测不重试，重启不能获得第三次探测。
已知400即使响应体截断也不重试；截断的部分字节无损保存，不参与评分。
少做的28次不构成追加额度；实际请求必须属于封存 schedule。

## 产物与恢复

启动时打印具体产物目录：`runs/e2_component/<输入身份 hash>/`。
`runs/e2_component/active.json` 只提供目录索引。

| 产物 | 用途 |
|---|---|
| `manifest.json` | 冻结源、代码、协议、模型、库版本、split、资格、请求 seed/顺序、文件 hash |
| `splits.json` / `evaluation_splits.json` | 原始64/96及共同重复排除后的64/94，不补位 |
| `data_qualification.json` | 稳定数据资格、完整复核记录、排除、源及数据 hash |
| `prefix_raw.json` / `old_prefix_raw.json` | 原始前缀文本，不含未来 E0 回答 |
| `scoring_gold.json` | 单独评分数据，不进入 query、记忆或 selector |
| `embeddings.json` / `questions/` | 可核验的向量、排名、分块、全文、最终 token IDs 和跨度 |
| `duplicate_audit.json` / `intervention.json` | 去重候选、实际干预变化；不合格时明确停止 |
| `preflight.json` / `smoke.json` | 服务、token 和技术验收证据 |
| `selection.json` | 完整 dev 摘要、两个 selector 的授权清单/成本/选择、封存 hash |
| `analysis.json` / `report.md` | 六对比、判定、方差、覆盖率、成本、packing 和确认样本量情景 |

独立持久账本为 **`runs/.e2-ledgers/component-v4.sqlite`** 及 SQLite 的 `-wal`/`-shm` 文件。
账本保存每次请求、原始响应、接纳结果与封存绑定，进程锁阻止两个客户端同时生成。
预算在发送前事务落盘；不明是否执行的请求也计费。
已保存原始响应可恢复评分，无需再调用模型；已完成行从不重发。
不要删除或改名账本来恢复预算，备份时连同账本文件和产物目录一起备份。

查看当前阶段和次数：

```bash
.venv-client/bin/python scripts/e2/component_replay.py status
```

`status` 只读账本并报告产物是否存在，不代替执行入口的 checksum 验证。
中断后原命令重跑即可续缺失行。相同身份重复 prepare/preflight/smoke/run 都复核并复用。
任意一次提交后若代码、模型、源文件、模板、packing 或评分器发生变化，
程序拒绝续用，也不自动创建一轮新预算；必须按 V4 将旧运行作废并重新审查修订。
首次提交之前的离线 prepare 错误可以修复，原离线产物留档，不混入新身份。

## 如何读结果

主机制 GO 要求 ON−OO、ON−NN、ON−ZE 三个同时区间下界都严格大于 0.03。
其中任一上界严格小于 0.03 为主机制 NO_GO；其他情况为 INCONCLUSIVE。
选择器差值 D_F/D_ON 独立报告，不代替机制通过。S=F 或 S=ON 时对应差值精确为零。
交互 I 仅是正确率加性尺度交互。

主区间是六对比同时至少 95% 覆盖的固定样本 Hoeffding 区间；
推断只针对该固定合格题集的新解码均值，并以条件独立、后端稳定、固定评分为假设。
94 题时普通差值半宽约 0.1707，单项观测差值须大于20.07pp才能使下界超过3pp；
本轮无法可靠分辨三个百分点。
报告中的观察方差正态情景仅用于下一次确认设计，不能替换主区间。
不确定不授权本轮追加样本或重复追显著。
