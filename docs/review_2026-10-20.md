### 已观察到的最小复现

1. 真正调用 Runner，先处理 2/4 题后恢复：
   - 恢复前 eval IDs：`[1,2]`；
   - 恢复后：runner total=4、memory records=4、eval IDs=`[3,4]`。
2. 给 HumanEval 的真实 build_memory_record 输入 score=1：
   - feedback=`success: check() passed`；
   - AWM 在线成功计数=0，ExpeL 在线经验池大小=0；
   - 同一 ExpeL 日志恢复后，经验池大小=1。
3. ExpeL 在线轨迹=`answer`，经过当前 seed 清理再恢复后=`<trajectory>answer</trajectory>`。
   无标签输出不一定触发差异；不能说 ExpeL 整个规则库丢失。
4. ExpeL 当前题前规则为 `(empty)`，用当前成功答案更新规则后，
   export_eval_context 记录的是新规则；读取器将其作为同题生成前特征。
5. CS 数值反例：`d = [+1]*300 + [-1]*700`，ε=1。
   - 普通平均值=-0.4；
   - 最终加权中心=0.347175；
   - 最终区间≈`[0.279301,0.415049]`。
   这是目标量错配的证明，不是对加权置信序列原语有效性的否定；
   也不把退化前出现正向信号本身视为误报。
6. 独立验证者构造真实收益为负的类别分布，balanced 概率仍令 gate 开启记忆，
   低于始终无记忆的准确率。已记录的 gate 准确率本身没有被伪造；
   问题在于它评估了一个先验处理错误的决策规则。

## 对现有结果的重新解释

### E0 H1

“6/18”是按当前实现得到的探索性信号，不是经过完整审计的最终事实。
用户提供的 DC-RS × MATH500 日志 n=438，需确认是否为恢复后的后缀；
HumanEval 的 AWM / ExpeL 没有正常学习成功经验。
APIBench 的 Baseline 为 75.30%，论文参考 64.5%，差 10.80 点，
但单凭更高不能认定本地 Baseline 错误，也不能认定两遍输出重复。

±3 点只有在样本集合、提示、解码、模型、判分和运行协议一致时才有复现诊断意义。
固定基准的 `configs/holdout.py:47–54` 记录 MMLU 构建序列约 873/1170 题，
而当前 E0 使用 969/1299 题；这是须核对论文表格对应口径的线索，
尚不能只凭 holdout 配置断言 Table 3 使用了哪一组分母。
不能为了过关重跑直到数值接近论文，也不能把所有偏差自动归因于 Baseline bug。

若完整审计和独立复跑确认本地比较设置一致、性能差异稳定，可以报告本地结果和复现偏差；
修改 E1 资格规则必须记录为看到数据后的协议修订，不再称其为原预注册决策。

超额伤害也不是“真正被害题目比例”的直接估计。若两次 Baseline 和记忆输出
在给定题目及历史下独立，设正确概率为 p0、p1，其期望为
`E[p0*(p0-p1)]`。它是基线容易做对的题上加权的负向效应，
不能识别每道题稳定的个体因果伤害。在线共享记忆还使逐题 iid bootstrap 的
解释受到限制；确认实验应加入独立任务顺序及记忆构建轨迹，而非只补答题重复。

### E0 H2

当前 AUC≈0.56 未达门槛，可以停止在这组特征上大量调参；
但泄漏和方法退化尚未纠正，不能发表为强结论“伤害不可预测”。
纠正后只能表述为“这些生成前特征及预测器没有提供足够信号”，
不能把逻辑回归失败提升为不可预测性定理。

### E0 H3

当前 ±0.126 是现有加权统计量的宽度，不能直接解释成
“对普通累计退化只能抓 13 个点”的检出限。
目标纠正后应重新估计检测概率、延迟、假警报率和成本；
即使抽样完全随机，仍需满足策略在探测前确定、反馈不泄漏到部署策略、
多版本选择和监测重启被纳入误差控制等条件。

## 科研方向评审

### 现有 E1a 的合理用途与不足

冻结旧版本、选择集选版本、测试集评估，是合理的可恢复性试验。
但是它只是方法可行性前提，不能独立作为新方法贡献。

当前入口要求 H1≥5%并通过复现，是研究问题错位：
新版可以仍然优于无记忆，却明显劣于旧版；这样的回退场景不必通过 H1。
资格规则应检查实现与数据有效性，伤害率可做分层变量，
候选任务/方法宜预先固定或在独立 discovery 集上选定。

20%/40%/60% 快照配后续 40% 题能避免记忆构建泄漏，
但它不包含 E0 最后 40% 更新，不能检验这些晚期更新是否摧毁记忆。
若要研究“最终版本退化”，应使用与完整构建流互斥的外部公开留出集，
比较早期、中期、最终版本。MATH500 与 MATH/train 的不重合留出方案
在官方 holdout 配置中已有先例；数据来源、去重和选择/测试分离仍需实际核验。
换顺序可以检验顺序敏感性，但不能把 E0 已用于筛选的题变成全新的确认数据。

HumanEval 的约 33 题测试集、APIBench 的约 183 题测试集，
对 3 点效应都可能检验能力不足。应先按配对差值方差估计样本量，
不能将不显著或一次 oracle 上限较低等同于不存在可恢复退化。
两次答题重复不能替代两条独立记忆构建轨迹。

### 创新边界

本次核查以下公开工作，不是完整的新颖性检索：

- [SeqMem-Eval](https://arxiv.org/html/2605.15384v1)：已经研究更新非单调、
  留出泛化、遗忘及有用记忆被后续更新破坏。再次展示旧版本胜过新版本身创新有限。
- [MemSkill](https://arxiv.org/html/2602.02474v1)：明确描述按稳定奖励回退到最佳 skill bank
  快照和早停；其回退对象与本项目不同，但“保存最佳版本后回退”不是新概念。
- [PACE](https://arxiv.org/abs/2606.08106v1)：已经使用配对 testing-by-betting
  e-process 对自进化候选作 anytime-valid 接受检验，提供每次决策的错误提交控制。
  因此“自进化 + 配对 + anytime-valid”这一组合不能直接作为创新声明。

可继续评估的主张是：
**在部署后持续变化的记忆与任务流中，以有限随机影子探测预算，控制跨时间、
跨版本的误回退，并减少发现退化前积累的实际损失。**

必须明确这与候选提交前验收的差别，并证明收益不是普通周期评估/滑窗即可达到。
“对任意自适应演化有效”可作为统计覆盖目标，但不能同时无条件保证任意短暂退化
都能低预算快速检出。检测延迟需要效应大小、持续时间等条件。

正式比较至少包括：始终无记忆、始终最新、固定周期配对评估回退、
滑窗退化检测、适配的 PACE 接受门控、oracle 上限。
总预算必须计算每个被探测题运行几个版本、各版本 token 和记忆更新成本；
K 个版本的全比较额外调用约为 ε(K−1)，不是 ε。
对公开方法的策略改编应明确标注，不把简化实现冒称原论文完整方法。

## 建议执行顺序

1. 修复反馈语义、状态恢复和日志恢复；加真实 Runner 的中断恢复、
   checkpoint 前后 prompt 一致性，以及生成前特征时序测试。
   保存兼容补丁版本与逐作业模型/解码/数据指纹。
2. 审计现有 E0：完整题目与顺序、resume 历史、Baseline 输出重复率及实际请求参数、
   与论文的样本集合和判分口径；可从原记录恢复的先恢复，无法恢复的才重跑。
   只重跑受影响轨迹，不默认把全部数据作废。
3. 在有限任务×方法上，使用独立后续数据验证旧版相对新版的配对优势，
   同时报无记忆；暂不把 H1 显著作为资格门槛。
   先对非破坏性检索方法验证恢复，再纳入状态更新更复杂的方法。
4. 确认可恢复差距后，定义部署期/版本期监测量与预算，
   完成非平稳模拟和误差控制，再跑真实闭环监测比较。
   优势不足时保留机制研究路线，不靠不断放宽阈值延续方向。
