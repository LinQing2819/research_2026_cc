# E4方案收敛：补充三轮评审与文献核验

2026-10-28。接续[前一组三轮讨论](E3之后的研究迭代_三轮讨论与文献对照.md)。
本轮新增研究设计、文献核验及旧表描述性复算；新增模型调用为0。

## 1．建议收敛到什么

建议将下一阶段收敛为 **E4-D1：自然更新的可测性与廉价预测诊断**。

核心问题是：两条预先指定的自然记忆更新，面对一个未进入本研究构建与拟合的固定题池，
其逐题准确率变化是否存在可重复结构；一个用旧数据拟合的简单词面探针，
能否利用其中一部分，值得继续投入独立确认？

这一阶段的产物应是有明确适用条件的测量结果。当前没有证据支持新的关系学习算法，
也没有证据支持已经节省评估成本。不再等待一个未定义的关系模型，
不默认增加GP、RL、来源绑定或全池LLM评分。

相较上一版，实际删去了第二任务、额外开发根、16题留出校准、全池语义预测和未具名关系网络。
保留同题旧新比较、独立解码重复、完整记忆状态、预定主方法以及失败后结束的规则。
研究问题更小，允许得出正向线索、局部阴性或未决，而不必把每轮评审都推向“方法通过”。

完整定义见[统一裁决稿](reviews/e4_diagnostic_design/r6_final_candidate.md)。

## 2．为什么需要继续缩小

E3六种配置选择方法复用同一已完成表，主方法平均测试准确率50.83%，
原始存储表示51.00%，未达到预设增量条件。E2仍为INCONCLUSIVE。
这些结果支持停止扩展当前选择器，不能推出一切记忆效应都不可学习。

上一轮已发现：共同题目难度的重复相关性，明显强于扣除题内平均后的配置增量；
相同输入也可能出现一次配置两次全对、另一次两次全错。
本轮进一步把“预测更新效果”与“测量随机回答”分开。

对N题有限池均匀抽n题、每题每版本r次回答，固定预测m后的标准残差校正估计量满足

\[
\operatorname{Var}(\widehat\mu_m)
=\frac{1-n/N}{n}S^2_{\tau-m}+\frac{\overline v}{nr}.
\]

第一项来自抽了哪些题，第二项来自同一道题重复生成仍会波动。
在独立、稳定解码等条件下，预测只能降低第一项；即使测遍题池，
有限次解码也没有给出期望准确率的精确真值。
因此，耗费大量调用做全池预测，可能挤掉真实测量，使总成本收益消失。

旧表test94题的描述性复算如下，全部对比属于同一已看历史：

| 对比 | 跨重复差值协方差 | 单次配对差的解码噪声估计 |
|---|---:|---:|
| NO−OO：规则变化，旧经历固定 | 约0 | 0.20213 |
| NN−ON：规则变化，新经历固定 | −0.01579 | 0.19681 |
| ON−OO：经历变化，旧规则固定 | 0.05102 | 0.18085 |
| NN−NO：经历变化，新规则固定 | 0.04278 | 0.21809 |
| NN−OO：完整记忆变化 | 0.03249 | 0.18617 |

协方差在独立、稳定重复假设下可估题间潜在效应方差，但两rep估计很不稳定；
负值保留，不能解释为负的真实方差或“已经证明没有效应”。
dev上的对应估计也已记录，不能只挑test的正对比设计下一次实验。
详见[推导与完整口径](reviews/e4_diagnostic_design/r4_noise_and_cost.md)。

以最后一行的点估计代入一个假设场景：每版本4rep、抽取一半题池，
完美预测可消除的总方差比例约25.9%。**这是不稳定的代入示例，既不是节约率，
也不是置信上界或未来功效保证。** 它说明预测开销必须与可省的测量一起核算。

## 3．本轮文献提供了哪些可用内容

本轮重点核验以下七篇原文的相关范围，未运行作者代码或独立复现论文实验。
逐篇读取范围、公式与限制见[文献记录](reviews/e4_diagnostic_design/r4_literature.md)
及[统计记录](reviews/e4_diagnostic_design/r4_statistics.md)。

| 文献 | 可以借用 | 对本方案的限制 |
|---|---|---|
| [GBV-PD](https://arxiv.org/html/2606.28037v2)，Cho、Shin、Ko | 将更新方向与原始难度分开；先检验逐题变化信号，再讨论优先测试；分列预计算成本 | 逐题增量预测已有。它使用参数梯度和参数变化，文本差不能继承其Taylor近似保证 |
| [FAQ](https://arxiv.org/html/2601.20251v3)，Wu、Nair、Candès | 预测器负责效率，抽样与残差校正负责估计目标；明确减少推理调用的成本对象 | 依赖历史模型在固定题库上的成绩。新模型适配不等于新题模板迁移；其有放回推断不能直接套给无放回随机解码差 |
| [PPI](https://arxiv.org/html/2301.09633v4)、[PPI++](https://arxiv.org/html/2311.01453v2)，Angelopoulos等 | 用少量真实测量校正全池预测；控制预测权重，保留纯测量基准 | 残差校正与控制变量已有，不能包装为新方法；渐近效率不保证小样本拟合必不劣 |
| [CheckList](https://aclanthology.org/2020.acl-main.442/)，Ribeiro等 | 能力与测试类型矩阵、模板族、合法不变/方向关系 | 不是现成的memory-diff有符号预测器。“diff＋CheckList评分”只能称本项目提示适配 |
| [PACE](https://arxiv.org/html/2606.08106v1) | 同题比较、候选与审计隔离、允许未决 | 条件胜率零假设不能由全池平均收益不正推出，不能借其结论保证任意选题或反馈复用 |
| [tinyBenchmarks](https://arxiv.org/html/2402.14992v2)，Polo等 | 区分参考成绩资源与待评对象的测量预算 | 已有大规模参考成绩与一条历史不同；100题经验结果不保证32题随机增量测量的精度 |

文献核验还带来两项具体修正。
线性编码两端后相减，可与共享线性端点头相减属于同一函数类；
若结果不同，需要先检查拟合目标、斜率约束和正则缩放，不能直接归因于关系信息。
此外，PACE原文中的部分保证依赖更强条件，不能只引用“配对”或“anytime-valid”名称。

目前保留下来的价值是限定自然更新下的测量与低成本可用性证据。
如果最终只有现成统计工具的适配且结果精度不足，不能改称“新评测框架”来补足贡献。

## 4．最终诊断如何进行

开发使用旧158题NN−OO的632份回答。它们已被分析，明确作为后续开发资源。
只新建两条从空状态开始的路径，每根最多64道构建题；
从预定成功batch窗口中取首个完整、非空规则发生文本变化的步骤，
不按准确率、规则错误或差分大小挑更新。

变化对象始终是完整记忆状态，包括规则、经历池、检索与实际packing。
保留一个64题池，每题代表一个事先隔离的解题模板族；
两个根共用题池，各自在预测锁定后独立抽32题，每版本4次回答。
允许知识概念重合，不能把所有共享物理定律的题都判作泄漏；
同母题换数、改名或同构解题步骤则须合并。

主预测器只有一个预定标量：题面与规则/经历的字符三元组相似度，在旧新端点之间作差；
用旧数据拟合一条有界斜率的岭直线，不训练编码器、不搜索特征。
零值、开发常数、原始标量、新版、直接文本编辑、长度变化和端点联合拟合作为对照。
端点联合头与主方法在共同差值坐标中对齐允许的预测范围和正则，避免制造虚假的关系优势。

主量检查题间残差方差是否下降。它不等于记忆更新提高了准确率：
总体收益为负的更新，也可能具有可预测的题间差异。
两组解码用来检查测量波动，共享同一批题，不算两次独立验证。
两根满足预定正向点估计及10%代入改善条件，只表示值得设计下一次独立等成本确认；
区间宽仍需写未决，不能声称真实改善至少10%。

同输入控制采用每个指定prompt早4次、晚4次生成。
早晚置换核对依赖明确的可交换性假设；随机人工标签只检查标签关联，不能检出共同时间漂移。
显著是核查信号，未显著不认证服务稳定。输入身份、模型/评分版本与时序记录仍不可少。

## 5．成本已经算清，运行资格尚未取得

| 新增用途 | 提交尝试上限 |
|---|---:|
| 两根构建：各64 solver＋最多8 curator | 144 |
| 两根32题、两版本、各4rep | 512 |
| 同输入早晚控制 | 64 |
| 接口探测及非构建重试 | 112 |
| **总计** | **832** |

112细分为最多8次登记探测和104次非构建重试。构建不重试；
其他逻辑请求最多一次额外尝试，所有可能已派发的请求都计费，不借余量补根或追显著。
保留2048输出上限，单请求输入上限5888，预留token包络为**6,602,752**。
另拟议24 GPU小时、8人工小时、2 CPU小时硬帽；这些是待验收的设计边界，未启动新生成。

真实风险包括：64题内可能没有合格自然更新；curator八条完整轨迹可能装不进上下文；
可能没有64个满足隔离条件的评价模板族；旧大跨度更新的拟合可能无法迁移到新单步更新。
这些都允许在固定预算内结束。超长不能临时剪轨迹或扩大窗口，失败不能换一条更有利的根。

本轮还纠正了资产判断：前稿提到的字符串反馈缺陷属于**HumanEval**；
APIBench仍缺当前可核验的数据/历史与评分口径资格，因而退出本轮，
不能写成“该API缺陷已修复”。
已有prefix哈希可用于日后恢复旧路径，原件未取回；
它不是新建根的必要前置，也不能替代真实新根。

尚需实际验收的材料是：模板族及构建清单、旧开发标签到实际输入的绑定、
模型和渲染身份、完整状态事件、请求账本与输入拒绝机制。
现有入口缺少部分状态与预算保证，直接运行旧E0/resume不满足该合同。

## 6．三轮评审记录与准入

R4、R5、R6是接续前一组三轮的新三轮，均按“审查—修订—再审”推进；
三轮各三个agent角色，共九份角色评议，属于内部多agent讨论，不是九名人类专家或实验复现。

| 轮次 | 主要收敛 |
|---|---|
| R4 | 定向核验核心文献；纠正API反馈缺陷归属；引入噪声与成本分解；退出未定义关系网络，选择CPU诊断 |
| R5 | 复用旧开发，仅新建两根；对齐端点拟合函数类和正则；补全条件推断、比例与早晚控制；保留2048输出 |
| R6 | 对同一最终稿核查统计、贡献边界及工程合同；裁决和文件身份记录在决定页 |

最终裁决及逐份评议索引见[三轮决定](reviews/e4_diagnostic_design/decision.md)。
R6三个角色均对限定设计给出PASS，没有必须继续修订项；实际运行资格和效果仍须靠资产与新数据获得。
下一步先落实具体清单和输入/账本合同；资格成立后，按同一设计实现和验收，
不需要再发明一套关系算法。当前未启动新采集。
