# 组件版本交叉实验：冻结机制预实验协议

2026-10-20，V4（依据 R2 修订，尚未获取任何新实验回答）。
此文件取代 research_v2_draft.md 的执行配置。
评审状态由 docs/reviews/ 下的逐轮记录给出；三轮完成前不编码。

## 研究问题与 A+B

**A：ExpeL 的规则和成功经历双组件记忆。B：因子干预与组件级版本选择。**

首轮只问：在相同分组件上下文限额下，旧/新规则与旧/新经历的组合，
是否能在后续题目上提供超出完整快照与纯经历控制的效用？
预定主组合为 ON（旧规则＋新经历）；不是在 test 上挑选最强混合臂。
将组件简单效应、加性尺度的交互、验证集选择的策略收益分开报告。

不声称这一轮证明旧能力恢复、新能力保留、跨任务泛化、在线回退有效、
任意时刻统计保证，或发明因子分析/版本混搭。潜在贡献是确定整库回退
是否过粗以及何时值得分组件恢复；该贡献仍可能被实验否决。

这是一次固定预算的机制 discovery，不以“pilot”替代正式证据。
如果只得到“抽象有害，扔掉规则更好”，其增量不足以支持方法论文。
如果固定 ON 已解释全部收益，不宣称 selector 有额外价值。

## 与最近邻的具体比较

| 已核验来源 | 干预/控制 | 与本实验的关系 |
|---|---|---|
| [SeqMem-Eval](https://arxiv.org/pdf/2605.15384v1)，摘要、§1–3 | 对完整记忆时间状态作在线/留出/回顾诊断 | 提供问题与统一任务接口；完整状态退化已知 |
| [Faulty Memories v2](https://arxiv.org/pdf/2605.12978v2)，§1–3 | 固定经历池、Static-All/Static-Group/Stream、episodic-only，正文明确角色分离 | 最接近；固定 ON 主机制必须超过匹配的 E新-only 控制 ZE |
| [作者项目页](https://dylanzsz.github.io/faulty-memory/)，2026-10-20 读取的 Experiment 1 | append-only visible / blind / add+delete / unrestricted rewrite；改变更新时可见历史和允许操作 | 已定位 conditioning/rewrite 并承认 retrieval crowding 混杂；本实验改在冻结答题阶段交叉两组件的历史版本，不重新归因其更新步骤 |
| [RoutePrism](https://arxiv.org/abs/2609.34160)，摘要 | 同源记录两种构建顺序；恢复被挤出的单条证据，与等长无支持替换等四条件比较 | 提醒必须保存 source/context/token；不能声称首次因果恢复证据 |
| [PACE](https://arxiv.org/abs/2606.08106)，摘要与 §4 | 候选与 incumbent 的配对接受测试 | 本实验无 sequential gate，不占用其创新；独立验证选择是普通基线 |
| [ChronoMem](https://arxiv.org/abs/2607.27773)，摘要 | 全库快照与自然语言指定回退 | 版本存储本身无创新 |
| [Scope Before You Persist](https://arxiv.org/abs/2609.29144)，摘要 | 固定 proposals/gate decisions，改变按任务族的 retrieval scope | 本轮不研究作用域，不声称首次局部记忆干预 |
| [SkillSmith](https://arxiv.org/abs/2606.01314)，公开方法摘要 | 预算内技能选择、delta debugging、冲突记录 | 本轮不做通用故障定位算法 |

## 唯一执行配置

- 模型：Qwen/Qwen3-8B，temperature=0.7，thinking=false，max_new_tokens=2048。
- 数据/方法：MMLU-Pro Engineering，ExpeL-Online-ST，历史 E0 rep0；
  不按 H1、baseline 复现差值或新结果筛选任务。
- 旧快照：floor(0.2 N) 个已完成题后的规则与经历；新快照：floor(0.6 N)。
- 只读取原始记忆日志至新快照边界，后续日志不给组件构造器。
  首先校验公共数据 ID/顺序与完整日志一致，再复制前缀为实验输入。
- 新边界之后的公开题目：按 seed=20261020 固定置换，前 64 为 dev，
  接着 96 为 test，其余不用。测试没有进入任一冻结前缀；
  但 E0 已分析过这些题，因此仍是 discovery，不是假装独立确认。
- 只有这一条历史构建轨迹。取消草案中的双顺序配置与 S/P 能力主张，
  不把答题随机种子当构建顺序。后续确认需另外创建未见评估题的构建轨迹。
- smoke：正式 dev 前 4 个合格 qid，七臂×两回答，共最多 56 次。
  它们就是正式 dev 行，参数在此前冻结；只生成一次，后续 run 从缺失行继续。
  不提前生成 test。若发现需修改设计/实现，该协议运行判无效并先修订重审，
  不择优拼接两种实现的结果；不得据 smoke 效果改快照或 packing。
- 每题每臂两个独立生成，取平均正确率；不用 pass@2、不挑最好回答。
  请求顺序按预设种子打散；独立 seed 由 qid/arm/rep 派生并保存。

## 七个固定干预臂

OO=(R旧,E旧)、ON=(R旧,E新)、NO=(R新,E旧)、NN=(R新,E新)；
ZE=(空规则,E新)、RZ=(R新,空经历)、ZZ=(空规则,空经历)。
七臂均使用 ExpeL 的同一个 solver scaffold；ZZ 不是官方 Baseline 复现。
E新为新时点的完整池，包含 E旧，不等于新阶段增量。

每题分别从 E旧/E新检索一次 top-3，再固定给各规则臂复用。
规则直接使用源日志的 insights_after；成功经历使用保存的
memory.rollout.attempts[0].trajectory，不删除专有字段、不重新改写。
不调用通用 Runner 的 seed/resume；不从冻结状态继续更新。
源记录 success/score、池大小、规则前后链须一致，否则明确拒绝导入，
不根据 score 悄悄补回在线没有学习过的经验。

固定快照人工交叉是可执行干预，不对应自然发生的在线历史。
原始未打包端点与官方 prompt builder 做离线一致性核验；
记录打包前后差异。主实验结论限定在本协议统一 packing 下。

## 上下文硬预算

研究上下文上限 L=8192，输出预留 2048，余量 256：
最终输入最多 5888 tokens。服务实际上限低于 L 则 preflight 拒绝；
服务上限更大也不提高 L。

规则块 1024 tokens，经历块 3072 tokens，各自含块内编号与标签。
空块标记计入额度；优先级保持源顺序/检索顺序。
从尾部删完整规则/完整案例，直到各自达标；不交换剩余额度。
用同一个 tokenizer/template 精确计数完整最终输入，禁止字数估计。
完整当前问题、选项、答案格式与固定 scaffold 不截断。

若某一臂最终输入仍超过 5888，该题所有臂在生成前共同排除，
保存排除理由且不拿后面的题补位；报告原始分母和覆盖率。
因子不变性必须成立：固定 E 时换 R，E 文本及 ID 不变；反之亦然。
检查实际 token IDs，不将相同上限称成实际等长。记录源规则差异、
实际入提示差异、packing 丢弃比例与相同臂比例。

优先以本地服务同款 tokenizer 展开 non-thinking chat template，
向 vLLM completions 发送已计数的 token IDs，避免服务二次模板扩展。
preflight 核验 served model、实际 max_model_len、tokenizer identity、
sentinel 的服务 tokenization 一致性和 usage.prompt_tokens。
若后端不支持精确核验就失败并给出明确诊断，不回退到估算。
400/上下文错误不重试；超时/429/5xx 每个逻辑请求最多重试两次，
使用相同 seed，所有已提交尝试均持久化计账，不挑多个结果中的最好者。

## 两个预定选择器与预算

完整 selector 从 OO/NN 选一个；组件 selector 从 OO/ON/NO/NN 选一个。
都只读 dev，按平均正确率最大化，平局优先 NN、OO、ON、NO。
允许组件 selector 选择完整端点。所有固定臂亦独立报告，不强迫方法胜出。

公平资源按预先可知的 reserved tokens 计：
每请求成本 `prompt_tokens + 2048`，含实际 scaffold；
不按生成结果长度自适应分配 dev。
两种 selector 使用同一个预算 B（完整 selector 在全部 dev 的成本）。
按同一个预定、共同排除后的合格 dev 顺序读取完整题块，
每块包括该 selector 的所有候选×2回答；
首次遇到放不下的题块即停止，不跳过去找更便宜的后续题。
完整 selector 使用全部合格 dev，组件 selector 使用最大可负担前缀。
合格 dev 为空、或组件 selector 不能消费一块时判程序不合格。
每个候选分母必须相同；selector 只接收授权数据投影，不能看到其他已有标签。
预先保存每个 selector 的 qid 清单、成本与剩余预算，不可越界读后续标签。

这只匹配选择期的预留 token 上限，不宣称 wall-time 或实际 token 严格相等。
另报实际输入/输出 token、CPU 检索/打包时间。七臂机制实验总花费与
每种策略实际允许读到的选择成本分别记账；固定策略选择成本为零。
dev 选择完成封存 selection.json 后才生成、评分和分析正式 test。

## 估计量与判据（V4 修订，提交第 2 轮重审）

主推断目标严格条件于：这条历史、该模型和 packing、实际合格的固定 test
题目集 T、dev 及已经冻结的两个选择 S/F。概率只来自新的独立生成，
不作 query 总体或跨构建历史推断。各请求需条件独立、后端分布稳定、评分固定；
hash 派生 seed 和随机打散只是操作措施，不是这些统计假设的证明。
两次重复保持独立；同一固定臂的结果被策略引用，不为 selector 另生成。
不共享不同臂/重复的回答缓存。相同所选臂在系数中代数消去。

对同题重复取均值后计算六个预登记对比：

- C1=ON−OO；
- C2=ON−NN；
- C3=ON−ZE；
- I=NN−NO−ON+OO：正确率加性尺度交互；
- D_F=S−F；
- D_ON=S−ON。

这是根据 R2 在尚无新实验回答时作的协议修订，将三个主机制对照直接纳入
六对比族，避免用较宽的线性组合区间代替它们。该版本之后不再改主检验族。
a=NO−OO=−C2−I，b=ON−OO=C1 可以作为简单效应的确定性推论报告。
未登记的七臂两两差值只作描述，不改变判定。

六对比使用 R2 给出的同一固定样本 Hoeffding 证明：
按臂顺序 (OO,ON,NO,NN,ZE,RZ,ZZ) 构造并合并系数 c，
`theta_hat=mean_i sum_a c_a*(Y_ia1+Y_ia2)/2`；
`h=sqrt(sum(c_a^2)*log(240)/(2*n*2))`，alpha=0.05，K=6。
CI 为 theta_hat±h 与系数所允许值域的交集；c=0 时精确 [0,0]。
六个区间条件同时覆盖率至少 95%，依据独立有界请求的 Hoeffding 加 union bound；
不要求六个对比独立，不回收重复/零对比的 alpha。
实际 n=|T|，不是名义96；n=0、缺行、失败或指纹不一致均拒绝效应分析。
不复用旧 weighted CS、不以 bootstrap/Wald 中更好看的结果替换此主 CI。

另报 R2 的解码方差无偏估计
`Vhat_dec=sum_i,a c_a^2*(Y_ia1-Y_ia2)^2/(4*n^2)`，
以及逐题差值样本方差。后者包含题间异质性，只作新题设计情景；
两者都不替代主区间。

交互不同于语义兼容性。混合臂最强可出现在 I=0，必须如实呈现。
一次全局 selector 总会等于某个固定臂。D_F 只评价这次实现出来的两个选择，
不是选择算法对 dev 随机性的平均效用；D_ON 只排除固定 ON，不排除固定 NO。
不以 selector 偶然胜过选错的 F 证明完整快照策略类不够好。
NO 缺少匹配的旧经历-only 控制，不作 NO 排除所有纯经历解释的主张。

最小重要差异 δ=0.03；不按新结果改动。逻辑求解最多 2240 次
（7×160×2，含 dev smoke），后端探测最多2次，另登记44次传输重试储备；
已提交生成尝试总上限2286，且每个逻辑请求最多3次尝试。
超时且可能已经执行的尝试也计数。预算耗尽而行不全则判技术失败，
不悄悄加预算、不将失败当答错；沒有构建/curator LLM 调用。
preflight/smoke 的原始响应也持久化，重复启动不得无限重复探测。

主机制状态与辅助策略状态分别输出：

1. 干预无效/数据不合格：不研究效应，先定位预定构造失败原因。
2. 主机制有希望：C1、C2、C3 的同时区间下界全部严格大于 δ。
   只支持“当前固定题集的 ON 有条件机制证据，值得独立确认”；
   不支持通用选择器或在线恢复主张。I 是否非零不是该状态的必要条件。
3. 主机制 NO-GO：上述任一上界严格小于 δ，写明被排除的是哪项必要条件；
   不推广成所有混合策略都无效。其余情况一律 INCONCLUSIVE。
4. 辅助 D_F/D_ON 各自仅按下界>δ、上界<δ、其余不确定独立标注；
   S=F 或 S=ON 时相应差值精确为零，不能说精度不足。
   辅助达标不替代主机制失败。
5. I 区间排除0只表示加性尺度交互符号；不显著不表示无交互。
   不确定时交付六对比、两种方差口径、样本量与成本敏感性表；
   只设计一次独立确认，不自动换题/时点/任务或追加本轮重复追显著。

在 n=96,r=2 下，非零普通差值/交互的主 CI 半宽约为0.169/0.239。
这一次不具备可靠分辨三个百分点的功效，主要用途是验证可执行干预、
检验大效应并估计下一阶段成本。对真实效应0.06、阈值0.03，
同样主区间与边际80%功效的保守充分设计需要普通差值约7300题；
不是所有有效方法的信息论下界。确认设计应按0.03/0.06/0.10情景
列出拒绝零和超过δ两类目标，给出观察方差到保守界的范围。
若资源不足，停止该精度主张，不能靠重复旧题伪装增加新题或新轨迹。

正式研究再预先划分 S/P，至少两任务、多条独立构建流，按 pilot 方差做功效设计，
并考察固定 ON 与数据驱动选择的差别；在新证据前不实现大规模在线 gate。

## 实现验收（第 3 轮审核）

必须检验：真实官方 prompt builder 一致性；源 trajectory 保真；
gold/test 信息不进入查询/记忆；组件打包不串扰；问题不截断；
准确的模型总上下文检查；参数/数据/template 指纹；
结果按 qid/arm/rep 原子保存并恢复，不覆盖历史、不用仅有 .done 判完成；
缺失/重复/指纹不一致时 analyze 拒绝；选择器不能读取未获预算的 dev 或 test。

服务器执行工具只负责该协议，不修改官方子模块，也不掩盖原 E0/E1 的六项已知问题。
本地无真实模型/数据，只能做离线验证；真实上下文与效果由服务器 preflight/smoke/discovery 分别核验。
